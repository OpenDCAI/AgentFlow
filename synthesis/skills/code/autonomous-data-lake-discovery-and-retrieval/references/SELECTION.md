# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the trajectory includes an explicit successful identification of ALL ground-truth files required by the reference task. The verification must confirm from the tool logs that the agent correctly located the specific filenames and paths cited in the benchmark's solution. A trace that misses a critical join-table or a transformation-rule file represents a functional failure of the discovery capability.
  - Accept only if the agent's final analytical code grounds all identifiers and column names in the specific schemas discovered during the sampling phase. The selection process must verify that the code uses the actual headers found in the files (e.g., 'patient_age_val') rather than hallucinated or generic guesses (e.g., 'age'). This ensures the resulting data captures the 'high-fidelity' grounding required for autonomous data science.
  - Accept only if the trajectory demonstrates 'Feedback-Driven Self-Correction' where the agent resolved at least one discovery mismatch. For instance, the agent might have initially targeted 'data_v1.csv' but realized after sampling that it was empty or outdated, subsequently pivoting to 'data_v2.csv'. This confirms the agent can handle the physical friction of messy data lakes rather than just getting lucky on the first try.
  - Accept only if the final state of the environment includes an executable program that successfully produces the correct mathematical or logical answer. The selection must verify that if the query requires a number (e.g., '60'), the agent's code produced exactly that number in the terminal output logs. This is the primary indicator that the discovery, retrieval, and analysis stages were all performed correctly and integrated seamlessly.
* **Rejection Criteria**:
  - Reject trajectories characterized by Blind Context Loading where the agent attempts to load every file in the directory into its prompt or memory. Professional data engineering requires surgical extraction; any agent that defaults to `os.listdir` followed by a loop of `read_csv` on everything fails the scalability test. This prevents the synthesis of 'lazy' agents that would overwhelm real-world compute environments.
  - Reject traces that achieve 'Success' through Semantic Hallucination where the agent guesses the contents of a file based on its name and hardcodes the answer. If the agent provides an answer that it could not have derived from the observed data samples (e.g., calculating a mean from a file it never actually opened), the trace is fraudulent. Any such shortcut nullifies the value of the discovery training data.
  - Reject any trajectory that solves the task by 'Sabotaging the Environment'—for example, by modifying the data lake scripts or deleting distractor files to clear the workspace. Discovery benchmarks explicitly measure the ability to navigate noise and hostily structured data; bypassing this challenge through file-system manipulation is a catastrophic alignment failure. The agent must solve the identification problem within the original environment's structure.
  - Reject submissions that demonstrate a Logic-to-Outcome Mismatch where the agent's thoughts claim to have found the data but the final code fails to execute. For instance, the agent might say 'I found file X in folder Y', but the code uses a different path or a non-existent variable. Selection must favor agents that accurately translate their discoveries into executable logic without internal contradiction.
