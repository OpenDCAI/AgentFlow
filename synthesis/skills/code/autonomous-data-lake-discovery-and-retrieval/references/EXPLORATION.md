# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a Hierarchical Namespace Reconnaissance by executing recursive directory listing or file-finding commands to map the ecosystem's physical topology. The agent should identify clusters of files sharing name prefixes or directory paths that suggest common semantic domains, such as '/meteorology' or '/sales_2023'. An edge case occurs when the repository uses numerical IDs for folders, requiring the agent to look for a 'manifest.json' or 'README' at the root to decode the organization logic.
  - Execute Representative Content Sampling to infer schema structures and data distributions without loading massive datasets into memory. The agent should utilize tools like `head` for text files or the `.info()` and `.head()` methods in pandas for structured files to verify the existence of columns like 'timestamp', 'price', or 'status'. A failure to avoid is attempting to read a multi-gigabyte dataset wholesale, which can lead to environment freezes or memory errors during initial discovery turns.
  - Implement Semantic Grounding via External Retrieval when the task uses domain-specific terms or abbreviations not present in local metadata. The agent must formulate specific search queries to define technical markers, such as standard metric names or specialized acronyms, to determine which column headers in the data lake likely realize those concepts. For example, a search for 'PM2.5 sensor codes' might reveal that a column named 'sensor_val_4' is the relevant data source for a health-related question.
  - Conduct Incremental Execution Feedback Loops to probe esoteric file formats that are not easily readable via standard terminal utilities. The agent should draft and run minimal Python snippets using specialized libraries (e.g., `cdflib` for .cdf or `geopandas` for .gpkg) to extract global attributes or attribute headers. An example is handled when a file appears to be a spreadsheet but contains multiple hidden sheets, requiring the agent to iterate through sheet names to locate the actual data table.
  - Establish a Multi-Agent Consensus Simulation by evaluating responses from different discovery sub-modules or search nodes to handle overlapping expertise. The agent should conceptually partition the data lake and query each partition for its ability to fulfill the specific data request, merging the results into a unified plan. This approach is critical for cases where relevant information is distributed across several disparate files, such as when one file contains identifiers and another contains the associated metrics.
* **Target Trajectory Profile**:
  - The trajectory must exhibit a clear Discovery-to-Action progression where every file access is preceded by a documented observation of its likely relevance. A high-quality trace shows the agent finding a filename in a directory listing, reasoning why it might contain the answer, and then sampling its content to confirm its schema. This prevents the 'blind scanning' failure mode where an agent randomly opens every CSV file in a folder hoping to find the target data.
  - Strong traces should include at least one Language or Tool Pivot based on the discovery of specialized file formats during the exploration phase. The agent must demonstrate it can identify a .gpkg file and immediately transition from generic pandas usage to geopandas or other spatial libraries to handle the data. This proves the agent's adaptability to the heterogeneous nature of real-world data lakes where a single toolchain is often insufficient for all discovered assets.
  - The trajectory must preserve evidence of Meticulous Context Management by documenting which files or clusters were searched and ruled out. High-quality exploration maintains a 'negative results' ledger, explaining why certain tempting files (e.g., 'summary_stats.csv') were discarded after content sampling revealed they did not meet the task's granularity requirements. This behavior mirrors professional data analysts who bound their problem scope to avoid repeating unproductive searches in massive repositories.
  - Evidence of Semantic Integration should be visible where the agent explains how extracted web definitions were used to verify local data columns. The trace is better when it captures the agent saying: 'The search results indicate X is an acronym for Y; I found column Y_val in file Z, so I will proceed with its analysis.' This closed-loop reasoning between external knowledge and internal file discovery distinguishes expert capability from simple data parsing.
