# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the infrastructure components strictly adhere to correct syntax producing 100% Data Fidelity transit parity (source vs destination row comparisons align perfectly).
  - Accept only if transformation artifacts successfully process nested schema constraints implementing functional complex SQL functions (like Window ranking) executing without relational logic breakdown.
  - Accept only if the agent operates gracefully with project-level components like pre-existing macros, workflow scripts, or state management, demonstrating systemic architectural assimilation.
  - Accept only if clear sequential validation boundaries existed, evaluating intermediate data distributions and schema compliance effectively bridging pipeline tools successfully.
* **Rejection Criteria**:
  - Reject traces posing as orchestrations that manifest merely as one-shot fragmented scripts completely ignoring inherent dependencies or failing to utilize the designated repo tool stack.
  - Reject paths generating Redundant Synchronizations due to missing state tracking, which cause table bloat and fail fundamental deterministic idempotency.
  - Reject trajectory solutions employing hardcoded configuration variables resulting from hallucination rather than systematic documented extraction logic.
  - Reject evaluations bypassing structural obstacles (like schema mismatches) by simply dropping columns/requirements illicitly to synthesize a faux success state.
