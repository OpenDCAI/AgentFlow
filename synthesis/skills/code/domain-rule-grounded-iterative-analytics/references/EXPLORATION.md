# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a Domain Logic and SOP Prawl before drafting any data processing code. The agent must first search for specific keywords like 'formula', 'rule', 'definition', or 'conversion' within the unstructured documentation to establish the mathematical constraints of the task. For example, if asked to calculate 'net revenue', the agent should confirm whether this includes or excludes service taxes as defined in the project's financial handbook. An edge case is when multiple manuals provide conflicting formulas; the agent must identify the most recent or relevant one based on file metadata.
  - Construct a 'Data-Context Linkage Map' to identify how columns in structured files map to concepts in the documentation. The agent should read the first few lines or schema of the CSV/JSON files and immediately compare the column headers to the definitions found in the data readme or manual. If a manual mentions 'Interchange Fees' but the CSV only has a column named 'ic_cost', the agent should explicitly document this mapping in its internal reasoning. This prevents the failure mode where an agent tries to group data by a non-existent column name or hallucinates a metric that is not present in the files.
  - Decompose the analytical query into a sequential check-and-filter pipeline rather than a single-shot script. The agent should plan to extract intermediate results—such as a list of identified merchant IDs—and verify their properties against the manual's rules before performing final aggregations. For example, if a rule applies only to 'International Transactions', the agent must first find the definition of 'International' (e.g., origin != destination) in the manual and apply that filter before calculating any sums. This 'check-first' approach ensures that the agent handles the hidden complexity of multi-step business logic.
  - Monitor the 'Unstructured-to-Structured' dependency chain for implicit rules with downstream impacts. Many business tasks involve rules that aren't explicitly requested but are required for accuracy, such as rounding conventions, currency conversions, or date-range exclusions. The agent should scan for these implicit constraints in the manual's tables and appendices early in the trace. An edge case is a fee structure that changes on a specific date; the agent must identify this temporal boundary in the text and split its data analysis accordingly to avoid providing a skewed average.
* **Target Trajectory Profile**:
  - A high-quality trajectory must clearly show the agent reading the documentation *before* attempting to execute a code-based solution. The trace should capture the observation of a specific rule, formula, or regulatory guideline followed by an action that implements that logic in a Python or SQL script. This temporal order proves the agent is grounding its code in the provided context rather than relying on pre-trained assumptions about financial or data structures.
  - The trace should maintain a 'Rule-to-Code' provenance by inserting comments into the generated code that cite the specific manual or section used. The agent should state, for instance, '# Following Section 3.1 of manual.md for fee calculation' within its code block. This ensures the reasoning is auditable and that the agent is intentionally following the project-specific rules provided in the environment. It also prevents the agent from falling into the trap of using generic data science patterns that might violate specific business constraints.
  - A strong trajectory must explicitly handle 'Missing Data' or 'Ambiguous Rule' scenarios through active environment probing. If a rule in the manual refers to a field that doesn't seem to exist in the CSV, the agent should search the environment for a 'mapping' file or a 'metadata' JSON to resolve the discrepancy. This is signaled by thoughts like 'The manual mentions ACI, but I don't see it in payments.csv; let me check payments-readme.md to see if it is aliased.' This level of meticulous cross-referencing defines the expert analytics capability.
  - Trajectories should exhibit 'Vectorized Idiomatic Coding' by using high-level library abstractions like GroupBy or PivotTables instead of inefficient for-loops. A professional analytics trace avoids manually iterating over rows of a massive CSV file, which often leads to errors and poor performance. The agent should demonstrate proficiency in using libraries like Pandas or Polars to perform mass data transformations quickly and cleanly. An example is the agent choosing to use `.map()` or `.apply()` with a logic function derived from the manual rather than a nested loop structure.
