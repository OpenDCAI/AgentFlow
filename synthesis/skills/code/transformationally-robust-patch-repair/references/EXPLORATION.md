# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Treat surface cues as weak evidence and semantic behavior as strong evidence. The agent should actively assume that names, order, and local shape may have changed while the defect remains behaviorally equivalent. This mindset changes the exploration strategy from 'find matching old patch context' to 'reconstruct the logic that fails'.
  - Rebuild the behavioral slice around the failing test instead of searching for exact lexical anchors. Start from the reproduced failure, trace the values and conditions that determine the incorrect outcome, and follow the transformed call chain until the wrong semantic branch is identified. An edge case is when helper extraction adds several new thin wrappers; the trajectory should collapse them mentally into one behavioral path.
  - Record which transformations are present and how they affect search reliability. Examples include identifier renaming, loop or conditional restructuring, helper extraction, expression decomposition, and file movement. Stating the transformation class is useful because it explains why naive code search fails and what deeper evidence is needed next.
  - Prioritize data-flow and invariant reconstruction over local pattern matching. Ask what values should be validated, what conditions should hold before state change, and what outputs indicate failure, then use those invariants to navigate the transformed code. If the agent finds itself relying on familiar variable names or patch-shape resemblance, the trajectory should explicitly correct course.
* **Target Trajectory Profile**:
  - A good trajectory should show that the agent localized the bug through semantics rather than through superficial resemblance. The trace should mention control-flow meaning, data dependencies, or failed invariants, not just the discovery of a similarly named function. This is the essence of transformation robustness.
  - A strong trace should preserve one explicit explanation of why the transformation did not change the underlying bug. For example, the security check may still be missing even though the helper was renamed and split in two. This explanation is important because it teaches downstream synthesis to separate semantic identity from syntactic disguise.
  - The validation plan should rerun transformed tests in the transformed environment. Using untransformed or external canonical tests undermines the purpose of the capability. The accepted trajectory must stay within the modified repository context and still demonstrate successful repair.
  - A high-quality trace should include at least one rejected superficial lead. Because transformed code is designed to foil shallow matching, the trace is more realistic when it shows that a tempting lexical cue was checked and discarded in favor of semantic evidence. That negative evidence is pedagogically valuable for synthesis.
