# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Reproduction Hypothesis Generation: Start from the human issue text or machine diagnostic report and convert it into a targeted reproduction hypothesis. Prioritize executing the exact target reproduction command right away to establish an irrefutable baseline failure signal before touching source code. An edge case is when the failure cannot be reproduced immediately, requiring inspection of issue-relevant tests instead.
  - Ecosystem Structure Audit: Map out massive or highly diverse repository layouts ranging from Web frameworks and SQL databases to ML pipelines. The agent must adapt to heterogeneous architectures by locating config files, schemas, and entry points, utilizing recursive grep searches to trace call graphs up to the error site. This prevents context bloat in 32k+ token codebases.
  - Log and Numeric Profiling: For machine diagnostics, runtime crashes, or SQL logical failures (e.g., unexpected query duplicates), map the structured data or execution output to explicit systemic state-change errors. Identify exactly what global variables are unpredictably mutated, where data distributions shift, or where gradient values explode by profiling terminal outputs for the onset of divergence.
  - Fault-Localization Notebook: Maintain an active internal notebook that strictly separates confirmed behavioral observations from mere hypotheses. Actively record negative exclusionary evidence when exploring multiple symmetric files to limit context bloat over long horizons.
* **Target Trajectory Profile**:
  - Causal Reproduction Path: A high-quality trajectory directly establishes one unbroken causal reproduction path from the symptom to a verifiable executable failure state. Traces lacking this executable benchmark proof of failure must remain unadvanced, maintaining execution-first discipline.
  - Systematic Localization Record: Maintain a trail that documents every file searched and ruled out. For tasks demanding long trajectories (50+ turns), this trail is essential to prevent circular reasoning or repetitive exploration loops inside massive repositories.
  - Minimal Region Isolation: The trace must actively isolate the precise minimal responsible region before authorizing codebase edits. If an issue spans multiple files, the trajectory must articulate why specific dependencies enforce surgical constraints, such as adding norm layers strictly where tensors explode.
  - Regression Validation Planning: A strong sequence explicitly plans regression validation beforehand, identifying the test runner logic required to guarantee secondary functional regressions are prevented. This restricts fixes from disabling required functionality to satisfy an edge case.
