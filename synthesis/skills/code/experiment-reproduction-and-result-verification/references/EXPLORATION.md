# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Begin by extracting the verification contract from the benchmark or rubric. The agent should identify which outputs matter, which scripts or commands generate them, and what evidence counts for code development, execution success, or result match. This prevents aimless experiment running without a clear success criterion.
  - Inspect the execution entrypoints and their dependencies before launching long runs. Determine what reproduce.sh or equivalent scripts do, what inputs and credentials they require, and which artifacts they are expected to emit. An edge case is a script that partially runs but silently skips key experiments; the trajectory should anticipate and check for that possibility.
  - Treat logs and generated artifacts as primary evidence sources. After execution, inspect logs for completed stages, errors, and metric summaries, then inspect output files such as tables, plots, checkpoints, or prediction files to determine what was actually produced. Verification cannot rest on process exit status alone.
  - Maintain a requirement-to-evidence matrix during exploration. For each required outcome, record where confirming evidence would appear and whether the current run provided it. This makes partial success legible and is especially important for long-horizon reproduction tasks with many subrequirements.
* **Target Trajectory Profile**:
  - A strong trajectory should clearly separate implementation evidence, execution evidence, and result-match evidence. These categories often overlap in intuition but not in benchmark scoring. The trajectory is stronger when it states, for example, that code exists, the script runs, but the final metric still does not match.
  - A good trace should include one clean-environment reproduction step. Verification is more credible when outputs are generated from a fresh start rather than inherited from previous hand-run artifacts. This protects against hard-coded or stale-result shortcuts.
  - The trajectory should preserve partial progress rather than flattening everything into pass or fail. Research reproduction often succeeds incrementally, and benchmark rubrics are designed to award that structure. A trace that records only a binary verdict discards useful supervision signal.
  - A high-quality trace should notice plateau or failure modes during execution and adapt the verification plan accordingly. For example, if a run ends early, produces incomplete outputs, or logs the wrong dataset split, the agent should update which requirements are still verifiable. This makes the resulting trajectory realistic and diagnostically useful.
