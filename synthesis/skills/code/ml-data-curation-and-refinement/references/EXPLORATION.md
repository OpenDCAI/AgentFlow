# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a Hierarchical Documentation Correlation pass to identify pre-existing data-handling benchmarks or weights. The agent should first read the project's README or 'data_manual.md' to see if specific imputation models (e.g., CSDI) or labeling thresholds are already recommended for the current domain. A concrete step is searching for hidden URLs in the documentation that point to pre-computed statistical anchors or model checkpoints, which saves excessive training time. An edge case is when an agent finds an outdated labeling rule in a comment and must cross-reference it with the latest manual to ensure it still reflects the current data schema.
  - Execute a Missingness Distribution Audit to categorize the nature of gaps in the dataset (MCAR, MAR, or MNAR). The agent should write and run a diagnostic script using libraries like 'missingno' to plot heatmaps and correlation matrices between missing columns and available features. For instance, in a weather sensor network, the agent might identify that a specific temperature range causes a sensor to fail, indicating the missingness is 'not at random'. This step is critical because choosing the wrong imputation logic for a specific distribution leads to significant bias in the resulting machine learning model.
  - Conduct a Programmatic Labeling Function (LF) Extraction by mapping heuristic rules from text manuals to technical code anchors. The agent must search the repository for mentions of 'threshold', 'condition', or 'criteria' to build a list of potential logic branches for assigning synthetic labels. A specific action involves identifying whether several conflicting rules apply to the same record and planning a 'voting' or 'consensus' logic to resolve them. For example, if two different manuals define 'fraud' differently, the agent must document this discrepancy and ask for the current project-standard definition before proceeding.
  - Perform an Execution-Driven Environment Verification on the interpreter state and initialization files like 'if __name__ == "__main__":'. The agent should execute a minimal 'hello world' test on the target labeling or imputation script to ensure that global scope variables and environment paths are correctly configured. This prevents the frequent failure mode where agents draft complex ML logic that never actually executes because it is gated behind a main block or a broken `sys.path` addition. An example is an agent identifying that a script requires a specific 'PYTHONPATH' to find its internal data-loading module and applying the `export` command proactively.
* **Target Trajectory Profile**:
  - The trajectory must demonstrate a 'Diagnostic-to-Implementation' transition where the choice of data cleaning tool is justified by an earlier statistical observation. A high-quality trace shows the agent explicitly noting a specific missingness correlation in a heatmap and then selecting a 'variational' or 'diffusion' model to handle that complexity. This ensures the reasoning is grounded in the physical properties of the dataset rather than generic library usage.
  - A strong trace includes evidence of 'Iterative Accuracy Refinement' where the agent compares imputed or labeled values against a small human-verified subset. The trace should capture the agent noticing a high error rate in its first labeling attempt, reviewing the manual for a missed constraint, and then surgically editing the labeling function. A concrete sign of quality is the agent seeing a 'Mean Absolute Error' that is too high and adjusting its model's noise iterations to reach the project's accuracy target.
  - The trajectory should preserve evidence of 'Symbolic Alignment' by mapping qualitative terms in a manual to specific variable names in the training code. High-quality exploration captures the agent linking a business rule (e.g., 'high volatility') to a specific standard deviation calculation in its Python script. For example, the agent should state: 'The manual defines volatility as the 30-day rolling variance; I will now implement this in `prepare_data.py` to drive the labeling logic.'
  - A professional-grade trajectory must exhibit 'Stewardship of State' by managing temporary artifacts and ensuring no data is overwritten without a backup. The agent should demonstrate it can perform 'dry-run' imputations or save results to a 'temp_labeled.csv' before committing to the final database update. This prevents the 'destructive' failure where a buggy labeling loop ruins thousands of raw data points, which is a critical risk in professional ML data engineering.
