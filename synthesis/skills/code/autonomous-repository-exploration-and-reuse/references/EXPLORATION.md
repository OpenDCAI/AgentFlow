# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Deconstruct the repository instructions into a hierarchical research pipeline (S: Setup, D: Download, T: Training, I: Inference, E: Evaluation) and perform Hybrid Structural Mapping to locate semantic anchors like CLIs or execution entry points. If the README is erroneous or missing steps, rely on dependency centrality to determine script hierarchies.
  - Initialize a mandatory 'Installation Verification Pass' to identify and solve out-of-band dependencies. Search the README and source files for download links (e.g., HuggingFace, Google Drive) tied to pre-trained weights, or missing system tools that throw errors. Validate missing physical dependencies through an immediate test run.
  - Perform a path and variable audit across the repository structure to identify hardcoded environments. Replace explicit absolute paths or static environment variables with relative paths or dynamic shell configurations to ensure portability.
  - Transition to Context-Aware Graph Traversal and Log-Based Self-Correction. Execute bash configurations or python entry points, parse standard error logs for mismatches (e.g., KeyError or ModuleNotFoundError), and apply precise surgical adaptations rather than dumping full source files into context.
* **Target Trajectory Profile**:
  - The trajectory must demonstrate a clear transition from 'Static Mapping' to 'Task-Driven Adaptation', where exploration actions are directly motivated by execution feedback from the repository. A high-quality trace shows the agent resolving uncertainty by attempting an initial run, parsing the error trace, and tracing the call chain rather than statically guessing parameters.
  - A strong trace includes iterative 'Log-Based Self-Correction' cycles where the agent resolves environment mismatches or dataset inconsistencies. The trace should capture the agent attempting a setup command, observing a 'Library Version Conflict', and responding with a surgical installation or environment variable adjustment.
  - The trace must maintain a 'Signal-to-Noise' ledger by explicitly filtering out non-source files and low-priority modules from its internal reasoning. Each interaction turn should be concise, focusing solely on the snippets of code solving the current execution bottleneck.
  - The trajectory must explicitly record 'Snapshot and Reset' protocols or similar defensive execution strategies when testing third-party environments. The agent should demonstrate it can track which commands polluted the workspace or caused irreversible configurations, rolling back broken states to maintain reproducibility.
