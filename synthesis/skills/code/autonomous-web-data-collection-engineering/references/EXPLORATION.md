# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a source-path arbitration to decide between REST API harvesting and direct HTML scraping based on availability and stability. The agent should first search for official developer documentation or API endpoints that provide structured JSON responses for the target query. An edge case occurs when an API exists but is rate-limited or requires authentication, requiring the agent to pivot to a headless-browser scraper as a robust fallback.
  - Execute a hierarchical DOM audit to identify stable anchors and extraction selectors before drafting code. The agent must inspect the target website's HTML patterns across multiple sample pages to find invariant tags, class names, or data-attributes that uniquely identify the required fields. A failure mode to avoid is relying on absolute indices like '/div[2]/span[1]', which break easily; the explorer should prioritize semantic identifiers like 'class="paper-title"'.
  - Conduct a temporal and geographic layout check to identify if the website uses dynamic loading or regional redirects. The agent should probe if the content is rendered server-side or if it requires JavaScript execution (e.g., Infinite Scroll or AJAX) by checking for hidden network payloads in the browser tools. An edge case is a site that shows different data based on the visitor's IP address, which necessitates planning for specialized proxy or header configurations in the development phase.
  - Implement a blueprint-to-artifact mapping by creating a structured data dictionary from the user's natural language terms. The agent must map the qualitative descriptions (e.g., 'the authors') to specific code variables and types (e.g., list of strings) to serve as a contract for the implementation squad. This step involves identifying potential nested data, such as a paper having multiple authors, and planning for appropriate collection depth. A concrete sign of quality is the agent documenting exactly how it will handle missing values (e.g., NULL vs. empty string) before implementation starts.
  - Audit the repository for 'knowledge seeds' like existing configuration files or previous crawl logs that could assist the task. The agent should search for '.yaml' or '.json' files that might store API keys, base URLs, or common headers used by the organization. This prevents redundant exploration and ensures the new scraper integrates with the existing infrastructure styles. An edge case is finding an old, broken scraper for the same domain and extracting its XPath selectors to save research time.
* **Target Trajectory Profile**:
  - The trajectory must demonstrate a clear progression from 'Discovery' to 'Blueprint' to 'Scripting', where each action is justified by an observation of the web environment. A high-quality trace explicitly records the agent finding a specific HTML tag or API endpoint and then documenting it in an internal plan before generating any code. This ensures the reasoning is grounded in the physical reality of the web source rather than hallucinatory pattern completion.
  - A strong trace includes at least one 'Modality Pivot' where the agent switches its approach based on technical feedback. For example, the agent might try to scrape a table directly, find it is obfuscated with Canvas rendering, and then pivot to searching for a hidden JSON endpoint in the network logs. This highlights the agent's ability to handle the 'hidden complexity' of modern web architectures autonomously.
  - The trace should preserve evidence of 'Selective Extraction' where the agent ignores distractor content like ads, sidebars, or footer links. High-quality exploration demonstrates the agent specifically targeting the 'main' content container by using search tools to verify content density. A specific sign of quality is the agent checking if a sample extraction contains the expected keywords from the user prompt before committing to a full-site crawl.
  - Trajectories must exhibit 'Idempotent Planning' by documenting how to handle partial failures or resume interrupted crawls. A professional trace shows the agent considering how to save intermediate results and prevent duplicate entries in the final dataset. For instance, the agent might plan to use a set of 'visited_urls' or a checksum-based deduplication logic in its implementation logic.
