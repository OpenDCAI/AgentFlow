# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a Multi-Table Schema Topology Audit to identify all mandatory columns, primary keys, and foreign key dependencies. The agent should find every 'CREATE TABLE' statement or schema metadata block to map how an entity in one table (e.g., an ActorID) must correspond to a record in another. An edge case is when a new row insertion fails because the agent neglected to check if a foreign key value already existed in the parent table, requiring a pre-emptive check of the Parent table's contents.
  - Conduct a Data Granularity and Format Benchmark by fetching sample rows from the target columns to understand the expected level of detail. The agent should execute targeted 'SELECT' queries on representative columns like 'Location' or 'Category' to determine if the database expects 'City, Country' versus just 'Country'. For instance, if the 'Loc' column contains 'New York' and 'Boston', the agent should steer its text extraction toward specific cities rather than general regions. An edge case appears when the schema is ambiguous (e.g., a 'Status' text field), in which case reading sample entries is the only way to identify the allowed label space.
  - Map Natural Language Instructions to Technical Table Operations by classifying the user request into specialized categories: Data Infilling, Row Population, or Column Addition. The agent must analyze phrases such as 'add details for missing entries' versus 'add a new record' to decide whether it needs to link to existing IDs or generate new ones. For example, a request to 'add a column for Gender' indicates a schema-changing operation where every existing row must be scanned for new data. A failure to perform this classification often results in the agent trying to add a new row when only an update to an existing one was requested.
  - Execute an Evidence-to-Schema Traceability Pass by locating all candidate entities in the text and linking them to potential table attributes. The agent should search the unstructured document for keywords derived from the column names, such as 'born', 'budget', or 'directed by', to create a list of spans ready for extraction. A specific action involves identifying if an entity in the text maps to multiple tables simultaneously, such as a person who is both a 'Director' and an 'Actor'. This ensures that the later implementation phase can efficiently call specialized tools for each attribute without missing overlapping requirements.
* **Target Trajectory Profile**:
  - The trajectory must demonstrate a clear transition from 'Schema Observation' to 'Dynamic Tool Planning' where the choice of extraction functions is justified by the database structure. A high-quality trace shows the agent explicitly identifying that a 'Genre' column has a fixed set of values in the DB, leading it to choose a 'Text Classifier' rather than an open-ended 'Named Entity Recognizer'. This proves the agent is adapting its extraction strategy to the software environment's rigid constraints on the fly.
  - A strong trace includes an 'Integration-Level Integrity Verification' turn where the agent simulates the insertion or update to catch potential constraint violations. The agent should document checks for primary key uniqueness and foreign key existence before authorizing the final database write action. For example, the agent might thought: 'I have extracted the new movie info; before I insert, I must check if this MovieTitle already exists to avoid a duplicate entry error.' This reflects professional database stewardship and prevents runtime database crashes.
  - The trajectory should preserve evidence of 'Semantic Granularity Correction' where the agent refines a value based on database demonstrations. The trace is better when it captures the agent seeing that existing 'Gross' values are stored as integers representing millions, and then converting a text string like '$1.2 billion' into '1200' to match the existing scale. This demonstrates closed-loop reasoning between the unstructured source and the structured target. An edge case involves the agent catching a date format mismatch (e.g., July 13, 1990 vs 1990-07-13) and applying a normalization step proactively.
  - High-quality exploration must exhibit 'Entity Linking Traceability' by documenting how extracted text spans are pinned to specific database records. The agent should show itself extracting an entity (e.g., 'Roger Allers'), and then searching the database to find its corresponding ID (e.g., DirectorID 49) before attempting to link a new movie to it. This ensures that relationships between tables are maintained correctly. Without this step, the synthesized data often ends up with orphaned rows or broken links that invalidate the database's relational utility.
