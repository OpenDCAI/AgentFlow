# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if execution sequences resolve functionally with 100% verified testing success or system state outcomes validating final physical environmental compliance.
  - Accept only if generated outputs (Dockerfiles or Bash pipelines) manifest strict idempotent properties, avoiding hardcoded values rendering deployments useless beyond the explicit local session.
  - Accept only if the agent reliably resolves dynamic friction events (Version constraint failures, network limits, incorrect tool variants) proactively demonstrating structural root-cause mitigation.
  - Accept only if trajectories strictly showcase Pollution-Free orchestration, effectively scrubbing false installation states and tracking exact dependency timelines perfectly.
* **Rejection Criteria**:
  - Reject trajectories producing 'Context-blind Overwrites' deleting or permanently fracturing core testing or binary directories indicating severe stewardship negligence.
  - Reject traces indicating 'Looping Indecision' reflecting an inability to formulate procedural sequences repeatedly cycling identical exploration calls fruitlessly.
  - Reject paths engaging in 'Sabotage Engineering' explicitly obfuscating test metrics, altering original core logics, or hard-coding unmanageable assumptions rather than fixing structural environment configurations.
  - Reject agent generations issuing massive single-shot unverified deployment commands heavily prone to silent error swallowing, violating foundational DevOps methodology.
