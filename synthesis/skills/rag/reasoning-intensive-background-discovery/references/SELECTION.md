# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Verify the surmounting of a significant Semantic Gap between query and evidence. Accept only cases where a clear divide exists between the query's informal/narrative language and the support document's expert/specialized terminology, requiring a logic leap. For instance, the user asks about 'warning lights' and the agent discovers the 'Common Alerting Protocol (CAP)' standard. If the query already uses the expert terms found in the documents, the reasoning difficulty is nullified.
  - Execute Recursive Self-Healing Sufficiency Checks to validate chunk coverage. The agent must evaluate whether the current retrieved chunks are technically sufficient to satisfy the specific sub-tasks or taxonomy dimensions identified in Phase 1. If the retrieved set contains a 'Pillar' label but lacks the associated 'Budget Amount' required for the audit, the agent must trigger a 'self-healing' search iteration to find the missing variable. A valid case correctly identifies that reaching a 'Pillar 2' finding requires re-querying for 'infrastructure costs' specifically.
  - Confirm Precisely Grounded Parameter Intersection for diagnostic or financial resolution. Accept the sample only if the retrieved expert context provides specific binary, numeric, or structural parameters (e.g., a specific budget amount, a bit-length, or a statute of limitations) required to solve the raw situational puzzle. The discovery must result in a concrete, actionable answer (e.g., 'Pillar 2: $4.5M') rather than a vague thematic description. An accepted trajectory shows the agent rejecting the 'famous' but incorrect pillar in favor of the mathematically perfect category.
  - Apply Context-Necessity Auditing via Parametric Knowledge Rejection. Accept only those samples where a baseline model without context cannot accurately guess the answer based on its pre-trained internal memory. This ensures the discovery is fundamentally anchored in the provided bounded corpus, especially for recent updates or niche project finance data. A query like 'How much was allocated to sirens in the 2024 Caribbean project?' is accepted because it relates to specific evidence that a base model cannot memorize.
* **Rejection Criteria**:
  - Discard Shallow Lexical Shortcuts where identical terminology appears in query and context. Reject any trajectory where the user prompt already employs the specialized technical terms or pillar names found in the expert documentation (e.g., naming 'Pillar 2' or 'RFC 791' in the query). This eliminates the core challenge of conceptual mapping and reduces the skill to a simple lookup task. Every valid sample should require a conceptual translation step to verify the agent's reasoning capability.
  - Reject Passive Topic-Matching without structural or regulatory governance. Discard samples where the agent finds a 'related' document but that document lacks a governing rule, principle, or mechanism to solve the user's stated problem. If the user asks for a project classification and the agent retrieves a general blog post about 'Climate Change', the discovery represents a reasoning failure. Only authoritative, rule-bearing documents or taxonomies satisfy the criteria for this specialized skill.
  - Eliminate Trajectories exhibiting Role-Flipping or Famous Subject Bias. Reject any case where the agent ignores rigorous text filters and returns a generically famous category or incorrectly identifies the 'Recipient' as the 'Investor' because of latent memory assumptions. Any instance where basic semantic assumptions overwrite the actual constraints embedded in the text table or project report must be purged immediately. These are reasoning hallucinations rather than successful expert-rule discovery.
  - Reject cases suffering from Numerical Fidelity violations beyond a strict ±5% tolerance. If the agent discovers a tax pillar but misreads or approximates the associated fiscal amount by more than five percent of the total project envelope, the trajectory must be rejected for lack of extraction precision. This is critical for auditing and compliance tasks where the relationship between a rule (Pillar) and a metric (Budget) must be exact. An agent that 'guesses' 1M when the text says 1.05M fails the fidelity check.
