# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement Iterative Instruction-Based Decomposition to break down high-level discovery intents into small, verifiable retrieval steps. The agent must analyze a complex request—such as auditing an entire financial report—and generate a sequence of specific instructions targeting distinct parts of the governing taxonomy (e.g., 'Instruction 1: Find Pillar 1 matches'). This allows the agent to issue targeted queries for each sub-standard before consolidating the final discovery. A concrete example is decomposing a network troubleshooting request into separate probes for 'Transport Layer errors' and 'Application Layer timeouts' to avoid context window pollution.
  - Deploy Hybrid Semantic-Lexical Probing to ensure both contextual themes and exact technical identifiers are captured. The agent should utilize both dense vector embeddings to find semantically related 'narrative' descriptions and BM25-style keyword matching to lock onto exact technical IDs, error codes, or budget numeric strings. This dual approach is essential when a user uses vague language (e.g., 'budget mismatch') but the answer depends on an exact currency value in a table. For instance, the agent might retrieve 'Pillar 2' documents via semantic search while simultaneously verifying exact 'Gauging Station' strings via lexical matching.
  - Execute Global Context-Augmented Indexing to situating small text fragments within the document's broader narrative. During the retrieval phase, the agent should prepend a concise two-sentence global summary of the parent document to each retrieved chunk to provide the 'structural anchor' required for accurate mapping. This prevents the agent from misclassifying a 'radar' mentioned in a general news section as a 'Pillar 2' infrastructure investment by verifying its document-level context. A perfect example is confirming that a fragment about 'risk data' belongs to an 'Early Warning' document rather than a 'General Insurance' policy through its augmented metadata tag.
  - Deploy Colloquial-to-Expert Dual-Index Traversal to surmount terminology variance between non-experts and professionals. The agent should simultaneously probe indices containing layman descriptions (sensory symptoms, sensory observations) and those containing formal Expert Blueprints (clinical codes, RFC field names). This ensures that a query about a 'burning chest' is evaluated against 'gastric reflux' and 'cardiac arrest' blueprints in parallel to avoid missing non-obvious root causes. A specific edge case is a user reporting a 'slow internet' symptom which must be bridged to the technical standard for 'packet fragmentation control' in RFC 791.
* **Target Trajectory Profile**:
  - Log Intent-to-Milestone Mapping to transition from raw observations to candidate category headers. The trajectory must explicitly document the transition from a 'layman observation' (e.g., 'sirens') to a 'candidate expert pillar' (e.g., 'Pillar 3') within the internal scratchpad to show a clear chain of reasoning. By recording 'Observed behavior X; searching for categories involving X; mapping to Standard Y', the agent proves it is following an analytical path rather than guessing. An edge case involves specifically logging the leap from a project description of 'community evacuation drills' to the 'Preparedness' pillar definition.
  - Maintain a Normalization Ledger of terminology bridges to audit the translation process throughout the reasoning chain. The agent must record how it translated the user's sensory or layman terms into the formal expert language found in the retrieved governing documents. This ledger acts as an audit trail showing, for instance, that 'packet getting lost' was successfully mapped to 'TTL expiration' in the RFC context or 'money for models' was mapped to 'Pillar 2'. This prevents subsequent synthesis steps from losing the original semantic connection to the user's raw intent.
  - Verify Taxonomy Compatibility with environment-specific metadata and jurisdictional constraints. The trajectory must show the agent checking if a discovered rule or standard actually applies to the specific project ID, version, or organization mentioned in the raw query. For example, the agent should verify if a discovered audit rule for 'MDBs' is applicable to the user's specific 'Climate Fund' scenario before finalizing the answer classification. Failure to do so results in a 'Lexical Lure' error where the agent picks a matching keyword from a document that belongs to a different project or year.
  - Execute Hierarchical Pointer-Chasing when the context identifies an explicit citation or section ID. When a retrieved document mentions a specific subsection (e.g., 'See Funding Guideline 4.2'), the logic array must immediately treat that identifier as a high-priority retrieval bridge for the next reasoning pass. The trajectory trace must record the step-by-step movement from the initial descriptive summary to the foundational parent rule array. A concrete example is moving from a project summary mentioning 'Pillar-level caps' directly to the specific document that defines the numeric thresholds for those caps.
