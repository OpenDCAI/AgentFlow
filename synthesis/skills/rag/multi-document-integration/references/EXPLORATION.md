# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement Structural Anchor Identification to bound the exploration of complex repositories or long reports. The agent must first search for 'skeleton' files, table of contents, or class headers that provide a low-noise map of how information is distributed across the environment. By retrieving a class skeleton (signatures and headers only) instead of full source code, the agent avoids context window exhaustion while maintaining a global view of the entity's relationships. For example, when summarizing a method, the agent should first retrieve the class declaration and method list to understand if the target is a helper or a core driver.
  - Execute Top-K Similarity Chunking to discover dispersed contextual dependencies in large-scale codebases. When a query targets a specific entity in a repository, the agent should initiate a vector search to retrieve the most semantically similar code fragments from adjacent files. Each chunk should be logged with its relative file path and line numbers to allow the synthesis phase to respect the physical structure of the repository. An edge case is retrieving 'Docstrings' from related functions to understand the expected interaction patterns of the target function without reading every line of logic.
  - Perform Complementary Seed Generation to resolve multi-source comparative queries. If a query identifies two or more subjects (e.g., 'Compare the 2022 and 2023 reports'), the agent must create independent retrieval strategies for each leg of the comparison. It should proactively check if 'Subject A' and 'Subject B' both exist in the retrieved pool and, if one is missing, generate a targeted supplementary query for the missing half. For instance, if the agent finds 'Amazon's income' but not 'Walmart's', it must launch a specific probe for 'Walmart 2023 income' to enable the subsequent integration.
  - Utilize Relational-Proximity Auditing to detect Information Fusion risks across fragments. The agent should actively scan retrieved fragments for sentences or code blocks that contain more than three distinct proper nouns or entity references, which are high-risk areas for misleading fusion. During exploration, it must document these overlaps as potential 'integration traps' where the relationship between a subject and an action might have been blurred by previous summarization steps. A concrete example is identifying a summary that says 'Both X and Y increased' and cross-referencing it with the raw data to ensure X didn't actually decrease while Y increased.
* **Target Trajectory Profile**:
  - Mandate Fragment-by-Fragment Evidence Accounting prior to synthesis formulation. The trajectory must explicitly list each distinct snippet, its source ID, and its specific contribution to the query before any merge logic is applied. This strict accounting ensures that the agent does not 'creatively fill' gaps with internal knowledge but relies solely on retrieved variables. For example, the scratchpad should record: 'Doc 1: Project 9% growth; Doc 2: GDPR risk is $20M; merging to show qualification.'
  - Demonstrate 'Structure-First' Navigation steps for hierarchical contexts. A robust trajectory shows the agent navigating from a high-level structure (e.g., a README or a Table of Contents) down to a specific leaf node (a function or a subsection). This path reveals a conscious understanding of the document's organization, moving from 'Step 1: Get class map' to 'Step 2: Get target method' to 'Step 3: Get related utilities.' An edge case is explicitly logging a decision to skip the 'Introduction' after determining it holds no technical specifics needed for the summary.
  - Enforce iterative 'Gap-Probing' and supplementary query cycles. The trace should vividly showcase the agent identifying a missing data point required for a multi-document synthesis and launching a second retrieval pass to find it. It must log the realization, such as: 'Current context only explains the BashOperator; missing the definition for GlobalCleanup; initiating search for GlobalCleanup utility.' This iterative behavior illustrates advanced orchestration rather than a single-shot, lucky retrieval.
  - Require Facet-Based Alignment ledgers for cross-document comparisons. The agent's intermediate reasoning must hold semantic attributes from different documents side-by-side in a 'comparison matrix' to identify deltas and overlaps. This prevents the agent from providing a vague summary of two documents and instead forces it to identify exactly what is unique or shared. A perfect example is a ledger stating: 'Original Paper: uses GraphRAG; Proposal: uses AriGraph; Delta identified in reasoning world-model mechanics.'
