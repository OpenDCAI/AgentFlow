# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Verify the presence of 'Unverifiable Detail Entanglement' for uncertain specificity. Accept only those samples where the question asks for a degree of detail (e.g., specific names, dates, or quantities) that the evidence addresses only at a high conceptual level. A valid case asks for the 'exact number of protesters' when the text only mentions 'a large group', forcing a specificity-based deflection. This ensures the benchmark measures the agent's awareness of its own knowledge boundaries.
  - Confirm ‘Binary Negation’ for false premise validation. Accept trajectories solely if a direct contradiction exists between a question’s assumption and the documented facts. For example, the question asks about the 'success' of an event that the documents describe as a 'failure'. This creates an objective, scorable rejection point where the correct answer must be 'Unanswerable' or a direct refutation.
  - Ensure 'Bridge Missingness' is the primary cause of multi-hop failure. Accept multi-hop samples only if the answer is present in the context, but the logical link or 'bridge' needed to connect the query to that answer is absent. This tests whether the agent leverages shortcut reasoning (guessing the nearby fact) or correctly identifies the broken reasoning path. A high-quality sample hides the person who performed an action, even if the action and person both appear in different sections of the same repo.
  - Maintain a 'Plausible Distractor' density of at least 4 items. Accept only those instances where the question is surrounded by several misleading but logically incorrect answer options that share high lexical overlap with the query. This prevents the model from choosing 'Unanswerable' by process of elimination when other options are obviously gibberish. Each distractor must be grounded in an actual fact from the context that simply isn't the answer to the specific query.
  - Validate 'Context Necessity' via Zero-Shot Rejection checking. Only accept samples where a baseline LLM (without context) cannot reliably determine if the question is unanswerable. Because the timelines are fictional (NeoQA style), the LLM's parametric knowledge should offer no clues. This ensures that detecting the 'missing' nature of the evidence is purely a function of retrieval and reasoning, not general common sense.
* **Rejection Criteria**:
  - Reject trajectories where the 'Missing Fact' is trivially off-topic. Discard cases where the query asks about 'Cooking' and the documents are about 'Rocket Science'. The absence of evidence must be non-trivial, where the documents *look* like they should have the answer because of high entity overlap, but still omit the decisive fact. Trivial off-topic refusals provide no signal for advanced RAG robustness.
  - Discard cases of 'Internal Knowledge Leakage' in the question premise. Reject any sample where the question accidentally provides the very fact it claims is missing (e.g., 'Given that the audit cost $50k, what was the cost?'). The question must maintain the gap, only asking for the information to see if the agent can correctly identify that it is missing from the articles. This ensures the reasoning direction is purely from Evidence to Answer.
  - Eliminate 'Vague Refusals' lacking specific justification. Reject trajectories where the model provides a generic 'I don't know' without identifying *what* exactly is missing. A robust rejection must point to the specific missing attribute or contradiction, such as 'The text doesn't mention the cost, only the robustness'. Bare refusals are indistinguishable from retrieval failures and provide poor training signal.
  - Reject 'Self-Correcting Premiums' where the question resolves its own gap. If the query asks an unanswerable question but then provides an assumption that makes it answerable (e.g., 'Assuming the cost was X...'), it no longer measures evidence rejection. The question must remain unanswerable based solely on the corpus to test the agent's ability to maintain boundaries under pressure. Any 'Assumed Fact' in the query must still require external verification to stay within the RAG paradigm.
  - Discard samples where shortcut reasoning is mathematically incentivized by the answer set. Reject if the 'Correct' (missing) answer is the only plausible numerical value in the entire context. If a question asks for a date and only one date exists in 100 documents, the agent might guess it even if it's unrelated to the question. This 'lexical lure' must be balanced with other misleading dates to ensure the rejection is a conscious logical decision.
