# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement Fictional Timeline Synthesis to neutralize the agent's internal parametric knowledge. You must generate a sequence of interconnected fictional events where each event conditions on a Knowledge Base (KB) of fictional entities, ensuring the agent cannot rely on pre-trained facts to answer. For example, by creating a fictional scandal about 'Amber Glaze Delights' rather than 'Twitter', you force the agent to strictly use retrieved evidence since no prior data on this entity exists in its weights. This strategy should prioritize 'irreversible' story paths where multiple mutually exclusive sub-plots are generated, but only one is finalized into the corpus.
  - Deploy Granularity-Gap Probing to identify 'Uncertain Specificity' traps. Start by retrieving a high-level fact about a topic, such as 'The company reported a profit', and then search for more granular sub-attributes like 'the exact percentage of profit from overseas markets'. If the granular detail is absent, you must flag this as a potential 'Uncertain Specificity' query seed. A concrete edge case involves a document mentioning a 'new certification program' without listing the criteria, which becomes a perfect target for an unanswerable question about specific 'labor and energy' rules.
  - Execute Missing-Bridge Reconnaissance within multi-hop environments. You must intentionally design retrieval sets where the 'End Node' (the answer) and the 'Start Node' (the subject) are present, but the 'Bridge Node' (the connecting fact) is meticulously removed from the corpus. The agent must log this missing link in a 'Connectivity Ledger' to verify if a logic path exists between the query and the potential answer. For instance, if Doc A mentions Person X and Doc B mentions a 2022 deal, but the document showing Person X was *at* that deal is hidden, the trajectory should identify a reasoning impasse.
  - Implement False Premise Seeding via Attribute Negation. Identify a core factual triplet in the environment, such as (School A, Receives, State Textbooks), and then intentionally generate a contradicting observation, such as (School A, is, Fully Private with No State Aid). Use these contradictions to create questions that ask about the 'State Aid amount' to see if the agent detects the premise violation. An edge case involves placing the contradicting rule in an 'Update' file that deprecates an older fact, forcing the agent to reject the question if it refers to the outdated state.
  - Utilize Diverse News Profile Generation to vary evidence perspectives. Generate synthetic articles for the same event using distinct profiles such as 'Sensational', 'Objective', or 'Skeptical'. This creates an environment where 'missing' information might be due to a specific newspaper's biases, requiring the agent to determine if *any* source contains the required fact. A concrete example is one source mentioning 'protests' and another 'celebrations', allowing for queries that ask for the 'protest count' which are only answerable from the first source.
* **Target Trajectory Profile**:
  - Mandate an explicit 'Fact-to-Constraint' Mismatch Log in the reasoning trace. The trajectory must formally itemize each constraint in the question and verify its existence or contradiction within the retrieved articles before a final summary is issued. It should record: 'Constraint 1 (Person): Present; Constraint 2 (Attribute - Cost): Absent; Decision: Deflect due to uncertain specificity.' This ensures the agent is not simply performing a keyword lookup but a logical audit of the question's premise.
  - Enforce 'Shortcut Resistance' verification for multi-hop trajectories. The agent's trace must demonstrate that it has attempted to find the bridge entity and, upon failure, consciously refused to link the start and end nodes based on simple topical proximity. A high-quality trajectory states: 'I found Entity A and Outcome C, but the link (Entity B) is missing; I will not assume A caused C.' This explicitly penalizes agents that leap from 'Subject' to 'Likely Answer' without checking the middle hop.
  - Require a 'Specificity Boundary' declaration for partial-answer scenarios. The trajectory should define the limits of its grounded knowledge, stating exactly where the evidence stops and the unanswerable gap begins. For example, it might log: 'Documents confirm that Selvia Renek wrote a blog post, but they do not mention the specific hashtag used in the post.' This granularity ensures that even if partial information is found, the agent maintains strict adherence to the required answer format.
  - Maintain a 'Premise Validation' ledger to catch deceptive queries. The agent must perform an intra-context audit to check if any factual assumption in the question is negated by the retrieved evidence. If a question asks 'Why did Company X fail?' but the evidence says 'Company X succeeded', the trace must log: 'Factual Conflict: Question assumes failure while Doc 4 confirms success; tagging as False Premise.' This behavior proves the agent is acting as an evidence-based validator.
