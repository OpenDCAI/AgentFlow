# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Coverage necessity must be absolutely critical to task success. The omission of a single targeted document or a dense sub-branch must mathematically, categorically, or factually flip the final output state. This acts as the ultimate proof that the context length itself was functionally leveraged during reasoning. A valid sample exists when removing the 49th document seamlessly alters the final computed baseline average.
  - The scale of evidence dispersion must be observably massive. Relevant data fragments must be highly distributed across vast stretches of tokens, actively testing the actual breadth and reliability of the model's extending attention window. Simply placing all facts cleanly inside the first 500 tokens of a 100k-token prompt completely nullifies the desired evaluation target. An acceptable case forces the required variables to reside at token blocks 10k, 50k, and 95k respectively.
  - Trajectories must explicitly record internal ledgers and audit trails. Bare answers generated without demonstrating a global data harvest log inside the intermediate scratchpad are considered entirely invalid and must be discarded. The internal reasoning must clearly showcase a step-by-step sequential or parallel extraction history bridging the diverse sections. For instance, the system must log 'Navigated to subsection A: found X... Navigated to subsection B: found Y' continuously.
  - The final output metric must remain tightly and rigorously scorable. Despite reading incredibly dense and sprawling contexts, the aggregated expectation must culminate in a precise extreme entity, an exact arithmetic sum, or an exact classification grouping set. Subjective essay generation over long contexts provides weak training signals and must be avoided. A perfect acceptable target is a strict JSON array of the exact top 5 performing global regions based on 200 retrieved market reports.
* **Rejection Criteria**:
  - Reject situations where one-document conversational shortcuts exist. Completely eliminate scenarios where the aggregated answer was accidentally pre-summarized in an introductory document, abstract, or executive summary table. If an agent can read the first paragraph and determine the sum of all subsequent pages, the entire exercise fails to measure exhaustive coverage. Always manually verify that summary paragraphs are neutralized before finalizing the knowledge corpus.
  - Discard environments suffering from heterogeneous format dominance. Reject situations where massive structural variances in documents (e.g., mixing complex parsed codebases with raw XML and plaintext poetry) cause extreme annotation noise rather than purely measuring attention scale. The difficulty should stem from exhausting the context, not struggling to interpret bizarrely shifting format corruptions. A rejected case resembles evaluating financial arrays hidden inside corrupted image OCR texts while surrounded by conversational chatlogs.
  - Eliminate context padding relying entirely on irrelevant token garbage. Ensure that document string lengths are not artificially inflated with pure, unrelated filler text simply to hit a 128k context mark without adding semantic pressure. The surrounding 'distractor' tokens must belong to the same domain and logically resemble the true evidence to genuinely stress the retrieval matrix. A bad example is placing one legitimate medical record surrounded by 50 chapters of a public-domain romance novel.
  - Reject omission of low-frequency entities during global profiling. Discard trajectories if the agent statistically profiles only the prominent tail of the context while lazily ignoring sparse, unique hits hidden deep within the massive distribution. Comprehensive coverage means every valid node must be accounted for regardless of its rarity. If a dataset asks for all errors and the agent only returns the 10 most frequent while dropping the 3 rare anomalies present at the end of the log, the execution is fundamentally flawed.
