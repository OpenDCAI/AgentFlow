# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Separate evidence gathering from multi-faceted operation design. The agent must retrieve raw facts, tables, or entity concepts needed, then explicitly isolate the distinct operational logic required (such as subset filtering, multi-metric optimization, or glossary application). By explicitly naming the operation prior to execution, it prevents blending search issues with computation failures. A clear edge case is retrieving a massive hardware table but explicitly documenting the required Pareto-trade-off constraint before starting the row-by-row filtering.
  - Decompose queries into weighted numeric or string constraint maps. Extract the core subject and highly specific negative qualifiers, soft budgets, or targeted glossary terms as mandatory filters. The agent must log these distinct constraints to track compliance throughout the sequence. For example, if looking for 'cars made in 1990 not in red using the official factory code', log '1990', 'NOT red', and 'Alias=FactoryCode' as distinct post-retrieval filters.
  - Identify Lexical Lures and Subject-Object Relational traps. Actively search for prominent entities that possess high frequency in the corpus but explicitly violate a minor negative constraint or have inverted actor roles (e.g., finding the 'Appellant' instead of 'Respondent'). The agent must perform explicit Relational Triplet Mapping (Subject-Action-Object) to ensure roles aren't flipped during complex table or constraint resolution. An edge case is logging famous explorers like Magellan but intentionally discarding them as 'Negative Candidates' because they violate a minor birthplace constraint.
  - Apply Multi-Metric Normalization for optimization and glossary mappings. If evaluating trade-offs or domain-specific language, transform layman phrases ('fast enough', 'the defender') into precise bounded numeric parameters ('<50ms') or strict glossary dictionary translations before evaluating the candidates. The agent must explicitly document this mapping to ensure subsequent sorting algorithms use clean parameters. For instance, documenting 'Interpreting low power as <150mW based on the retrieved context manual' anchors the mathematical operation in the provided knowledge base.
* **Target Trajectory Profile**:
  - Raw extraction strictly precedes transformation and multi-objective ranking. The trace must log all localized variables, matching table cells, or text candidate pools prior to any math execution, lexical substitution, or Pareto filtering. Merging the data gathering and algorithmic operation into a single uncheckable paragraph prevents validation of the reasoning path. A good trace isolates the raw array before running the 'intersection' or 'find-minimum' step.
  - Maintain a per-step constraint fulfillment ledger or Best-Fit Matrix. The trajectory must explicitly evaluate candidates against the identified hard constraints/budgets and document a pass/fail check for each entity. When addressing trade-offs, it should hold top candidates side-by-side to highlight exactly which metrics were gained and lost. For example, logging 'Candidate A: Best Power (PASS), Worst Latency; Candidate B: Balanced' proves the model objectively weighed independent variables rather than randomly selecting.
  - Execute an explicit Authoritative Lexical and Relational audit. The trace must enforce actor-role verification and formal glossary term lookups when output constraints are specified by the prompt or the text structure. It should narrate the application of specific formats, such as converting standard citations to a specific corpus bracket style or swapping a word for its glossary equivalent. Without this structural verification, the agent defaults to baseline language model tendencies and hallucinates unofficial formats.
  - Final answer strictly respects computational boundaries and requested output formats. The terminal generation completely omits any violating entities, adheres perfectly to the mathematical logic executed, and returns the result in the exact string literal, JSON schema, or numeric unit requested. A correct underlying integer or entity wrapped in a colloquial summary instead of the requested rigid table layout or official nomenclature still constitutes an operational failure for this skill.
