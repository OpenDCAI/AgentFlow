# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Retrieval alone is insufficient for answering. The answer must indisputably require an explicit multi-faceted operation such as mathematical optimization, intersecting negative constraints, or strict application of a formal glossary. If the final derived answer was already cleanly stated inside the unadulterated corpus text without needing to process independent filters, it lacks execution rigor. The required computational or formatting step serves as the core evaluation hurdle.
  - Presence of 'Competing Objective' paradoxes or 'Knowledge Overshadowing' tests. The correct candidate must require balancing conflicting numerical thresholds, or accurately resist relying on a universally famous entity that violates a single localized negative constraint. This provides proof that the agent genuinely respected the structured operational boundaries rather than guessing based on pre-trained popularity metrics. An accepted trajectory clearly rejects the 'famous' incorrect hit in favor of the obscure but mathematically perfect hit.
  - 100% Terminological Parity and Objective Verifiability. The agent's applied reasoning step, including filtering, sorting, arithmetic, and lexical-alias representation conversion must be precisely verifiable by a reviewer. There can be absolutely no subjective interpretation or hallucinatory gap-filling allowed in the logic sequence. The final output must perfectly match the string-literal provided in the retrieved glossary or the computed integer derived from the table constraints.
  - Output schema completely resists interpretive divergence. The terminal answer expected from the sample query should possess an extremely stable schema, such as a localized table row, an isolated computed value, or a formal term. This objective target allows precise data evaluation at scale without annotator discrepancies. Open-ended interpretive essays evaluating trade-offs are unsuitable; responses must be tightened to single, explicitly optimal choices based on the budget math.
* **Rejection Criteria**:
  - The post-processing operation or constraint is merely decorative. Reject samples where the additional mathematical calculation, format conversion, or constraint filtering doesn't actually narrow down the dataset or meaningfully transform the information. The question must force the logic matrix to act identically to a programmatic execution script. If removing the constraint requirement yields the same entity via basic dense retrieval, the sample offers weak supervision.
  - Famous Subject Bias or Role Flipping masks underlying extraction logic. Discard trajectories where the agent ignores rigorous text filters and returns a generically famous entity, or improperly identifies the 'Patient' as the 'Doctor' because of latent memory assumptions. Any instance where basic semantic mapping assumptions overwrite the actual constraints embedded in the text table must be purged immediately. These are reasoning hallucinations rather than successful post-processing.
  - Optimization logic relies on Hidden Math or unstated domain translations. Reject contexts where an optimization weight equation or an ambiguous technical terminology dictionary isn't directly integrated into the prompt or the retrieved references. The agent must never arbitrarily invent a ranking formula or translation dictionary that sits outside the provided evidence boundaries. A sample demanding complex accounting knowledge not defined in the source files is completely unfair contextually.
  - Format corruption fundamentally masks table and relational logic parsing. Reject structured-evidence cases where table headers, tabular boundaries, or relational role descriptors are mangled so badly that assigning operands requires random guessing. The model should be challenged by computational complexity and dense constraints, not confused entirely by artificially irrecoverable formatting degradation. Clean but dense algorithmic structures are the optimal target for this capability.
