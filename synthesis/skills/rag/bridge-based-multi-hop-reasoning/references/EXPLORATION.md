# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify candidate bridge entities or topics. During exploration, mine the corpus for repeated entities, concepts, or relation labels that connect otherwise separate documents. Record each candidate bridge alongside the documents it links and the distinct claim each provides. A bridge is useful only if it enables a reasoning chain rather than mere topical clustering.
  - Execute Intent-to-Milestone Decomposition for procedural intents. Upon receiving a procedural request, use a reasoning pass to identify the 'milestone' states required to reach the conclusion (e.g., 'Step 1: Authenticate', 'Step 2: Access Settings'). Probe the knowledge base specifically for transitions that fulfill these intermediate milestones, binding the multi-hop sequence together.
  - Force at least one explicit hop boundary. Construct exploration traces where the answer cannot be read directly from a single document and instead requires crossing at least one defined bridge or UI phase. Attempt single-document answering and keep exclusively those cases that still fail.
  - Deploy Fragmented Path Reconnaissance. Intentionally look for 'near-miss' nodes or proxy connections when an explicit transitional edge (a direct physical bridge) is missing between two required states. Formulate cases where the agent must logically step through a parent directory or a shared category to restore the reasoning hop.
* **Target Trajectory Profile**:
  - Bridge declaration strictly before inference. A good trajectory formally names the connecting entity, hierarchy node, or intermediate milestone before showing how each document contributes to it. This structural transparency ensures the reasoning remains anchored in verifiable graph nodes or text mentions.
  - Per-hop evidence retention and verification. Maintain an ongoing ledger after each hop. Keep the intermediate conclusion explicitly in the scratchpad (e.g., 'Milestone [Search] reached via Screen A; next sub-goal [Filtering] pending') so the subsequent inference has a continuous, visible foundation.
  - Wrong-bridge elimination logic. The trajectory should briefly note why competing bridge candidates or distractor UI buttons were rejected when navigating the retrieved set. This trains the agent to treat bridge selection as an evidential elimination decision.
  - Final inference is rendered last. Only after the multi-hop network or sequential menu path is completely constructed should the agent produce the final yes/no, path list, or computed answer. Premature answering usually represents an assumed rather than grounded hop.
