# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - 100% Logical Isomorphism between source connectives and target transitions. Accept the trajectory only if the translated document preserves the exact logical relationship (e.g., cause-and-effect) found in the original source article. Any shift that turns a contrast into an addition results in an immediate rejection. Use a verification step where the agent summarizes the 'Logic Path' of the translation to ensure it matches the source's intent.
  - Strict Register Consistency across all transition markers in the target string. The sample is authorized if every connector matches the domain's formality level as established in Phase 1. For instance, a medical report must not use casual street transitions, and a casual blog must not use archaic legal connectors. The validator checks if the target synonyms chosen are collectively appropriate for the document's tagged sub-genre.
  - Syntactic Naturalness and locale-appropriate positioning of connectives. Accept the sample if the transition markers are parked in the correct part of the target sentence according to the grammar of that locale. This prevents 'Translationese' where the connective is literal but incorrectly placed, breaking the natural reading rhythm. A successful case might move a starting 'However' to a mid-sentence particle if the target language (like Japanese) requires it.
  - Preservation of Implicit-vs-Explicit Logic balances according to the target script. Accept trajectories that successfully navigate the 'Discourse Delta' between a concise source and a more verbose target. The model must show it didn’t just add words randomly but used connectors to bridge semantic gaps created by the translation process. A valid sample proves that the final text is as 'easy to follow' as the original for a native speaker.
* **Rejection Criteria**:
  - Disjointed Flow or 'Staccato' Sentence Strings. Reject any sample where the sentences are grammatically correct but fail to link together into a coherent narrative. This typically happens when an agent translates sentence-by-sentence and ignores the connective logic. A clear rejection is a 3-sentence argument where the result of the logic is disconnected from the premises due to a missing or wrong transition.
  - Contradictory or Nonsensical Connective Mapping. Discard trajectories where the agent uses a transition word that creates a logical impossibility in the target language. For example, if the source says 'A happened, so B happened,' and the translation says 'A happened, however B happened,' it is a catastrophic failure of discourse handling. This ensures the agent isn't just 'guessing' transitions based on frequency.
  - Instruction-Register Mismatch for transitions. Reject results where the agent uses 'low-reg' connectors (like 'so' or 'but') when the instruction or context explicitly demanded the 'high-reg' professional translation typical of DocHPLT standards. A rejection trigger occurs if a technical paper's transition is reduced to a simple 'And' without any additive nuance preserved. This protects the agent's professional status.
  - Omission of Hard Logical Constraints within a discourse chain. Reject the trajectory if a specific filter or causal constraint mentioned in sentence 1 is completely unacknowledged by the connective choice in sentence 2. The agent must never simplify the document's logic to the point where the causal links are broken. For example, ignoring a 'Therefore' marker turns an explanation into a series of random facts, which is an accuracy violation.
