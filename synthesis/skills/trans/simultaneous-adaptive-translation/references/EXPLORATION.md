# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement a Latency-Aware Chunk Segmentation strategy by prompting a high-capability model to act as a professional interpreter. The agent must provide the source text and request an output segmented into three granularities: brief phrases (low), clause-long segments (medium), and full sentences (high). An edge case occurs when the semantic unit is split across a prepositional phrase, in which case the segmentation must be rejected in favor of keeping the phrase intact for translatability.
  - Enforce a Monotonicity Constraint during the chunk-alignment phase to ensure the source and target chunks follow a parallel order. The agent must verify that each target chunk corresponds directly to its source chunk without requiring rear-sentence information for basic meaning. A failure point is detected if the target translation of the first chunk requires knowledge of a verb found only in the final source chunk, which violates the SiMT paradigm.
  - Execute a Sequential Interleaving transformation on the aligned chunks by alternating source segments with target translations. The agent must insert explicit signaling tokens such as <|end-of-read|> after every source fragment and <|end-of-write|> after every target fragment. For example, a successful data seed must follow the exact structure [Source_Chunk1, <|eor|>, Target_Chunk1, <|eow|>], which mimics the streaming reality of an interpretative environment.
  - Apply Latency Indicator Labeling to every synthesized training sample to create a control mechanism for inference. Each sample MUST be prefixed with a task prompt specifying 'low latency', 'medium latency', or 'high latency' to allow the agent to associate different segmentation patterns with specific user needs. An edge case involves 'interpolation' where no specific label is provided, requiring the agent to default to a medium latency behavior that balances safety and speed.
* **Target Trajectory Profile**:
  - The trajectory must showcase Adaptive Read/Write logic where the decision to stop reading is triggered by semantic completeness. Instead of reading a fixed number of tokens, the agent's log should indicate: 'Observation: Detected complete noun phrase; Action: Emit <|end-of-read|> to start translation.' A negative example to avoid is a trajectory that waits for the entire sentence regardless of a low-latency instruction.
  - Consistent Reuse of KV-Cache must be documented through a strictly auto-regressive generation trace. The trace should demonstrate that target tokens are appended directly to the current context without re-calculating the prompt or prior chunks. The agent logs: 'Action: Appending target token to KV-cache; Observation: No prompt re-computation required,' ensuring inference efficiency matches the 'Offline' speed benchmarks.
  - Demonstrated Monotonic Translation Fidelity where the output remains aligned with the source order even for non-isomorphic language pairs. The trajectory is successful if it correctly reorders local phrases while maintaining the global sequence flow of the source chunks. A concrete test is translating a German VO sentence into an English SVO sentence while ensuring the temporal markers remain consistent with the input stream.
  - Explicit Latency-Control following through the use of indicator tokens. The trajectory must prove that a 'low latency' prompt results in more frequent switching between reading and writing than a 'high latency' prompt. If the agent receives a 'high latency' instruction but outputs tiny, fragmented word-for-word chunks, the trajectory fails the adaptive policy requirement.
