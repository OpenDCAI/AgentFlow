# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Compliance with Average Latency (AL) thresholds based on the requested latency level. Accept the trajectory only if the AL—representing the delay between source input and target output—is significantly lower than the total sentence length for streaming tasks. For example, a 'low latency' task should have an AL of 2-3 words, while a 'high latency' task can exceed 8-10 words. If the delay is constant regardless of the instruction, the sample fails the adaptation check.
  - 100% Target Language Purity and Signal Placement accuracy. Accept the sample only when the <|end-of-read|> and <|end-of-write|> tokens are positioned correctly as logical gatekeepers. Each target segment must be enclosed exactly between These tokens, and any target text appearing outside a 'write' window is an automatic rejection. An edge case to reject is an agent that continues translating after the source stream has paused without emitting the write signal.
  - Fidelity to Monotonic Semantic Mapping as verified by chunk-level alignment. The selection filter checks if each generated target chunk accurately reflects its corresponding source chunk without 'hallucinating' content from future chunks not yet read. A valid sample ensures that the translation of the second source chunk does not include details only found in the fourth source chunk. If 'future-leakage' is detected in the translation, the trajectory is discarded.
  - Preservation of Offline Translation Competence as a baseline metric. The selected sample must demonstrate that the SiMT capability does not degrade the agent's ability to translate full sentences once the entire stream is received. The agent compares the cumulative SiMT output with a standard offline version; if the SiMT version is significantly less fluent despite having all information, it is rejected for poor adaptive quality.
* **Rejection Criteria**:
  - Fixed Policy Rigidness / Wait-k Defaulting. Reject trajectories that exhibit the 'Wait-k' behavior of reading a static number of words regardless of sentence structure. As demonstrated in common failures, a fixed policy leads to garbage prefixes when a thought is incomplete. Discard any sample where the agent emits a translation chunk that is grammatically incoherent because it forced a translation at a fixed interval.
  - Instruction-Latency Mismatch and Indicator Ignoring. Reject any trajectory where a 'low' latency instruction produces 'high' latency behavior (waiting for the full text) or vice-versa. The model must show measurable behavioral shifts based on the prompt's latency token. For instance, if 'high latency' results in the same fragmented output as 'low latency', the adaptive policy has failed to learn the latency-aware segmentation.
  - Hallucinated Prefixes or 'Source-Filling' attempts. Reject samples where the agent 'invents' initial words to start a sentence when it hasn't read enough of the source yet. This is a typical pathology in simultaneous systems where the model 'guesses' the subject. A clear rejection is an agent translating 'The...' when the source only contains 'Wait...', as this introduces factual errors into the stream.
  - KV-Cache Recomputation and Latency Bloat. Reject any trajectory that involves re-sending the entire prompt history at every new chunk increment, as this violates the efficiency requirement. The selection layer must verify that the process is strictly auto-regressive. If the log shows a 'Re-encoding prompt' step for setiap source update, it is rejected for not being 'as efficient as offline'.
