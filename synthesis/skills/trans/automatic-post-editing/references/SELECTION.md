# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - 100% Correction of Identifiable Errors in the draft string. Accept the trajectory only if every specific grammatical, semantic, or terminological fault detected in the exploration phase is rectified in the final answer. The validator compares the 'Draft' against the 'Answer'; if an entity omission was spotted but not fixed, the sample is rejected. A valid sample ensures that the corrected text is a measurable improvement over the hypothesis.
  - Zero 'Post-Editing Hallucination' where the agent adds unprovided facts. The results are only authorized if the refined translation stays strictly within the semantic boundaries of the provided source text. The agent checks if the 'Word Count' or 'Information Density' changed due to unrequested elaboration. For instance, if the agent adds a sentence explaining the character's motivation that wasn't in the source, the sample is discarded.
  - Isomorphism of Semantic Intent for Search and Fact Queries. Accept the samples that show the agent successfully corrected a draft to reflect the precise technical intent (e.g., changing 'most frequent' from 'aam' to 'adhik baar'). This is verified by ensuring the target terms match professional or native-speaker standards for that specific communicative domain. A successful case improves the 'Retrievability' or 'Usability' of the text for the end user.
  - Perfect Morphosyntactic Agreement in the target-language result. Accept only if the final answer follows all grammatical rules (gender, case, number) of the target locale, resolving any 'clashed' structures in the draft. The selection filter checks if the agreement between the subject and verb is consistent. For example, a draft with a masculine verb for a female subject must be corrected to the feminine form.
* **Rejection Criteria**:
  - Stylistic-Only Paraphrasing with no Accuracy Benefit. Reject the sample if the differences between the draft and the answer are merely synonymous word swaps that don't fix an underlying error. Correct post-editing requires a clear 'Error-Correction' signal; if 'happy' is just changed to 'glad', the trajectory is too weak to evaluate the skill. This prevents 'lazy' synthesis that defaults to arbitrary preference.
  - Literal Dependency on a Corrupted Draft. Reject any trajectory where the agent fails to overrule the draft's error despite the source text providing the correct information. The source text must always serve as the master truth. A clear rejection is a case where the source says '5' and the draft says '8' and the agent keeps the '8' because it was 'in the draft'.
  - Source-Language Leakage during the refinement process. Reject the results if the agent, in an attempt to follow the draft, accidentally re-introduces words or structures from the original source language. This often happens when models get confused by the tri-part structure (Source, Draft, Target). A rejection trigger is seeing English punctuation or symbols in a Chinese post-edited result.
  - Omission of Technical Entities from the final string. Reject the trajectory if the agent dropped a proper noun, a chemical formula, or a specific citation to make the sentence 'flow' better. Domain-specific translation demands that all 'anchors' from the source remain present. If the 'Draft' omitted an entity and the agent failed to restore it from the 'Source', the sample is rejected for failure of fidelity.
