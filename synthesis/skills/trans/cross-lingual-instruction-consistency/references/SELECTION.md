# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - 100% Target Language Purity Compliance (LID > 99%). Accept a sample only if the translated output is entirely in the language requested by the meta-instruction, with zero unauthorized leakage from the prompt or context language. First, run a character-level language identification check on the final result. A definitive rejection occurs if an English-to-Spanish instruction for German text results in a response that contains German words or English commentary.
  - Zero Task-Alignment Drift across n x n configurations. The sample is authorized only when the agent performs the correct underlying task (summarization, extraction, etc.) as defined in the meta-instruction, regardless of the language mismatch. First, compare the 'Model Task' (e.g., 'ChatSummarization') with the output content. For example, if the prompt asks to summarize a German chat in Dutch, but the agent provides a full word-for-word translation in Dutch, the sample is rejected for task-drift.
  - Isomorphic Semantic Mapping of Case Entities. Accept the trajectory if all key IT entities, case numbers, and timestamps from the context are faithfully represented in the target language. First, extract a list of 'Key Entities' from the source context (in L1) and verify their corresponding presence in the output (in L2). A valid sample ensures that a 'Version 1.0.11' in a German source is not lost when moving into a Dutch target summary.
  - Strict JSON Schema Integrity with Language-Correct Keys. If a structural format like JSON is requested, accept the sample only if the keys and values are in the correct language as specified. First, parse the JSON to verify syntax, then check if 'Main Problem' was correctly translated into the target language value (e.g., 'Hoofdoorzaak') as part of the translation task. If the JSON structure breaks due to the inclusion of non-English characters, the sample is rejected.
* **Rejection Criteria**:
  - Instruction-Context Language Collision (Language Leakage). Reject any trajectory where the agent responds in the same language as the context (e.g., German) when the instruction explicitly requested a different target (e.g., Dutch). This is a known failure mode where models 'latch' onto the context language. A clear rejection is a case where the agent translates a French text into French because it saw French context and became 'confused'.
  - Positional Formatting Collapse / Rule Omission. Reject the sample if the agent fails to output the correct format (JSON, XML, etc.) because the formatting instructions were separated from the meta-instruction by a long context block. First, check if the output matches the required format. If a 'JSON' instruction was given at the top but the agent outputted 'Plain Text' because the context was 2000 tokens long, the sample is a failure of positional robustness.
  - Low-Resource Quality Degradation (The 'Japan/Dutch Gap'). Reject outcomes that show a significant drop in 'Faithfulness' or 'Completeness' specifically for Japanese or Dutch pairs, as identified in the enterprise benchmark. First, score the quality of the translation; if it contains hallucinations or omits more than 30% of key events from the source, it is rejected. This prevents the synthesis of 'garbage' data for challenging linguistic targets.
  - Instructional Metadata Leakage in Target String. Reject any response that includes 'preamble' text in the instruction language (English) such as 'Here is your translation:' or 'Sure, I can help'. For enterprise n x n tasks, the output must be clean and target-script only. A rejection trigger occurs if the agent includes English meta-commentary when the user requested a pure Japanese summary of a French document.
