# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement a Language Matrix Mapping pass to identify the three distinct linguistic vectors in the environment: the Meta-Instruction Language (prompt), the Source Content Language (context), and the requested Target Language (output). First, use a language identification model to tag each block of text, then verify if the requested output language differs from the prompt and context. A concrete edge case involves a prompt in English that provides a French customer case but asks for the final answer in Spanish, requiring the agent to lock the Spanish output constraint before processing the French text.
  - Extract cross-lingual intent markers to ensure the task's directionality is anchored against linguistic noise. The agent must parse the meta-instruction to determine the exact 'Target Language' identifier (e.g., 'Dutch', 'Japanese', or 'Brazillian Portuguese') and record it as a high-priority state variable. First, locate the language keyword in the instruction, then perform a cross-reference check to see if that language matches the source or prompt. For example, if the prompt says 'Translate to Dutch' but the context is in German, the agent must explicitly log that the output must NOT be German.
  - Identify positional stressors within the task components to mitigate sensitivity to instruction placement. The agent should analyze the prompt layout, noting if formatting rules (like JSON instructions) are located at the beginning, middle, or end of the text stream. First, map the sections of the prompt into a 'Positional Map', then evaluate if reordering these sections would impact the agent's ability to recognize the target language. An edge case involves a long context block that pushes the 'Output in Japanese' instruction to the very end, which often causes weaker models to default back to English.
  - Apply low-resource vulnerability checks for specific language pairs like Japanese or Dutch. During exploration, the agent should flag tasks involving languages that exhibit high 'Quality Delta' drops in enterprise benchmarks to apply extra validation steps. First, calculate the 'Resource Rank' of the target language, then initiate a deeper semantic-check for technical entities if the language is Japanese or Dutch. For instance, if the context is an IT issue in Japanese, the agent logs 'High Complexity: Japanese context' to trigger more rigorous decoding of technical proper nouns.
  - Perform a Source-Instruction Boundary Audit to ensure context tokens do not bleed into the meta-logic. The agent must use structural markers or tags (like 'Doc 1' or '{{case_details}}') to define the rigorous wall between what is 'to be translated' and 'how to translate'. First, define the start/end coordinates of the context block, then verify that the language of the context does not influence the grammar of the meta-instruction logic. An example is an agent that starts using German grammar in its internal chain-of-thought simply because the provided case details were German.
* **Target Trajectory Profile**:
  - Demonstrates explicit 'Linguistic Isomorphism' where the output language strictly matches the requested target language regardless of the prompt or source language. A high-quality trajectory must show the agent verifying its output against the target constraint: 'Instruction requested Dutch; verifying that no English or German tokens are leaked into the final response block.' This is the primary metric for successful cross-lingual robustness.
  - Prioritizes 'Instruction Disentanglement' by resolving embedded linguistic signals correctly. The trajectory should document the agent identifying the 'Meta-Instruction' as the master command that overrides any linguistic traits found in the 'Source Context'. The log records: 'Noted context is in Japanese; meta-instruction commands Portuguese output; proceeding with PT-BR generation despite Japanese influence.' This prevents the 'Source-Language Default' failure mode.
  - Illustrates 'Positional Independence' where the agent successfully follows rules regardless of their location in the prompt. A robust path shows the agent extracting formatting and language constraints even when they are buried between long blocks of context. The trace states: 'Located JSON output and Dutch language requirements at the end of the long context block; confirmed alignment before generation.' This directly addresses the positional sensitivity found in large-scale enterprise LLM evaluations.
  - Features a 'Technical-Entity Preservation' check inside the target language syntax. The trajectory captures the agent's logic for mapping technical terms (like 'AWS IAM' or 'ECRImageScan') across the language barrier without losing the entity's functional meaning. The log notation: 'Mapped English 'IAM policy error' from German context to Dutch 'IAM-beleidsfout'; ensuring the technical identity is preserved.' This proves the agent is performing domain-specific translation rather than generic text replacement.
