# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - **Trace-backed solvability.** Accept a trajectory only if every critical translation decision can be tied to a specific observation already present in the exploration record. First point to the exact clue, then show the action that used it, and finally verify that the final answer reflects that action. For example, if the trace claims the agent preserved a URL but the logged output silently altered it, reject the sample.
  - **Capability isolation.** Accept the sample only when lexical-substitution prompt robustness is the main skill being exercised and no stronger uncontrolled factor dominates outcome quality. First remove any accidental confounders, then ask whether a simpler baseline without the target capability could still succeed for the wrong reason, and finally keep the sample only if the answer is no. As an edge case, reject any example where external world knowledge, rather than the intended capability, is doing most of the work.
  - **Determinable target output.** The trajectory must support a final answer that is either uniquely correct or at least narrowly constrained enough to evaluate reliably. First check whether protected literals, glossary items, or discourse choices are fixed by evidence, then verify that alternative outputs can be meaningfully scored, and finally keep the example only if the evaluation boundary is sharp. For instance, if two radically different renderings would both pass with no principled preference, the item is too loose.
  - **Observable error contrast.** Accept only trajectories where the most likely failure output is qualitatively different from the success output in a way a reviewer can spot. First define the failure class, then compare it against the approved answer, and finally confirm that the distinction matches the target capability. A useful example is literal proverb output versus idiomatic proverb output; a weak example is two almost identical phrasings whose difference does not expose the intended skill.
* **Rejection Criteria**:
  - **Hidden or missing evidence.** Reject the sample if the trajectory relies on information that is not actually present in the environment, even if the final translation looks plausible. First inspect the trace for unstated assumptions, then remove any step that depends on outside inference, and finally discard the example if the chain no longer holds. A common edge case is a pronoun-resolution item whose required antecedent never appears in the provided context.
  - **Overloaded difficulty.** Reject items that combine too many major challenges at once, because they produce noisy data that cannot be cleanly attributed to lexical-substitution prompt robustness. First count the independent hard factors, then identify which one dominates the failure risk, and finally discard the sample if attribution is ambiguous. For example, a prompt-noise case that also includes a long legal document and a dense glossary is unsuitable unless one can clearly isolate the primary stressor.
  - **Triviality after perturbation.** Reject any sample where the injected challenge is so weak that the intended capability is barely exercised. First compare the corrupted or constrained version with its clean counterpart, then estimate whether a simple template-matching system would still pass, and finally discard the example if the answer is yes. A typo sample with only an extra comma, for instance, is too easy to be informative.
  - **Output ambiguity that cannot be audited.** Reject the trajectory if the final translation cannot be checked with a grounded rubric tied to the trace. First test whether reviewers could explain why one answer is better than another, then inspect whether the criterion depends on private preference, and finally drop the sample if auditability fails. As an example, do not keep a style-only sample whose scoring depends entirely on vague personal taste without any anchored evidence.
