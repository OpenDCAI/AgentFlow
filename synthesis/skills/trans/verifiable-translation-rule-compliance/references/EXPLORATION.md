# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Formulate a pristine linguistic baseline before injecting rigid architectural rules. Extract clean conversational or technical text. Confirm it resolves smoothly in the target language. Then meticulously inject specific verifiable constraints: explicit XML <tags>, specific {PLACEHOLDERS}, exact mathematical currency conversions, or hard token-count/syllable bounds.
  - Isolate programmatic limits from grammatical flows. Build environments where rigid parameters—like an English database schema ID embedded into a French sentence, or a strict 8-syllable per line limit—require the agent to contort its linguistic flow to perfectly accommodate the non-negotiable rule. Ensure the rule is physically trackable via regex or counting scripts.
  - Apply structural chunking constraints for deeply encapsulated data. When facing texts nested heavily in LaTeX, XML, or poly-scriptal sequences, establish boundaries. Calculate token density and mark where the agent must stop translating and retain the native characters to prevent tag deletion or context bleed.
  - Log the explicit procedural execution path. The exploration trace must separate the mathematical or formatting task from the phrasing task. First, locate the protected string/tag. Second, lock it. Third, determine the surrounding target syntax. Finally, combine them. This verifies procedural compliance.
* **Target Trajectory Profile**:
  - Prioritizes computational rule fidelity over optional stylistic smoothing. The trajectory shows the agent actively parsing verifiable items (URLs, HTML headers, {VARS}) and logging their strict retention. The trace highlights: 'Identified <title> XML tag as protected structural string; keeping wrapper unchanged.'
  - Demonstrates structural persistence across complex syntax constraints. The agent explicitly proves it navigated mathematical boundaries (e.g., counting syllables or morae precisely) and adapted its vocabulary to fit the hard limit without sacrificing meaning.
  - Features transparent calculation points. For instances requiring conversion (dates, currencies) or counting (syllable constraints), the log must feature the objective calculation step before output generation. For example, 'Counted 7 syllables on line one; substituting synonym to meet exact 8-syllable mandate.'
  - Contains clean observable error contrast thresholds. The trace must naturally highlight what a failure mechanism looks like. If an incapble model modifies an XML tree or translates a `{USER_ID}` placeholder, the boundary of failure must be blatantly obvious to validation scripts.
