# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement 'Behavior Gap Probes' by comparing an agent's response to an expert-annotated gold response in a Teacher-Forcing context. The explorer should feed real user-consultant dialog history into the agent and log where the model's knowledge utilization diverges. For instance, if the expert synthesizes a 500-word manual into 20 words, but the agent outputs 200 words, tag this as a 'Low Compression' gap. Execute this by recording the ROUGE-1 precision and Compression Ratio calculated against the retrieved tool observation for every turn.
  - Execute 'Knowledge Synthesis Divergence' simulations where the agent is provided with intentionally redundant or verbose internal search results. The goal is to see if the agent can effectively 'digest' the data into few-shot human-like insights or if it defaults to verbatim copying. To execute this, provide three different knowledge chunks about the same topic (e.g., three overlapping return policy updates) and monitor if the agent identifies the 'Absolute Truth' among them. An edge case is a response that technically includes the answer but is buried under 10 sentences of irrelevant text.
  - Utilize 'Complex Troubleshooting Seeding' from the PCS (Product Customer Support) scenario where tasks require multi-step reasoning over external knowledge. Identify situations where the user has a specific error code that relates to multiple potential root causes in a KB document. The explorer must verify that the agent doesn't just list all causes, but uses 'Intent Filtering' to ask for the user's specific system version or symptoms first. Log the 'Dialogue Act Diversity' to ensure the agent uses acts like 'request' and 'inform' in a ratio that matches human experts.
  - Execute 'Tool-Observation Sensitivity' tests by varying the density of information returned by the search tools. In one path, provide a clean, concise tool result; in another, provide a noisy result with irrelevant metadata. The explorer logs whether the agent's output becomes 'Noisy' in response to the noisy tool result. A successful trace demonstrates the agent's ability to maintain a 'Clean Persona' despite receiving 'Unstructured Backend' data, effectively shielding the user from the raw database complexity.
  - Perform 'Teacher-Forcing Performance Audits' where an LLM-as-a-judge scores the agent's behavior on the metrics of Coherence, Specificity, Satisfaction, and Effectiveness. Each exploration session should terminate with a performance report that correlates the 'Behavior Gap' (how much it diverged from the expert) with the final satisfaction score. A critical edge case involves an agent that is 'More Specific' than the human but 'Less Effective', identifying instances where 'Information Dumping' actually harms the user experience.
* **Target Trajectory Profile**:
  - The trajectory MUST demonstrate a high 'Compression Ratio' relative to the tool observation, meaning the response effectively condenses the retrieved data. The log should explicitly record: 'Knowledge Length: 400 words; Response Length: 40 words; Compression: 0.9'. If the compression ratio is below 0.5 for non-critical explanations, the profile is rejected for 'Verbatim Over-Copying'. A high-quality profile shows the agent using its own words to explain a technical mechanism rather than just echoing the manual's jargon.
  - Exhibit 'Expert-Aligned Dialogue Act Selection' where the distribution of acts (greet, inform, request, reqmore) mirrors technical support experts rather than chatty assistants. The profile must show the agent using fewer 'Excessive' acts (like unnecessary greetings) and focusing on 'Inform' and 'Request' acts as task complexity grows. For example, in a troubleshooting turn, the agent should prioritize asking for the product version before explaining a fix. If the agent uses 5 different dialog acts in a single turn for a simple query, it is flagged as a 'Behavioral Misalignment' failure.
  - Require evidence of 'Strategic Tool Invocation' where the agent only calls the KnowledgeLookup or DB tool when actually needed to resolve a knowledge gap. The trajectory log must show that the agent does not 'Double-Tap' tools—calling the same search twice with identical parameters—or call tools that have zero relevance to the current turn context. An edge case is an agent that correctly identifies that the user's follow-up doesn't require a new search because the previous result already contained the answer.
  - Demonstrate 'Numerical Anchor Reconciliation' specifically during information-volume scenarios. The trajectory log must record the agent identifying a high result count (e.g., 25 entries found) and following a 'Narrowing Policy' (ask user for area/price) instead of listing all 25. This ensures the synthetic data supports a 'Service-Oriented' agent that prevents user overload. A successful profile captures the agent saying: 'I found 25 matches; to help narrow this down, are you looking for a specific neighborhood?'
  - Feature 'Grounding-to-Intent Convergence' where the final response explicitly reconciles the retrieved fact with the user's *unstated* need. The log should document how the agent extracted a technical detail (e.g., 'Requires iOS 15+') and translated it for the user (e.g., 'You will need to update your phone first'). This demonstrates that the agent 'digested' the information to create a 'Meaningful Insight' rather than just relaying text. If the transition between retrieval and response lacks this 'Synthesis' step, the profile is rejected.
