# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Verify a 'Synthesis-over-Copying' standard by calculating the ROUGE-1 precision between the response and the knowledge chunk. Accept a trajectory only if the ROUGE-1 precision is lower than 0.7 for general descriptions (indicating original phrasing) while maintaining 100% accuracy for entities and numbers. Any response that is a 90% character-match for a long paragraph of retrieved text is rejected as a 'Behavioral Failure' of the LLM.
  - Demand 'Dialogue Act Parsimony' ensuring the agent doesn't exceed 2-3 distinct dialog acts per turn in technical support contexts. The selection phase confirms that if a human expert used exactly one 'Inform' act, the agent didn't use 'Greet + Inform + Recommend + Request + Reqmore'. This prevents the 'Verbosity Bias' typical of zero-shot agents. A successful sample shows the agent being as 'Efficient' as a human peer in the same context.
  - Confirm 'Protocol-Driven Tool Efficiency' by auditing the turn-by-turn tool use against the PCS (Product Customer Support) expert benchmark. Accept trajectories only when the agent's tool choice at Turn N matches the expert's tool choice with at least an 80% F1 overlap. For instance, if the prompt context implies a screen-share is needed for diagnosing a graphics error, the agent must select 'ScreenShare' rather than just the 'KnowledgeLookup' tool.
  - Check for 'Actionable Insight Generation' where the agent's response provides a clear 'Next Step' derived from the retrieved content. The selection module must confirm that the response doesn't end in a 'Knowledge Cul-de-sac' (e.g., 'I found the manual here it is'). Instead, it must offer: 'Based on the manual, you should [Action].' If the response lacks this 'Synthesized Recommendation', it is rejected for low 'Effectiveness' based on the PCS performance metrics.
  - Assess 'Quantitative Factual Anchor' consistency across multi-turn histories. The selector verifies that if a search returned 5 available items in Turn 2, the agent doesn't refer to them as 'all 7 of those' in Turn 3. This ensures that the 'Reconciliation' is not just local to the turn but persistent across the session state. A hard rejection occurs if the agent misinterprets the result count of a search provided in its own immediate history.
* **Rejection Criteria**:
  - Reject 'Redundant Result Dumping' where the agent ignores the volume-narrowing policy and lists a massive amount of technical jargon from the KB tool. Any instance where the agent outputs more than 50% of the raw KB tool result without editing or summarizing it is grounds for immediate purging. This is consistent with the paper's finding that LLM agents are significantly more 'verbose and less grounded' than human experts.
  - Discard 'Tool-Use Hallucinations' where the agent provides a detailed answer that logically requires external knowledge, but its trajectory shows zero tool calls were made. This indicates the model is relying on its internal pre-trained memory (which may be stale) rather than the 'Ground-Truth' tool provided in the environment. This represents a catastrophic failure of the RAG capability.
  - Eliminate 'Greeting/Politeness Bloat' where the agent's behavior gap manifests as excessive filler text. In high-complexity tasks like PCS, human experts are concise. If the agent spends 30 words on 'I'm happy to help you with that problem, let me see what I can find' before getting to the data, it fails the 'Expert Alignment' behavior check and is discarded.
  - Refuse 'Synthesis Failure' where the agent creates a summary that contradicts the raw tool observation. For instance, if the KnowledgeLookup says 'Price: $50-60' and the agent synthesizes this as 'It's very affordable at $20', the reconciliation logic has collapsed. The selection process must verify every 'Synthesized' fact against the 'Raw' source.
  - Reject 'Instruction-Following Dissonance' where the agent is instructed to be concise but still generates a 200-word essay derived from a 300-word tool result. This represents a failure of the agent's 'Behavioral Calibration'. The selection phase must prioritize the 'Compression Ratio' metric as a hard constraint for RAG-based responses.
