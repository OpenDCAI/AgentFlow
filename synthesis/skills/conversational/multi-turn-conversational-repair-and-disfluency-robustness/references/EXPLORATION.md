# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement 'Intent-Mismatch Seeding' by intentionally generating agent responses that slightly misinterpret a user's core constraint or prioritize a low-value detail over a high-value one. The agent must monitor the simulated user's reaction for 'disruptive floor-taking' markers like 'Actually...', 'Wait...', or 'You're not listening.' To execute this effectively, the agent must log the transition from an 'Aligned State' to a 'Mismatch State' to document which error triggered the user's aggressive correction.
  - Develop 'Disfluency-to-Intent Reconstruction' scenarios by saturating user prompts with multiple overlapping repairs, stuttering pauses, and sudden code-switching (e.g., 'I want... uh... I need the... wait, el rojo, no, the blue one'). The agent should extract the single 'Final-Intent' slot while logging the discarded 'False Starts' as noise. A concrete example includes successfully parsing a 50-word user turn containing 4 self-corrections and 2 language switches into a clean 5-word API execution.
  - Execute 'Premature Turn-Cutting' probes where the agent's response is injected before the simulated user has provided a complete predicate. The agent must simulate a 'Barging-in' failure to see if it can gracefully recover when the user pushes back with an interruption marker. An important check is whether the agent can correctly identify that a user finishing their own interrupted thought requires appending to the previous context rather than starting a completely new task.
  - Implement 'Syntactic Switch-Point Mapping' for cultural code-switching exploration. Mix dialects and languages (like Hinglish or Spanglish) ensuring that the transitions do not break the underlying Matrix Language rules (Equivalence Constraint). A concrete edge case involves correctly interpreting an emotional tag or noun from Language B inserted seamlessly into a complex verb phrase in Language A, ensuring the semantic backbone is preserved.
* **Target Trajectory Profile**:
  - The trajectory MUST exhibit 'Decisive Failure Recovery' where the final answer is only correct because the agent successfully integrated the data from a user-initiated corrective interruption. The log must show the agent's explicit turn-2 error being completely nullified and replaced by the user's turn-3 correction. If the agent could have been right without the user's interruption (e.g., getting lucky), the trajectory is rejected for low 'Repair-Dependency'.
  - Demonstrate 'Zero-Bleed Intent Overwrite' where the finalized response is 100% free of the attributes contained in the previously 'revoked' or 'mismatched' instruction. The trace must document the agent cleaning its context buffer of the 'Erroneous Intent' immediately after the user's disruptive correction. A failed profile is one where the agent tries to 'compromise' by offering both the wrong and right option, proving it failed to treat the interruption as a hard rewrite.
  - Require evidence of 'Instruction Precedence' specifically for disfluent, multilingual, or messy input strings. The trajectory must record the agent identifying the linguistic noise tokens (uh, um, er) and cross-lingual repetitions, bypassing them to reach the 'Grounded Intent'. This prevents 'Numerical Splitting' errors where a model mistakenly tries to satisfy both the wrong initial stuttered guess and the final spoken correction simultaneously.
  - Exhibit 'Turn-Taking Awareness' by explicitly acknowledging when the agent's own behavior caused the communicative breakdown. The trajectory log must show the assistant using a 'Repair Header' (e.g., 'Sorry for interrupting,' or 'I missed that part of your concern') before addressing the corrected intent. This proves the agent's 'Social-Calibrated Reliability' by demonstrating it possesses the meta-awareness to yield the conversational floor.
