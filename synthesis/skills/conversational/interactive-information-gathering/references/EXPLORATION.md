# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement 'Hidden-Context Seed Generation' by constructing initial user messages that are intentionally plausible for at least two disparate personas (e.g., 'How do I manage this balance' shared by a gymnast and a budget analyst). The agent must simulate a 'User Setting' for each seed, containing a specific goal, a non-trivial obstacle, and five 'Hidden Constraints' that are not visible in the first message. For example, if the goal is 'Expanding a mental health community,' the hidden constraints might include 'Limited research time' or 'Brand integrity concerns' which must be extracted through dialogue.
  - Execute 'Naive-vs-Seeking' Divergence Mapping to identify the 'Generic Response' trap. The agent should generate two potential paths: a 'Naive' path where it outputs a 7-point bulleted list of generic advice, and an 'Information-Seeking' path where it asks a single targeted question. To execute this, verify that the 'Seeking' path results in a more efficient cumulative reward by uncovering a specific 'Hidden Constraint' (like an exact campus location or a specific budget limit) that the 'Naive' path would have missed or merely guessed at.
  - Utilize 'Checklist-Driven Requirement Elicitation' by generating a hidden 5-item verify-list for every scenario (e.g., 1. Identify platform, 2. Identify audience, 3. Check budget). During exploration, the agent must log its progress against this checklist turn-by-turn. A successful exploration trajectory is one where each agent turn results in a 'Yes' on a new checklist item because the agent asked a question directly targeting that 'missing' information node rather than drifting into meta-discussion.
  - Perform 'Drip-Feed Information Reveal' simulations where the user agent is instructed to reveal at most ONE piece of hidden context per turn. This forces the agent to practice 'Turn Efficiency' by selecting the most critical information node to uncover first. For instance, if the agent asks about 'budget' and 'time' in the same turn, the simulator only reveals 'budget,' teaching the agent to prioritize and structure its inquiry funnel into discrete, high-impact conversational units.
  - Execute 'Personality-Augmented Scoping' by assigning user simulators specific traits like 'casual spelling' or 'vague phrasing'. The explorer must log how these traits impede the information-gathering process. An edge case involves a 'Vague Seeker' who provides high-entropy responses (e.g., 'I just want to help more people'), requiring the agent to use more 'Directed Choice' questions (e.g., 'Are you looking for local or online reach?') rather than open-ended follow-ups.
* **Target Trajectory Profile**:
  - The trajectory MUST exhibit 'Information-Seeking Dominance,' characterized by at least 2-3 turns of targeted questioning before any substantial advice is given. To satisfy this, the log must show a 'Zero-Advice' early phase focused exclusively on uncovering the 5 hidden constraints defined in the scenario. A successful profile proves that the agent successfully avoided the 'Naive' impulse to provide a lengthy, generic summary in Turn 1, which the paper identifies as the primary failure mode of current LLMs.
  - Demonstrate 'Turn-Level Checklist Precision' where the agent's internal reasoning explicitly identifies which hidden constraint it is targeting in each turn. For example: 'Constraint 3 (Budget) is unknown; Action: Ask about financial limits.' The trace must show a 1-to-1 correlation between the agent's question and a 'Yes' result on the verification checklist. If an agent asks a broad question like 'Tell me more about your situation,' and it doesn't resolve a specific checklist item, the turn is logged as 'Low Efficiency'.
  - Exhibit 'Constraint-to-Solution Grounding' where the final response explicitly incorporates all 5 discovered hidden constraints into the recommended action plan. The log should document how the agent resolved the 'Budget Constraint,' the 'Time Obstacle,' and the 'Persona Goal' in a single coherent final turn. An edge case is an agent that discovers a constraint (e.g., 'I hate using Reddit') but then suggests using Reddit in the final answer; this must be flagged as a 'Reconciliation Failure' and rejected.
  - Maintain 'Contextual Stability' across 10 turns without suffering from 'Question Fatigue'. The log must show the user simulator remaining engaged because the agent's questions felt 'relevant' rather than 'excessive'. To achieve this, verify that after 2 turns of questioning, the agent gives a 'Subtle Reward' (a minor helpful insight) to maintain the conversational flow before asking the next question. This reflects the paper's finding that 'excessive questioning can frustrate users' and must be balanced with progress.
  - Feature 'Proactive Obstacle Identification' where the agent doesn't just ask about the goal, but specifically hunts for the 'realistic obstacle' mentioned in the user's hidden setting. A quality profile shows the agent asking: 'What has been the biggest challenge for you so far in trying to find these connections?' rather than just 'What kind of connections do you want?' This demonstrates the agent's ability to uncover the 'why' behind the user's need for assistance.
