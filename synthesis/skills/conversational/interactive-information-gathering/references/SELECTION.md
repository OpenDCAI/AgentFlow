# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Verify a 'Information Gain Monotonicity' where each agent turn leads to a measurable decrease in the remaining 'Hidden Context' (Checklist). Accept a trajectory only if the agent resolves at least 3 out of 5 hidden constraints within the first 6 turns. This ensures higher 'Turn Efficiency', as the paper notes current models often require too many turns to infer intent. A rejection occurs if the agent reaches Turn 10 with 3 or more unresolved checklist items despite user cooperation.
  - Demand 'Anti-Verbosity Calibration' by penalizing responses that exceed 150 words in the early 'Information-Seeking' phase. Accept only trajectories where the agent uses concise, targeted one-line or two-line inquiries (Right Block style in Fig 1). If the agent provides more than 3 bullet points of advice before resolving at least 3 constraints, the sample is rejected for 'Naive/Generic Drift', even if the eventual advice is half-correct.
  - Confirm 'Checkpoint Alignment Precision' where the agent's final answer is mathematically grounded in the discovered setting variables. The selection phase must verify that if the user revealed a '$500 budget,' the agent's final solution costs less than $500. This is the ultimate test of the 'Retrieval-to-Reconciliation' pipeline, ensuring the information gathered wasn't just 'chatter' but served as a functional constraint for the task.
  - Assess 'Inquiry Depth' by confirming the agent identifies 'Multi-Hop Ambiguities' (e.g., mapping a vague 'style evolution' to a specific 'year' and then to a 'chef persona'). Accept trajectories where the agent's questions follow a logical funnel: Intent -> Obstacle -> Constraint. A failure case is 'Horizontal Questioning,' where the agent asks for the same type of information repeatedly without progressing to deeper constraints.
  - Check for 'Persona Sensitivity' ensuring the agent's questions are adapted to the user's discovered traits. If the user uses 'casual spelling' and 'emojis,' the agent must acknowledge this by slightly relaxing its own formality or using warmer framing, without breaking its helpful assistant role. This validates 'Socially-Aware Information Seeking' as described in the InfoQuest simulation methodology.
* **Rejection Criteria**:
  - Reject 'Naive Verbosity' where the agent outputs a 'Center Block' (Fig 1) style response—a long, generic essay of advice in the first turn. This is the primary negative pattern the paper seeks to evaluate. Even if the advice is 'good,' the sample is rejected because it didn't *know* if it was good for the user's specific hidden context. We prioritize the *process* of seeking over the *result* of guessing correctly.
  - Discard 'Goal-Blind Questioning' where the agent asks questions that the user already answered in a previous turn (Chronological Hallucination). The selection process must ensure the agent 'remembers' every revealed constraint. If the user said 'I'm a student' in Turn 2 and the agent asks 'What do you do for a living?' in Turn 4, it is a hard rejection for failing the multi-turn memory requirement of the InfoQuest benchmark.
  - Eliminate 'Meta-Inquiry Loops' where the agent asks the user 'Is there anything else I should know?' or 'Tell me more about your situation.' These are 'Generic Placeholders' that do not contribute to resolving the specific 5-item checklist. High-performance information gathering requires 'Directed Questions' (e.g., 'Are you looking for a free or paid group?') rather than passive 'Helpfulness Hooks'.
  - Refuse 'Constraint-Contradicting Solutions' where the final answer violates a hidden constraint that was revealed earlier. If the user reveals they have a 'busy academic schedule,' and the agent suggests a '10-hour daily workshop,' the synthesis has failed. This ensures 'Context-Awareness' is not just a stage of talk, but a binding rule for the final result.
  - Reject 'Hallucinated Setting Completion' where the agent assumes a user constraint that was never revealed. For example, if the agent says, 'Since you probably don't have much money as a student,' before the user actually mentioned their budget, it is a 'Person-Based Stereotyping' failure. All information must be 'Interactive-Source Grounded' from the actual dialogue history.
