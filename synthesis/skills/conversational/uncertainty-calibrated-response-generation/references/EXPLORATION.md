# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement 'Hinter-Guesser' Sequence Seeding by designing interactions where an answerer (User) provides progressively specific clues while the questoner (Agent) attempts a best-guess at every turn. To execute this, start with a broad category and provide 5-10 hints that narrow the hypothesis space, logging the model's confidence scores at each interval. A concrete edge case involves a model correctly guessing the answer on Turn 2 by chance; the exploration must verify that a calibrated model maintains low confidence until the clues actually rule out other candidates.
  - Execute 'Placebo-Turn Insertion' experiments to disentangle information gain from conversational length artifacts. For a successful guess trajectory, insert 2-3 placebo turns (e.g., 'Is the system ready? Yes.') between informative hints and monitor for spurious confidence spikes. To achieve this, verify that the 'Placebo Delta' (ΔConf) remains statistically insignificant (p > 0.05) compared to the 'Informative Delta'. A critical edge case is a model that increases its confidence solely because the Turn Index is higher, which identifies a major hallucination vulnerability.
  - Utilize 'Cross-Format Semantic Contextualization' to compare confidence behavior between multi-turn dialogues and single-turn summaries. For every 10-turn dialogue, generate a single-turn prompt containing a concise summary of all accumulated clues and record the confidence divergence. In practice, calculate the InfoECE for both formats to see if the model 'gets lost' or becomes over-confident in the structured dialogue. An important check is whether larger models integrate compressed evidence more effectively than smaller ones, which often rely on turn-structure for calibration.
  - Apply 'P(SUFFICIENT) Multi-Path Sampling' to find the information threshold where an answer becomes uniquely identifiable. For a given secret entity, generate dozens of hint permutations and log the turn where the model's 'Sufficiency Probe' (logit-based) crosses the 80% threshold. To execute this, use a separate LLM-as-a-Judge to verify if the clues provided up to that turn objectively constrain the answer space to a single entity. An edge case involves the agent identifying it is 'uncertain' even when accurate, correctly signaling that more data is required for a conclusive decision.
* **Target Trajectory Profile**:
  - The trajectory must exhibit 'Monotonic Confidence Progression' as measured by Kendall’s τ, ensuring that confidence cd,i+1 >= cd,i as clues become increasingly specific. To satisfy this, the log must show the agent's internal probability (P(SUFFICIENT)) rising in direct correlation with the narrowing of the hypothesis space. If the trajectory shows confidence dropping or fluctuating randomly despite helpful info, it is rejected as a calibration failure. High-quality profiles show the agent tracking evidence accumulation rather than just text repetition.
  - Require 'Sufficiency-over-Correctness Calibration' where the agent maintains low confidence for 'Correct-but-Underspecified' answers. The trace must document instances where the agent guessed the right city at Turn 3 but assigned a low confidence score (e.g., < 0.3) because other cities still fit the clues. This demonstrates the model's ability to avoid 'Lucky Guesses' and ensures the safety of subsequent actions in agentic workflows. A failed profile is one where the agent is 100% sure after only one or two vague hints.
  - Features 'Placebo-Resistant Stance' where the confidence signal remains flat or decreases when uninformative filler is added to the history. The trajectory should include a comparison between an 'Informative turn' (Conf jump > 0.1) and a 'Placebo turn' (Conf jump < 0.02). This proof-of-work confirms the agent is performing 'Semantic Density Analysis' rather than relying on turn count. An edge case to accept is an agent that lowers its sufficiency score if a placebo turn introduces conversational noise that complicates the context.
  - Demonstrate 'Structure-Aware Calibration' where the InfoECE (Information-level ECE) is consistent across different dialogue lengths. The log must group turns into normalized information bins (e.g., 20%, 40%, 60%) and show the average gap between confidence and correctness is under 0.1 across all bins. This ensures the synthetic data supports a trustworthy agent that identifies its own knowledge gaps at any stage of the conversation. A successful profile proves that calibration doesn't decay as the 'token-window' of the multi-turn chat grows.
