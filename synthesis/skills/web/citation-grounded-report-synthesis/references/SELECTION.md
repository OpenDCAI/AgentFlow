# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept the trajectory only if the final answer satisfies a 'Strict Two-Stage Adjudication' protocol: Stage 1 verifies 'Checklist-Depth' (did the agent identify the correct logical entity using the reasoning chain?) and Stage 2 verifies 'Checklist-Width' (did the agent harvest all requested detailed attributes?). If the agent identifies the right company but misses the 'unavailability' list, it fails the width metric. A successful trace demonstrates an agent passing both 100% on logical identity and 95%+ on attribute recall.
  - Accept only when the agent's reasoning log provides an 'Explicit Logic Proof' connecting the oblique prompt clues to the final entity. The agent must state: 'Identified [X] because it is the only 1989 console designed by the creator of [Y], matching the relationship chain.' This ensures the task was solved through deduction rather than a lucky keyword match or parametric hallucination. An edge case is an agent correctly identifying a 'hidden' entity that has recently rebranded, proving it used fresh web evidence over stale training data.
  - Accept exclusively if 'Attribute Distribution' is verified, meaning the answer correctly captures data points that were spread across at least two distinct URLs or site sections. The selection process must verify that the agent did not just copy-paste a pre-existing table but actually 'built' the table from fragmented observations. For instance, 'Verified that international pricing was found in the Global FAQ while U.S. pricing was extracted from the local checkout simulator.'
  - Accept only if the 'Soft Constraints' of expert presentation—such as Markdown mastery, information density, and citation grounding—are met. The final report must feature Bold headers, structured lists, or tables that allow a user to find specific answers in under 5 seconds. An example is an agent that provides a 'Summary of Findings' table at the top of a 2,000-word investigative report, demonstrating superior 'Presentation' and 'User Utility' metrics.
* **Rejection Criteria**:
  - Forcefully reject trajectories that exhibit 'Deep Logic Failure' (DEEP), where the agent misidentifies the core entity because its reasoning chain was broken. Even if the rest of the report is fluent and well-formatted, a mistake in the 'Subject' identity is a catastrophic failure that renders the research invalid. For example, if the prompt describes a specific 1988 music review but the agent researches the wrong album, the trace is discarded.
  - Reject operational logs characterized by 'Coverage Failure' (WIDE), where the agent omits major data points or 'hallucinates placeholders' to fill a requested table. If a user asks for 'eligible vs restricted vs unavailable' states and the agent only lists 'eligible' and 'not eligible,' it has failed the granular aggregation requirement. A success state requires that no requested data 'Grain' is ignored or simplified beyond the user's specific intent.
  - Dismiss assignments where 'Systemic Failure' (BOTH) occurs, representing a lack of both investigative depth and surface coverage. This occurs when the agent both misses the entity and provides incomplete or hallucinated details about the wrong entity. Any trajectory that settles for a 'Low Quality Tie' in its internal evaluation—signaling mutual hallucination between two paths—is an automatic ground for rejection.
  - Reject any trajectory that fails the 'De-contextualization Lithmus Test' by using the specific filename or website titles found in the environment context within the final answer. This indicates the agent is merely summarizing the 'Current Document' rather than performing 'Live Open-Web Research.' A valid result must solve the problem using general web-wide facts as seen from the user's perspective, not by referencing internal system identifiers.
