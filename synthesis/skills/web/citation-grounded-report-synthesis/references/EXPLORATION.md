# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement 'Recursive Depth Expansion' to trace the ancestry and logical lineage of a target entity when its name is not explicitly mentioned in the user prompt. The agent should navigate to 'Root Hubs'—such as comprehensive industry guides or historical directories—and crawl 'Depth 1' and 'Depth 2' child nodes to identify the specific logic chain (e.g., Designer -> Influence -> Year -> Specific Product). For example, to find a specific console, the agent should first find the designer's Wikipedia page and then trace their 1989 releases to identify the 'Game Boy' through its creator lineage. In edge cases, if the logical chain appears broken, the agent must search for the specific 'Relationship Motif' (e.g., 'who designed the Game & Watch?') to re-establish the path.
  - Deploy 'Horizontal Sibling Harvesting' to capture a broad set of parallel entities that share a common category or parent node to satisfy 'Wide' aggregation requirements. Once a 'Target Node' is identified, the agent must immediately inspect adjacent links or sibling list items on the same page (e.g., competing models, regional branches, or related incidents) to map the 'Horizontal Width' of the knowledge tree. A concrete step involves the agent logging all sibling URLs to a 'Width Queue' before drilling down into each one. An edge case occurs when sibling data is fragmented across different sites; the agent should then issue queries like 'competitors of [X] released in [Year]' to manually reconstruct the width of the set.
  - Execute 'Topological Navigation by Attribute' to discover hidden data-silos that are not indexed on standard summary pages. The agent should identify specific technical keywords found in preliminary search snippets and use them as 'Bridge Queries' to reach deeper levels of the information tree, such as specific 'Terms of Service' documents or 'Technical Appendices'. If the user asks for 'prohibited countries,' the agent should not just look at a homepage but specifically search for the 'Eligibility and Availability' sub-pages within the site structure. An example edge case is finding that a company's pricing is 'hidden' behind a customer-success portal, requiring the agent to search for secondary 'pricing leaked' or 'archived pricing' repositories.
  - Systematically apply 'De-contextualized Verification' by treating every discovery as a hypothesis that must be confirmed using a totally different search ecosystem. The agent must verify that a specific fact found on a wiki-hub matches the data on the original manufacturer's primary domain to ensure high factual alignment. This step requires the agent to close the current tab and issue a new, direct query for the identified entity to prevent 'Parametric Memorization' and 'Echo-chamber' errors. An edge case involves identifying a conflict between two authoritative sources; the agent must then document the discrepancy in its research log and search for a 'Tie-breaker' registry or official government filing.
* **Target Trajectory Profile**:
  - The trajectory MUST demonstrate a clear 'Search Tree Transition' from identifying the logical container (The Root) to extracting the specific leaf data (The Facts). This proves the agent is not just 'stumbling' onto the answer but is following a structured research architecture that moves from general context to specific multi-hop deduction. For example, the trajectory should show an agent finding a company first, then its specific joint-venture portal, and finally the specific state-level pricing table.
  - The pathway MUST record the discovery of 'Sibling Heterogeneity' where the agent explicitly lists and differentiates between multiple related entities (e.g., listing all three tiers of a gymnastics program separately). This ensures the trajectory captures the 'Width' of the task rather than settling for the first result found. A concrete edge case involves the agent identifying that 'Tier 1' and 'Tier 2' are handled on one page while 'Tier 3' requires a secondary navigation to a 'Rules and Policies' PDF.
  - The trajectory MUST showcase 'Recursive Error Recovery' where the agent detects a 'Retrieval Gap' and reformulates its search plan to fill it. If a specific column in a requested table (e.g., 'Restocking Fee') is missing after the first wide-pass, the agent's log must show a deliberate 'Deep Dive' query for that specific missing attribute. An example success state is an agent searching for 'Apple Store Singapore volume return restocking fee' after the general return policy page failed to specify the percentage for large orders.
  - The trajectory MUST culminate in a 'Provenance-Verified Data Set' where every atomic fact (dates, percentages, names) is linked to a specific, unique observation turn in the log. The agent must prove it visited at least one primary source (e.g., .gov, .edu, or an official product page) for every critical research pillar. Any trajectory relying solely on a single third-party 'Summary Snippet' for a multi-faceted report should be discarded as insufficient for this expert capability.
