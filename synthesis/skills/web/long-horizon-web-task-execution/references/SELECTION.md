# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the execution fundamentally spans at least five highly interdependent actions transitioning across discrete modal states or diverse URL boundaries. This explicit measurement completely filters out superficial single-page comprehension benchmarks. Shorter workflows simply cannot invoke the requisite multi-step burden mapping.
  - Accept the trajectory exclusively if procedural widget interaction and complex topographical navigation succeed autonomously. The agent demonstrably manipulates convoluted non-text boundaries such as cascading dropdowns, nested dynamic sub-trees, or physical check-boxes. Repeatedly slamming primitive text queries against deeply gated interfaces renders the solution inherently unacceptable.
  - Approve tracking logs explicitly charting perfect retention of multifaceted rulesets throughout massive state diversions. Absolute adherence spanning sequential loops guarantees comprehensive memory capacity over intense execution stretches. Drifting toward simplified assumptions halfway through a 15-item aggregation pass automatically triggers total rejection.
  - Validate outputs strictly displaying final systemic task execution validated natively within the browser rendering. Partial accomplishments ending at a promising product preview without completing checkout verifications drastically shortchange the requested horizon. Full loop closure producing precise structured aggregations, or documented terminal interface changes, is absolutely mandatory.
* **Rejection Criteria**:
  - Vigorously reject sequences padded repetitively with undirected, meandering clicks utilized solely to falsely inflate action counts. The volume of interactive jumps must organically dictate the foundational task architecture. Aimless repetitive navigation completely invalidates accurate endurance assessment.
  - Discard assignments allowing agents to sidestep operational limits based upon severely degraded functional requirements or cosmetic constraints. If critical stipulations regarding quantity blocks or exclusive geographic filters are inherently skippable without consequence, long-term boundary retention remains untested. The test structure demands consequences for skipped parameters.
  - Refuse traces collapsing into elementary search extractions utterly devoid of multi-tier navigation logic. Scenarios effectively resolved via an initial broad URL pull inherently fail to enforce mandatory deep tree-walking attributes. Extensive interface manipulation loops must define the ultimate success parameter.
  - Reject evaluations missing definitive confirmation vectors tied to successful action sequencing or completed data grids. Assuming a task is complete based exclusively on latent semantic assumptions rather than observed application tracking numbers or mathematically sound final arrays renders the data entirely unusable. Strict completion audibility provides the dataset its core strength.
