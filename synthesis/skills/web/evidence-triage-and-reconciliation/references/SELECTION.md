# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept the trajectory exclusively if the final answer choice is supported by a 'Synopsis Audit' showing no unresolved 'Failure Taxonomy' labels. Every suspicious behavior identified during the deconstruction phase must be addressed and neutralized by new, primary-source evidence. For example, an 'Overconfident Claim' label must be replaced by a 'Verified via Primary Document' label in the final reasoning log.
  - Accept only when 'Sub-Question Atomicity' is achieved, meaning the verification questions were strictly structured as simpler, verifiable units rather than complex, multi-hop tasks. A success state demonstrates the agent used a series of 1-4 simple checks (e.g., 'Is the date 2024?') to confirm a difficult answer. If the verifier tried to solve the whole task in one go, the selection logic must reject the sample for failing the asymmetry requirement.
  - Accept only if the 'Instruction-Alignment Rubric' maps 100% of the user's constraints to the final output state. The agent must break the original prompt into atomic requirements and prove that the synthesized answer satisfies every single one (e.g., correct entity, correct date range, correct unit scaling). A failure occurs if the agent covers the correct person but misses the specific 'earliest' constraint mentioned in the prompt.
  - Accept exclusively if 'Provenance Verification' is documented, showing that the most critical metrics were confirmed via primary registries. The log must state: 'Verified the 3:1 ratio directly in the CAS research table results, overriding the generic mention found in the previous search snippet.' This ensures the agent is prioritizing the highest-tier evidence available in the web environment.
* **Rejection Criteria**:
  - Reject any trajectory that exhibits 'Verification Circularity', where the verifier uses the same sources or search snippets that the original agent used to justify the original mistake. If the verifier says 'Source X (used in Step 1) says the answer is Y, therefore Y is correct,' it has failed to leverage verification asymmetry. The verifier MUST seek independent or higher-tier evidence to be valid.
  - Reject samples where 'Generic Search Logic' persists in the verification phase. Any trajectory that uses broad queries like 'Is the answer for task Z correct?' instead of specific sub-questions like 'What is the publication date on the researcher's official CV?' is a failure. This reflects the 'Generic Search' failure mode identified in the baseline research.
  - Reject trajectories characterized by 'Premature Consensus', where the verifier confirms an answer solely because multiple search snippets say the same thing without opening a primary page. This is the 'Consulting Wrong Evidence' trap; the verifier must verify that the consensus isn't just an unverified echo-chamber of a single original error. If no primary PDF or registry is visited during verification of a high-stakes claim, discard the sample.
  - Reject trajectories that display 'Instruction Blindness' by accepting an answer that misses a negative constraint (e.g., 'Before 2023') simply because the retrieved info was otherwise accurate. If the agent ignores the temporal or geographic boundaries set by the user, the 'Problem Understanding' failure mode is triggered. The verifier must explicitly check the terminal answer against the original prompt's rubrics.
