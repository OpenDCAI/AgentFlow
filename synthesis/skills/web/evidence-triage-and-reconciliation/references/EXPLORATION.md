# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement 'Step-Indexed Synopsis Generation' to manage long-horizon trajectories that exceed standard context limits. The agent must summarize every prior action into a compact description of the source visited and the concrete info obtained (e.g., 'Step 5: Visited SEC 10-K; Extracted R&D as 5M'). This prevents 'Goal Drift' by ensuring the evidence history remains visible and structured for the verifier to scan for inconsistencies or missing logical links.
  - Deploy 'Failure Taxonomy Heuristic Scanning' to identify behaviors that align with known failure modes like 'Generic Search Reliance' or 'Consulting Wrong Evidence'. The agent should evaluate each search step to see if it used a low-authority secondary domain (like a forum) for a high-stakes factual claim. An edge case involves identifying when an agent 'settles' for a search snippet rather than clicking into the underlying source, representing a 'Finding Sources' error.
  - Execute 'Asymmetric Sub-Question Formulation' by transforming the current answer into a set of 'Yes/No' or 'Quantitative' sub-tasks that are strictly easier to solve than the original task. The agent must identify the 'riskiest' facts in the answer (e.g., specific dates or unique identifiers) and draft queries that target those specific nodes. For example, rather than re-researching a person's life, ask: 'Is it true that this person graduated from university Y in year Z?'
  - Perform 'Negative Premise Querying' to actively seek evidence that refutes the agent's current conclusion. The search agent must generate queries designed to find contradictory data (e.g., searching for 'Researcher X did NOT attend Y') to test for 'Premature Conclusion' or 'Inference Leap' failures. A concrete example is searching for a company's bankruptcy rumors when the agent's primary search only showed positive financial growth reports.
  - Utilize 'Provenance Tiering' to categorize every retrieved page into Primary, Secondary, or Junk evidence channels. The agent should prioritize primary sites (e.g., .gov, .edu, IEEE) and flag any claim that relies exclusively on mid-tier sources for verification. This prevents 'Consulting Wrong Evidence' by forcing a search pivot to a higher-authority registry if the initial verification info came from an unverified blog.
* **Target Trajectory Profile**:
  - The trajectory MUST show a 'Summarize-Identify-Verify' loop where the agent first audits its previous work before issuing new searches. This ensures the agent is not simply re-running the same failed query but is instead targeting identified vulnerabilities in its earlier logic. An edge case is an agent detecting that it previously misunderstood an instruction and explicitly reformulating the goal state.
  - The path MUST record the discovery and documentation of at least one 'Logical Gap' or 'Ambiguous Source' that was ignored in the first attempt. The verifier should log 'Suspicious behavior detected: Used a generic summary for a specific figure' to justify its subsequent verification sub-queries. This proves the agent is performing active reflection rather than a linear repeat of actions.
  - The trajectory MUST culminate in a set of verified 'Atomic Rubric Seeds' where every component of the final answer has been cross-checked against independent source citations. Each sub-question must result in a definitive 'Confirmed' or 'Refuted' state supported by a direct quote from the HTML viewport. If the verifier finds a contradiction, the trajectory must show a branch into 'Corrective Refinement' to update the answer.
  - A strong trajectory MUST exhibit 'Asymmetry Efficiency', where the verification steps are significantly fewer and more direct than the original exploration steps. The agent should prove it can reach a veracity verdict using 2-3 high-leverage queries rather than repeating the dozens of steps taken during the initial retrieval. This demonstrates the agent is correctly identifying the 'pivot points' of the fact-check.
