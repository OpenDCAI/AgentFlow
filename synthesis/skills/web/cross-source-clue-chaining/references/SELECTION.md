# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept the trajectory exclusively if the final answer relies critically on piecing together facts, bridge entities, or citations from at least two structurally distinct web sources. Single-page zero-shot lookups or searches that return the full answer in the first snippet instantly fail this requirement. A success state demonstrates the agent used Source A for a name and Source B for a date.
  - Accept only when 'Temporal Metric Accuracy' is verified, meaning the specific attributes selected perfectly match the user's specific time-frame constraints (e.g., December 2025). There must be no residual error where the agent provides facts from a 2024 version of a similar event. For example, the agent logs: 'Verified that this specific official stood beside the president in the late December briefing, distinguishing it from the earlier October incident.'
  - Accept exclusively if the agent's reasoning log proves the task was solved 'Hint-Free', meaning the prompt lacked explicit bridging entities to guide the search path. The agent must independently discover the intermediaries (e.g., a specific paper title or a relative's name) needed to bridge the gap. If the question provided the 'how-to' path, the trajectory is rejected for failing the discovery mechanic.
  - Accept only if the agent demonstrates 'Snippet-to-Page Pivoting' by clicking through to a full article when the search snippet provides incomplete or ambiguous information. The log must show the agent deciding to 'Click' because the search result alone did not confirm a crucial attribute. An edge case is an agent correctly identifying that a snippet mentions 'ministers' but visiting the page to find the 'acting' minister's specific name.
* **Rejection Criteria**:
  - Reject trajectories that solve the task in a single 'Vanilla RAG' step or a single broad query that happens to hit a pre-consolidated aggregator page like Wikipedia. Complexity must arise from the structural separation of facts on the open web. If one lucky search provides everything, the sample is too trivial for this capability.
  - Reject trajectories where 'Parametric Hallucination' occurs, such as the agent guessing a common-sense answer (e.g., 'the CIA did it') without finding confirming evidence in the browsed pages. Success must be grounded in the text of the retrieved articles, not the agent's internal world knowledge. Any answer provided before the evidence is seen in the observation block is an automatic fail.
  - Reject any trajectory characterized by 'Shortcut Hallucination' where the agent finds the answer in a search snippet that accidentally includes two unrelated entities together, bypassing the chained design. The agent must prove a logical connection through its reasoning steps. For example, if two names appear in one snippet due to an ad, but the agent ignores the actual news text, the trace is invalid.
  - Reject trajectories built on repetitive keyword fiddling with no change in retrieval strategy or attribute targeting. Slight edits like pluralization or swapping words do not demonstrate multi-hop planning. The example should only survive if the agent identifies a missing factual segment and pivots its conceptual search angle to find it.
