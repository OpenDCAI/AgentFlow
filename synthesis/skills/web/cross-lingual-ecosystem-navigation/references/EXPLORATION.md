# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform 'Cross-Lingual UI Motif Mapping' by inspecting the structural roles of buttons and menus to identify core interactive nodes like 'Search', 'Buy', or 'Filter' regardless of the surface language. Instead of relying on text labels, the agent should examine the element's position, HTML class names (e.g., 'btn-purchase'), or accompanying icons to deduce functionality. An edge case involves right-to-left (RTL) languages like Arabic, where the placement of the 'Next' and 'Back' buttons is mirrored, requiring the agent to adjust its spatial navigation assumptions.
  - Implement 'Native-Script Query Expansion' by translating key entities and constraints into the target language script (e.g., Hanzi, Cyrillic, or Devanagari) to trigger more relevant results in local search engines. The agent should generate multiple variations including technical terms, formal names, and common aliases to bypass English-to-Local translation noise. For example, if searching for a specific coat on a Vietnamese site, the agent must search for 'áo khoác' and its specific size variants in Vietnamese rather than using English terms.
  - Execute 'Interface State-Action Probing' by performing low-stakes interactions like clicking pagination or attribute tabs to observe how the URL and page content update in the non-English environment. The agent should log the changes in the HTML DOM or screenshot to confirm if the 'Size' or 'Color' attributes have been successfully registered by the server. A concrete edge case is a Turkish site where clicking an attribute returns a 404 or a refresh to the home page, which signals that the agent must try a different attribute selection motif.
  - Monitor 'Token Cost and Action Efficiency' by tracking the number of search and click steps taken in mid-to-low resource languages to prevent loops or over-action. The agent should set an internal 'Persistence Threshold' (e.g., maximum 5 search reformulations or 10 clicks) before concluding that the current search path is a dead end. An edge case is Hindi (hi) where tokenization density might lead to context-window exhaustion, requiring the agent to summarize previous steps more aggressively to maintain the long-horizon interactive state.
* **Target Trajectory Profile**:
  - The trajectory MUST showcase 'Semantic Attribute Alignment' where the agent successfully matches an English-language instruction constraint to a specific foreign-language UI option. For example, the agent must document the step where it maps the desired 'Large' size to the German 'Groß' or Chinese '大号' checkbox. If the agent clicks a random attribute or ignores the menu entirely, the trajectory is too shallow for this capability.
  - The pathway MUST establish 'Action Step Optimality' by reaching the goal state within a reasonable footprint (e.g., 5-8 actions), avoiding the 'Over-Action' trap common in multilingual agents. The log should show the agent identifying the correct item or button directly rather than clicking through multiple irrelevant pages or repetitive search reformulations. An edge case is an agent correctly identifying that zero results match the constraints and choosing to 'backtrack' early rather than clicking 'Next' endlessly.
  - The trajectory SHOULD demonstrate 'Script-Agnostic Goal Completion' by reaching a terminal success marker (like a 'Purchase' or 'Download' receipt) in a language completely different from the initial prompt. The reasoning steps should explicitly state: 'Navigating to the Urdu confirmation page now that the item has been selected.' This proves the agent is not simply translating text but is functionally controlling the environment.
  - A strong trajectory MUST record an 'Explicit Search-to-Interaction Pivot' where the agent moves from keyword-based evidence gathering to active UI manipulation (filling forms, selecting dropdowns). The transition must be justified by the discovery of a non-English product or entry page. For instance, the agent finds a Bulgarian item page and then shifts its strategy from 'Searching' to 'Clicking attribute' to resolve the final size constraint.
