# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the task requires extracting and joining signals from at least two fundamentally different modalities (e.g., CSV + PDF, Table + Time-Series Logs, Dataframe + Narrative Text). Cases where the data is already flat and the 'extraction' is just a simple string split are too trivial for this skill. There must be a visible 'parsing' or 'statistical reduction' step for the unstructured source. For example, using `PyPDF2` to find CPT codes qualifies; using `str.split(',')` on a CSV column does not.
  - Accept only if the agent justifies the extraction method based on the data's specific density characteristics (e.g., and choosing keyword matching for short-text or statistical slope for long-telemetry). The trace must show the agent thinking: 'TF-IDF is not suitable for these 10-word daily summaries; I will use a clinical keyword dictionary for "readiness" markers.' This confirms the agent is performing task-specific reasoning. An edge case is accepting a trajectory where the agent chooses a 3-day rolling window for telemetry because the question specifies 'recent performance'.
  - Accept only if the trajectory includes an explicit join validation step where the agent checks if identifiers match across modalities. Successful selection requires seeing exactly how the agent resolved a naming or ID discrepancy between a PDF bill and a structured database. Traces that forget to check for merge-loss (e.g., 0 rows returned after a join) must be rejected because they fail the 'Signal Integration' requirement. Successful traces must show the agent confirming: 'Merge successful; 98% of structured records now have PDF features.'
  - Accept only if the final engineered feature is logically derived from at least 3-5 individual unstructured observations (e.g., a trend over 10 days, a total count from a multi-page PDF, or a keyword density across several notes). The skill is about 'engineering' a signal, not just extracting one scalar. A successful trace shows the agent calculating a derivative (like 'slope') or a composite (like 'cost/visit') using data from multiple points in the unstructured source.
  - Accept only if the agent demonstrates 'Modality Robustness' by handling missing or corrupted unstructured objects without crashing. If a specific PDF is missing or a telemetry file is empty, the trace must show the agent applying a fallback strategy (e.g., zeroing the feature or imputing the median) rather than failing the whole pipeline. This proves the agent can handle the inherent messiness of multimodal clinical or industrial data environments.
* **Rejection Criteria**:
  - Reject trajectories where the agent treats unstructured modalities as simple text strings without applying any signal-reduction logic (e.g., just passing the raw text of a 5-page PDF into a model target). This is a failure of 'Signal Engineering', which requires distilling the bulk data into a meaningful analytical variable. The agent must be seen 'summarizing' or 'extracting' numeric indicators. For instance, just reading the first page of a note and stopping is insufficient.
  - Reject cases where the agent hallucinates signal patterns like 'improving trends' without actually running a statistical verification (like a linear regression or a comparison of start/end points). Even if the trend looks visually obvious in a tiny sample, a Data Analysis Agent must provide a mathematical basis (e.g., a slope of -2.5) for the engineering claim. This prevents teaching the model to guess based on qualitative vibes rather than quantitative evidence.
  - Reject trajectories that exhibit 'Leakage Neglect' by using multimodal features that contain information from the future (e.g., billing costs extracted from a PDF that was generated *after* the prediction date). Successful selection requires the agent to audit the timestamps of the unstructured sources relative to the goal. A common failure is an agent using 'discharge summaries' (which include the answer) to 'predict' a readmission that hasn't happened yet.
  - Reject examples where the multimodal extraction is redundant with an existing structured column. If the spreadsheet already has a 'TotalCost' column and the agent spends 10 steps extracting the same 'TotalCost' from a PDF, it is failing the 'Feature Engineering' requirement for unique signal gain. This skill mandates pulling *unobserved* context from unstructured files to improve the reach of the table. An edge case is if the PDF extraction is used specifically to *verify* the table, which belongs under 'contextual knowledge grounding'.
  - Reject tasks where the main challenge is purely linguistic (e.g., 'Is this note happy or sad?') without any tabular integration. This skill is specifically for analytical workflows where the goal is a dataset or a model. If the task is just 'summarize this clinical text', it should be routed to a generic NLU or reporting skill.
