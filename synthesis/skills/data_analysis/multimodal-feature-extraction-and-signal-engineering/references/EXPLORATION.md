# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a 'Modality-to-Method' mapping to select the appropriate extraction pipeline based on the file format and data density. For scanned PDFs or invoices, the agent should prioritize regex pattern matching for structured identifiers (like billing codes or dates), whereas for high-frequency telemetry, it must plan for statistical aggregation rather than raw point inspection. For instance, if an agent sees 100 rows of sensor data per ID, it should explicitly check for library support (e.g., Scipy) to compute slopes or variances. A concrete edge case is when an agent detects that text notes are too short for statistical vectorization (e.g., <50 words) and must switch to a keyword-counting strategy to recover meaningful signals.
  - Execute 'Cross-Source Identifier Validation' to ensure that unstructured features can be successfully joined to the primary analysis table. The agent must verify that the 'Patient_ID' or 'Sensor_UUID' found inside a PDF text block or a log file header exactly matches the keys in the structured CSV file. For example, before spending time parsing 500 PDFs, the agent should sample one and confirm the regex captures a key that exists in the database. An edge case is discovering that the PDF uses a 'Last Name, First Name' format while the database uses a numeric ID, requiring a secondary mapping step during the engineering phase.
  - Implement 'Signal-Specific Scaling and Normalization' checks to handle right-skewed distributions common in multimodal signals like costs or durations. The agent should compute skewness or plot a distribution for extracted features like 'Total Billed Amount' to decide if log-transform, square-root, or Z-score normalization is needed for a valid analysis. For instance, a raw cost value from a PDF might be highly skewed, so the agent should proactively propose a 'log_cost' translation to ensure the model isn't dominated by outliers. An edge case is a vital sign like 'Temperature' where raw Z-scores are less meaningful than 'Threshold Crossings' (e.g., >37.5C), requiring the agent to pivot to binary flags.
  - Conduct a 'Domain-Informed Composite Plan' to synthesize multiple raw signals into authoritative indices. Rather than treating 'Age' and 'Heart Rate' as independent, the agent should search for formulas (e.g., Mean Arterial Pressure or Early Warning Scores) that combine extracted features into a single, highly predictive variable. For example, the agent might plan to calculate a 'Hemodynamic Stability Score' by summing the normalized standard deviations of three extracted vitals. A failure mode to avoid is extracting 20 independent raw vital signs without identifying the 'Trend' or 'Volatility' signals that are often more informative in clinical or industrial logs.
* **Target Trajectory Profile**:
  - The trajectory must record an explicit 'Signal Engineering' phase where raw data (logs, strings, series) is consumed and returned as a typed numeric feature. The trace should show the agent proposing a specific transformation, such as: 'Daily notes are sparse; extracting counts for mobility keywords like "walking" to use as a mobility_trend feature.' This transparency ensures that the resulting analytical dataset is grounded in a reproducible transformation logic. An edge case is when the agent corrects its plan after discovering that a chosen regex for a PDF total is capturing 'tax' instead of 'sub-total', logging the correction explicitly.
  - A high-quality profile demonstrates 'Multimodal Handoff'—the moment where features from one modality are joined to another to create a unified row. The trace should show the agent performing a left-join between the 'structured_metadata' and the 'extracted_signals' and then checking for null-rates to ensure the extraction worked for most entities. For example, after parsing sensor logs, the agent should log: 'Extracted trends for 950/1000 IDs; 50 missing IDs have no log files available; imputing with median.' This proves the agent is managing the data-to-feature lifecycle across sources.
  - The trajectory should preserve 'Metadata-Feature Consistency' by ensuring that the engineered signal respects the context of the underlying record. If a log timestamp occurs *after* the target event, the agent must be seen filtering it out to avoid data leakage; such temporal boundary checks must be documented in the reasoning. For instance, in a predictive task, the agent should log: 'Filtering out all clinical notes written after the prediction window to prevent look-ahead bias.' This makes the trajectory suitable for synthesizing high-stakes data science training pairs.
  - A robust profile must conclude with a 'Feature Importance or Correlation Audit' to validate the utility of the engineering effort. By the end of this phase, the agent should have checked whether the newly extracted multimodal signal (e.g., 'Slope of Pressure') actually relates to the target variable. An edge case to avoid is completing the extraction of 50 features from noisy logs without ever checking if any of them are non-zero or have any variance, which would signal a poor signal-engineering attempt.
