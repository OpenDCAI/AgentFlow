# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the trajectory includes an explicit code-based inspection of the dataset's internal layers or MultiIndex levels. The trace must document the use of discovery tools like `df.info()`, `h5py.visit()`, or `adata.obs.head()` to prove the agent is navigating the structure rather than guessing. Successful selection requires seeing exactly how the agent mapped the question's labels to the file's internal partitions.
  - Accept only if the agent justifies the path or attribute choice through semantic matching with the user's intent. Successful traces must show the agent linking prompt terms (e.g., 'Platform') to exact structural elements (e.g., `/groups/metadata/platform_info`). This confirms the agent is performing active semantic grounding as defined in the analytical framework.
  - Accept only if necessary metadata-driven operations—such as applying scale factors, masking null values, or resolving sparse formats—are performed based on hierarchical attributes. The trace must show that the agent did not just read the raw bits but correctly interpreted the 'metadata instructions' embedded in the file layers. This ensures the output is a valid scientific representation rather than an unscaled raw array.
  - Accept only if the trajectory demonstrates 'Structural Recovery' when an initial path or column hypothesis fails. If a direct access to 'population' fails with a KeyError, the trace should show the agent listing all keys to find that the data is in 'cell_type'. This proves the agent can autonomously adapt to the specific hierarchy of the provided environment.
  - Accept only if the agent correctly aligns heterogeneous components stored at different levels of the file tree. For multi-part objects like AnnData, the agent must be seen subsetting the matrix (`.X`) using indices derived from a metadata frame (`.obs`). This verifies that the agent understands the relational linkage between the various hierarchies within the single file.
* **Rejection Criteria**:
  - Reject trajectories where the agent treats a complex hierarchical or multi-component file as a flat dataframe without inspection. If the agent attempts a direct `pd.read_csv()`-style operation on an HDF5 or .h5ad file that requires specific library loaders, it represents a fundamental grounding failure. This skill mandates active navigation of the layers.
  - Reject cases where the agent ignores component-level attributes that are fatal to the final analytical result. For instance, if the file metadata indicates that values are 'log-normalized' and the agent treats them as 'raw counts', the resulting statistic is logically flawed. Successful selection requires 'reading the fine print' of the hierarchical metadata before computation.
  - Reject trajectories that exhibit 'Blind Brute-Force' iteration without a strategic hierarchy traversal plan. If the agent merely tries random strings as keys until one doesn't throw an error, it is not demonstrating structural reasoning. Orchestration requires a systematic plan based on listing keys and matching intents to the most plausible layer.
  - Reject examples where the hierarchy is so trivial (e.g., a single group with one dataset) that no navigation risk exists. The task must provide at least two plausible paths, deep nesting, or a relational split between matrix and metadata to create a real navigation challenge. Obvious lookup tasks should be routed to general dataset construction skills.
  - Reject cases where the agent fails to verify the semantic validity of the request against the structure's known domain context. If the agent is asked to find 'Brain markers' in a file whose metadata clearly specifies its source as 'Blood' and the agent proceeds without a refusal or sanity check, it indicates a failure to ground the analysis in the provided hierarchy.
