# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform 'Scientific Container Component Mapping' to identify the relationship between measurement matrices and metadata attributes. In complex formats like AnnData or MissionBio H5, measurement data is often separated from group labels, so the agent must proactively list attributes like `.obs`, `.var`, and `.uns` using specific library tools (e.g., `adata.obs.columns`). For instance, before calculating a group mean, the agent must confirm if the grouping label (e.g., 'Treatment') is stored in the row-metadata vs. the column-metadata to avoid slicing the wrong dimension.
  - Execute 'Structural Path Enumeration' to map the entire data tree before variable extraction for group-based formats. For file-based formats like HDF5 or NetCDF, the agent must recursively visit all groups and subgroups to generate a master list of absolute dataset paths. A concrete example is calling a recursive visitor function in h5py to distinguish between '/raw/data/temp' and '/processed/data/temp' to avoid accidental data corruption or incorrect versioning.
  - Apply 'Token-to-Path Disambiguation' to resolve vague user references using semantic matching against the data hierarchy. The agent should break the user prompt into key concepts and scan the enumerated path list or header levels for matching tokens. For instance, if a user requests 'genomic expression', the agent mapping this to '/layers/normalized_counts' in a scientific container demonstrates robust semantic grounding in the face of linguistic underspecification.
  - Conduct a 'Platform-Specific Structure Audit' to identify technical 'footguns' associated with specialized analytical platforms like MissionBio or ParseBio. These platforms often use non-standard naming conventions (e.g., storing Protein vs DNA data in distinct nested layers) that are invisible to generic dataframe loaders. An edge case is failing to recognize that a numeric column actually represents a categorical 'Cluster_ID' stored in a separate lookup table within the file, which would lead to incorrect mathematical operations.
  - Execute a 'Metadata and Attribute Audit' to recover hidden domain-specific parameters such as units, offsets, or scale factors from nested nodes. Scientific datasets often store critical transformation logic in attributes rather than raw columns, so the agent must specifically query 'attrs' (HDF5) or 'uns' (AnnData) dictionaries. An edge case is finding a 'mask_value' attribute that identifies which numbers should be treated as null, which is essential for accurate statistical aggregation later.
  - Deploy a 'Dimensionality and Sparsity Verification' step to determine the storage format of multi-dimensional arrays (e.g., CSR sparse matrices vs dense tensors). After locating a dataset path, the agent must call `.shape` or `.dtype` and check if the data requires decompression or conversion (e.g., `adata.X.toarray()`) before plotting or computing. A clear failure mode is attempting to perform a matrix multiplication on a high-dimensional sparse object before converting it to a dense format, resulting in kernel crashes or memory errors.
* **Target Trajectory Profile**:
  - The trajectory must record an explicit 'Hierarchy Enumeration' phase where the agent logs the structural components of the file. The trace should show the agent printing the nested keys or column levels (e.g., 'Found Group Attributes: [.obs, .var, .layers]') to prove the search was evidence-based. An edge case is when the agent corrects its initial access attempt after discovering that the requested 'counts' are in a sub-layer named 'raw' rather than the top-level matrix.
  - A high-quality profile demonstrates the transition from a 'layman goal' to a 'structural commitment' involving specific internal indices. Use internal narrative to explain why a specific path or attribute was loaded (e.g., 'User wants cell proportions; loading metadata from .obs/cell_type'). This transparency ensures the grounding is auditable and distinguishes the agent's logic from lucky guesses based on pre-trained biases.
  - The trajectory should isolate the 'Attribute Linking' step where metadata influences the data interpretation or loading process. It must show the agent retrieving an attribute like 'fill_value' or 'scale_factor' from a file header and using it to adjust a NumPy array. For example, the agent should log an observation like 'Detected scale_factor = 0.001 in metadata; multiplying matrix by this value' to demonstrate high-fidelity scientific data handling.
  - A robust profile must end in a 'validated data state' where the agent confirms the structural alignment of the retrieved pieces. By the end of this phase, the agent should have resolved all parent-child ambiguities and successfully linked the metadata labels to the numeric measurement rows. An edge case to avoid is ending exploration with a reference to a parent group while the actual question requires data from a specific child leaf within that group.
