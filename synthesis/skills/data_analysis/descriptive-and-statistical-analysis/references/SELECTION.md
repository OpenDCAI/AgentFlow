# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the chosen statistical test matches the feature types (e.g., Chi-square for categorical, t-test for continuous numeric). The agent must explicitly check data types using `df.dtypes` or equivalent before committing to a comparative inference method. A clear example of success is using a Kruskal-Wallis test when the group variances are found to be significantly unequal. An edge case is a task that asks for 'relationship' where the agent correctly selects a non-linear correlation metric like Spearman after seeing non-linear trends in a scatter plot.
  - Accept only if the final interpretation is strictly supported by the internal numerical results captured in the log. Every qualitative claim such as 'Group A is higher than Group B' must be traceable to a specific mean, median, or test statistic printed during the execution phase. This prevents the agent from making plausible guesses based on prior knowledge that the data doesn't actually confirm. An edge case to reject is a claim of 'strong correlation' when the R-squared value is actually below 0.3.
  - Accept only if the unsupervised patterns (clusters/PCA) are checked for stability or biological/logical coherence. The agent should evaluate if its identified groups align with the task's entities or provide a silhouette score/residual check to validate the partition quality. This ensures the patterns are not artifacts of a single random seed or poor hyperparameter choice. A successful trace shows the agent checking if a cluster is dominated by a single outlier row, which would make the cluster invalid for group-level inference.
  - Accept only if the analytical thresholds (e.g., p-value cutoffs or QC limits) are calibrated for the specific data modality and platform provided. Results must demonstrate that the agent understood if the environment was 'sparse', 'dense', or 'noisy' (e.g., from Xenium, Visium, or Excel logs) and adjusted its sensitivity accordingly. For example, rejecting a result where a sequencing-style 0.05 p-value was used for a massive dataset where 0.001 is more appropriate. An edge case is accepting a 'direction' as a result only if the confidence interval does not cross zero.
* **Rejection Criteria**:
  - Reject trajectories that guess a statistical conclusion (like 'A is higher than B') without running any comparative calculation or test. Even if the conclusion is eventually 'correct' by luck, the absence of a visible code-based derivation represents a fundamental failure of grounded data analysis. This prevents teaching the model to ignore evidence in favor of linguistic probability. A common example is an agent saying a cluster is 'enriched' without ever running a differential distribution test.
  - Reject cases where the dimensionality reduction or clustering algorithm is applied to inappropriate or unscaled data. PCA and many clustering methods require data to be centered or normalized to avoid being skewed by variables with high raw ranges. If the agent runs PCA on a raw, unscaled CSV with units like 'Income' and 'Age' mixed together, the result is mathematically flawed. An edge case is a trajectory that uses K-means on data with highly irregular, non-spherical sub-populations without a sanity check.
  - Reject examples where 'significance' is visually inferred from a plot without a formal numerical testing procedure. While visualization aids understanding, a Data Analysis Agent must provide a mathematical basis (e.g., p-value or confidence interval) for any claim of statistical reliability. Purely visual analysis is prone to subjective bias and cannot be deterministicly graded. A typical failure is an agent looking at a bar chart and declaring a 'strong' difference when the error bars clearly overlap.
  - Reject trajectories that exhibit 'Threshold Blindness' by applying generic scRNA-seq or business defaults to a mismatched data environment. If an agent applies a '200 genes' filter to a spatial dataset where the median is 25, it will discard the majority of valid evidence. Success in this capability requires the agent to evaluate the 'Detectability' and 'Sparsity' of the specific environment first. An edge case to avoid is using a '95% confidence' rule for a high-stake medical context where a stricter 99% rule is implied by the business logic.
