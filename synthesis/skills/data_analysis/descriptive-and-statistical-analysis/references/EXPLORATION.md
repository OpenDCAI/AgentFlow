# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Extract pre-computed analytical results from internal metadata containers before re-calculating from scratch. In complex scientific objects like AnnData or HDF5, researchers often store intermediate results like 'neighbors', 'clusters', or 'embeddings' in specific non-obvious attributes such as .uns or .obsm. For example, if a question asks about cluster separation, the agent should first check if a '.leiden' or '.cluster' column already exists in the observation metadata to avoid redundant computation. An edge case is finding a stale cluster label that does not match the current filtered subset, requiring a fresh re-calculation of the partition.
  - Construct relational and topology-aware mappings if the question implies proximity or neighborhood dynamics. Many datasets (spatial, network, or GIS) require an adjacency matrix or k-nearest-neighbor (kNN) graph to be built before a statistic like 'local enrichment' can be computed for each record. The agent must locate coordinate columns (e.g., x, y mapping) or linkage IDs and execute a neighbor-search algorithm to define the local scope for each point. A concrete edge case is a high-density dataset where a global adjacency matrix exceeds memory, necessitating a subsampled or radius-limited search approach.
  - Map the latent dimension landscape by inspecting principal component loadings and explained variance ratios. For tasks involving 'main axes' or 'dimensionality reduction', the agent should query the feature-level contributions (loadings) to see which raw variables drive the separation in the embedding. This allows the agent to relate abstract mathematical vectors back to meaningful names or categories provided in the task. An edge case is when PC1 is dominated by a technical artifact like 'total counts' or 'library size', which the agent must recognize and ignore in favor of biologically or business-relevant axes.
  - Execute platform-aware diagnostic checks to verify data scale and distribution assumptions. Before applying a specific test like a t-test or ANOVA, the agent should verify if the data is raw, normalized, or log-transformed by checking the typical value ranges or metadata flags. This ensures the correct statistical approach—for instance, choosing between a parametric t-test for normal data versus a non-parametric Mann-Whitney U test for skewed counts. A common edge case is data stored with a hard cutoff or zero-inflation that would invalidate standard correlation coefficients if not handled with a suitable rank-based metric.
* **Target Trajectory Profile**:
  - The trajectory must record a distinct 'Method Selection' phase where the agent justifies its chosen statistical tool based on the question type. The trace should show the agent mapping a prompt's intent (e.g., 'find markers') to a specific algorithm (e.g., 'rank_genes_groups' with a Wilcoxon test) and explaining why it fits the distribution. An edge case is when the agent switches from a simple correlation to a partial correlation after discovering a confounding variable in the metadata.
  - A high-quality profile demonstrates the linkage between unsupervised patterns and ground-truth metadata. It must show the agent running a clustering or PCA tool and then immediately performing a cross-tabulation or 'enrichment' check against existing user labels. For example, the agent should log an observation like 'Cluster 3 matches high-expenditure users; extracting its unique features' to prove the pattern is grounded. An edge case involves identifying that a 'statistical cluster' actually corresponds to an 'unwanted batch effect' and applying a correction before final reporting.
  - The trace should preserve the exact numerical anchors (p-values, UMI thresholds, or Z-scores) used to support analytical claims. Even if the final answer is a natural language conclusion, the underlying code should print the test statistics and their associated significance levels in the observation log. This transparency ensures that an analyst can verify if 'significant' meant a p-value of 0.049 versus 0.0001. An edge case is a result that is 'statistically significant' but 'biologically/business trivial' due to a very large sample size, which the agent should call out.
  - The trajectory should demonstrate 'Domain-Dependent Calibration' in its filtering and testing logic. The agent must be seen adjusting its threshold for significance or filtering for the specific platform context (e.g., using a lower gene-count cutoff for sparse imaging data than for dense sequencing data). This highlights the agent's ability to 'think' about the data source rather than applying a naive global default. For instance, the agent should explicitly note, 'Standard threshold is 100, but for this platform, a cutoff of 10 is used to preserve valid low-count observations.'
