# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the agent identifies an objective design violation or integrity misleader provided in the environment. The error must be verifiably present in the charting code or chart image properties (e.g., a non-zero `bottom` parameter or a `top-to-bottom` inversion JSON flag). Success requires the agent to correctly map physical values past the visual trap.
  - Accept only if the agent's proposed 'Makeover' (fix) or final numeric answer logically offsets the detected error. If the agent identifies a 'Non-Zero Baseline' but recommends changing the 'Color,' the grounding is poor. Successful selection shows the agent recalculating truth ignoring the visual distortion.
  - Accept only if the agent justifies the audit using numeric evidence from the underlying dataset. The trace must show the agent comparing the visual representation to the raw data values (e.g., calculating a proportion from a dataframe rather than estimating bar heights).
  - Accept only if the agent classifies the violation appropriately. The audit must distinguish between 'Honest but Ugly' (too many gridlines) and 'Deceptive / Misleading' (dual axes, inverted axes). This demonstrates a nuanced understanding of visualization theory.
* **Rejection Criteria**:
  - Reject trajectories where the agent is 'deceived' and provides an answer that aligns with the visual trick but contradicts the underlying truth. If the graph 'lies' (e.g., inverted axis) and the agent reports the visually tallest bar as the highest value, reject it immediately.
  - Reject cases where the agent ignores explicit 'misleaders' (like inappropriate log scales) and proceeds with a standard analytical library call that yields a skewed result. If the agent does not audit the scale type before performing a visual distribution check, it fails the integrity-aware requirement.
  - Reject trajectories that exhibit 'Visual Bias' where the agent's reasoning relies on bar height alone without verifying the Y-axis baseline. If an agent concludes there is a 'huge gap' between two values on a truncated axis without checking if the axis starts at zero, it is repeating a human perception error.
  - Reject cases where the agent offers purely aesthetic advice without a basis in data effectiveness. Recommendations like 'I think pink would look better than blue' without a functional reason (e.g., colorblind accessibility) are outside the scope of a rigorous data analysis audit.
  - Reject tasks where the chart is already technically perfect and the agent invents 'best practices' to sound helpful. This skill evaluates identifying and correcting violations; critiquing an honest chart violates truthfulness.
