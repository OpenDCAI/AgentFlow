# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Execute an 'Instruction-to-Criterion Mapping' to identify which of the 20 professional norms (e.g., Topic Consistency, Research Gap Clarity, Result Depth) is being targeted. You must normalize the user's casual request into a checkable professional standard derived from authoritative guides like the ICLR Reviewer Guide or Stanford's paper-writing tips. For example, if a user asks to 'fix the intro,' determine if the failure is in 'Problem Definition' or 'Integration of SOTA' before searching for content. An edge case is a request that is too vague, requiring you to default to checking the 'Clarity and Visibility of Contributions' as the most salient success metric.
  - Conduct a 'Global-to-Local Context Audit' (context T) to identify dependencies between the paragraph to be revised (p) and the remainder of the document. You must scan the full text for specific evidence, metrics, or terminological definitions that could fill the gaps identified in paragraph p. A concrete step involves checking if the 'Results' section contains specific percentages that the 'Abstract' currently summarizes too broadly. A failure mode is performing a revision in isolation, which leads to 'hallucinated improvements' that contradict the actual data found elsewhere in the paper.
  - Perform a 'Rational-Driven Gap Analysis' by simulating the persona of a critical professional reviewer. You must identify exactly why the current text (BEFORE IMPROVEMENT) fails the assigned criterion—is it too belabored, is it missing the 'ideal situation,' or is the problem definition underspecified? For instance, when looking at a 'Background' section, check if all critical concepts mentioned in the 'Methodology' were actually defined. An important indicator of quality is identifying a 'missing bridge' between a claim and its experimental support.
  - Build a 'Revision Constraint Ledger' that lists all terminological and logical invariants that must survive the revision. You must identify the core 'Intellectual Seed' of the paragraph that represents the author's original idea and ensure the revision does not 'smooth it away' or overwrite it with generic GPT-style filler like 'pivotal' or 'transformative.' A practical action is extracting the primary nouns and specific system names (e.g., 'CVG framework') to ensure they are handled as immutable tokens. This prevents the agent from accidentally changing the author's specific contribution while trying to improve 'clarity.'
  - Evaluate 'Audience Alignment' by checking the complexity and register of the surrounding sections against the target paragraph. You must determine if the current paragraph is 'out of sync' with the presumed technical background of the readership (e.g., being too basic in an Evaluation section). An edge case involves finding a paragraph that is too jargon-heavy compared to the Introduction, necessitating a 'lay-accessible' simplification pass that still adheres to technical accuracy.
* **Target Trajectory Profile**:
  - The trajectory MUST record an 'Intent-to-Context Bridge' where the agent notes exactly which section of the document provided the information needed to fix the target paragraph. It should show the agent stating: 'Revise Abstract per contribution criteria; found 22% metric in Section 4.1; will integrate to address user's request for significance.' This proves the revision is grounded in the environment rather than the model's weights.
  - A good trajectory demonstrates 'Criteria-Guided Scrutiny' by identifying specific professional violations in the original text. It should contain a reasoning step like: 'The current motivation is belabored; it describes history but omits the iterative feedback gap.' This provides an explicit 'Diagnostic Rationale' that justifies the subsequent modifications to the user.
  - A good trajectory explicitly avoids 'Surface-Level Polishing' by rejecting revisions that only improve fluency without adding semantic value. It must record a step where the agent checks: 'Does this revision satisfy the underlying professional criterion (e.g., Reproducibility)?' If the revision just uses 'prettier' words for the same vague content, the trajectory must be flagged as insufficient.
  - A good trajectory documents 'Stereotype/GPT-Language Suppression' to ensure the output sounds like a human researcher. It should record the replacement of generic descriptors (e.g., 'innovative strategy') with grounded descriptions (e.g., 'Constrained Variational Generation framework'). An edge case is the trajectory noting the deletion of 'unnecessary length' to satisfy the 'Conciseness' criterion found in Table 2.
