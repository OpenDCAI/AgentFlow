# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  * Start by extracting the four core informational elements from the source: entity, date, event, and result. Treat them as mandatory candidates for the summary unless the source genuinely omits one. A concrete example is separating “Mr. Baker” from “4 June,” “motorcycle collided with a car,” and “died,” rather than blending them into an unstructured gist.
  * Distinguish core facts from supporting detail before writing. Many source texts contain vivid but secondary information that can drown out the event skeleton if copied indiscriminately. An edge case is a dramatic crash article where descriptive damage details are memorable but less central than the result of survival or death.
  * Map the causal or temporal relation among the extracted elements. Compression is not only about inclusion; it is also about preserving the logic linking what happened to what followed. For example, the event should lead into the result rather than being listed as unrelated fragments.
  * Note absent or unsupported elements explicitly during exploration. If the source lacks a date or the result remains unknown, the agent should avoid inventing it to complete the template. This protects the summarization process from hallucinated completeness.
* **Target Trajectory Profile**:
  * A good trajectory contains all source-supported core elements in a structured intermediate representation before wording the summary. This intermediate step can be a four-slot table or ordered checklist. It provides a direct bridge from extraction to compression.
  * A good trajectory prioritizes fidelity over surface abstraction. The summary may paraphrase, but it should not introduce facts that are not grounded in the source. A strong edge case is preserving that the investigation is ongoing only if it is truly central to the event’s current state.
  * A good trajectory compresses non-core details rather than stacking them. Supporting facts should appear only if they sharpen the event or result and fit the length budget. This helps prevent the common failure mode where a summary sounds rich but misses the main outcome.
  * A good trajectory ends with a coherence pass that checks whether the summary reads as a single communicative unit rather than a heap of extracted facts. The entity, date, event, and result should connect smoothly and logically. An example is avoiding summaries that name the injured parties without saying what happened to them.
