# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Workspace Reachability Characterization: The agent must systematically probe the limits of the left and right arm workspaces by attempting to identify coordinates that are uniquely reachable by one arm versus those in a shared central zone. To do this, the agent logs points where the kinematic solver indicates a 'singularity' or 'out-of-reach' status for one arm but success for the other. For example, a target on the far-right boundary should be explicitly flagged as a 'Right-Arm Only' zone to guide future coordinate-to-actuator assignments.
  - Coordination Mode Identification: The agent should categorize every task into one of three modes: Independent Parallel (arms doing different things), Sequential Collaborative (handovers), or Synchronous Collaborative (holding the same object together). Identification involves checking if the task instruction mentions a shared object or interdependent chronological steps. An edge case is moving a tray with two arms, which requires the agent to lock both arms into a 'Synchronicity' logic where velocity and rotation are mirrored.
  - Occlusion-Aware Multi-View Alignment: Since bimanual manipulation often involves one arm blocking the view of the other, the agent must synchronize ego-centric (wrist-mounted) and third-person (fixed overview) camera views. It should capture 'Visual State' pairs where the third-person view resolves the spatial ambiguity of the ego-centric view during a close-up grasp. A concrete example is when the left gripper blocks the view of a small object, the agent must cross-reference the fixed external camera to verify the object's remaining 3D coordinates.
  - Inter-Arm Collision Distance Mapping: The agent must record trajectories where 'Safe Distance' thresholds are maintained between the two end-effectors throughout the action sequence. During exploration, the agent should purposefully bring arms close to each other without contact to find the minimum distance at which the simulator's collision checker triggers. This data provides the supervision for generating 'collision-avoidance offsets' in future planning steps.
  - Task-Adaptive Execution Snapshotting: The agent should implement a mechanism where successful bimanual trajectories are truncated into 'chunks' to evaluate how the state evolves after a collaborative event like a hand-off. The agent records the environment state immediately after a gripper release to ensure the next arm's starting pose is grounded in the updated physics. For instance, in a handover, the 'snap' of the block being released must be observed to verify it didn't slip or shift before the second arm attempts its grasp.
* **Target Trajectory Profile**:
  - Actuator-Consistent Goal Targeting: A high-quality trajectory must clearly show the arm selection being dictated by the object's position relative to the robot's center line. The profile should exhibit no 'cross-arm' movements where a right arm reaches behind a left arm, as this violates standard hardware kinematic constraints. For example, any attempt to reach a far-left object with the right arm should be discarded or logged as a failure case for training reachability awareness.
  - Logical Dependency Continuity: For collaborative tasks like handovers, the trajectory must contain an unbroken chain of 'Grasp(Left) -> Transfer-to-Center -> Grasp(Right) -> Release(Left)'. The data profile must verify that the item never touches the table between the exchange steps to ensure it captures genuine bimanual collaboration rather than sequential 'pick-and-place'. If the object drops or is staged on the table, it should be marked as a 'Decoupled' strategy rather than 'Bimanual Collaboration'.
  - Spatio-Temporal Synchronization Markers: The trajectory must log high-frequency coordinate updates for both arms simultaneously to provide supervision for dual-arm rhythmic tasks. The target profile ensures that both arm poses are recorded in the same temporal window (snapshot), proving the agent is thinking about both actuators as a unified 16-dimensional system. A sample where only one arm is active while the other is 'missing' from the command stream is considered a lower-quality single-arm variant.
  - Explicit Collision Deconfliction Maneuvers: A premium trajectory includes segments where one arm 'waits' or 'moves to origin' to clear a path for the other arm's primary movement. This identifies 'Wait-States' which are critical for bimanual safety. An example is a trajectory where the left arm moves to a high 'parked' position to allow the right arm to access a target that was previously occluded by the left gripper's structure.
  - Viewpoint-Inversion Resilience: The trajectory profile must include documentation that correctly identifies 'Left' and 'Right' even when the camera perspective is reversed in a third-person view. Because external cameras often face the robot, the 'Right Arm' appears on the left side of the image; the profile must explicitly reconcile this spatial inversion in its internal reasoning. A failed profile is one where the agent chooses the arm based on 'Image-Left' rather than 'Hardware-Left'.
