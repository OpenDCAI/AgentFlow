# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Kinematic Reachability Validation: Accept only if the selected arm can physically reach the target coordinate without hitting a joint limit or a singularity. The selector must cross-check the target object's 3D pose against the known arm length and 'Hardware-Left/Right' assignment. If a command requires a right arm to reach a coordinate x < -0.3, the sample must be rejected as kinematically unviable unless it is part of a deliberate failure-recovery test.
  - Coordination Mode Accuracy: The sample is accepted only if the agent correctly identifies whether the task is 'Parallel' or 'Collaborative' and structures its planning JSON accordingly. For 'Collaborative' tasks, the selector must verify that the sequence shows a logical hand-off or joint-lifting behavior. A 'Collaborative' task that is solved by one arm alone while the other sits idle is rejected for failing to test the bimanual capability.
  - Synchronized State Integrity: For synchronous lifting, accept only if the trajectory shows both grippers contacting and exerting force on the object simultaneously. The time-gap between the two 'Close-Gripper' commands must be within a minimal simulator-step threshold to ensure the data supervises 'true' synchronization. If one arm lifts the object before the other has closed its gripper, the sample is rejected for physical incoherence.
  - Inter-Arm Collision Safety Check: Every accepted trajectory must pass a 'Self-Collision' audit, ensuring the distance between any two arm joints never falls below a safety threshold (e.g., 5cm). The selector must parse the end-effector pose history to confirm that no command sequence would cause the arms to intersect or physically interfere. This ensures that the synthesized data teaches clean, deconflicted behavior rather than hazardous mutual interference.
  - Role Consistency Maintenance: Accept only if the agent maintains the same arm for a specific sub-goal throughout its completion. If the agent starts a grasp with the left arm but then 'switches' its reasoning to the right arm in the next step without a valid handover, the sample is rejected as a 'Role Hallucination'. Consistency is verified by tracking the 'ArmTag' across consecutive JSON chunks in the trajectory field.
* **Rejection Criteria**:
  - Single-Arm Bias Trivialization: Reject any sample where the entire multi-step goal can be solved using only one arm without increasing task duration or violating safety. If the environment is so small that the left arm can easily reach everything on the right and left, the bimanual requirement is decorative and provides no training signal for coordination. This skill requires large workspaces or collaborative-heavy instructions to be valid.
  - Hardware-Agnostic Arm Assignment: Reject trajectories where the arm choice is random or based purely on object color rather than spatial proximity. The selector should discard samples where the agent uses its 'Left' arm to pick up an object on the far right simply because it was the first object mentioned. Valid reachability logic must be the primary driver for actuator allocation decisions.
  - Unsynchronized Coordination Lags: Discard bimanual plans where the 'Action Lag' from sequential processing causes the second arm to act based on an outdated world state. If the first arm moves an object and the second arm tries to grasp it at its *original* position, the sample is a failed reasoning case. Rejection is forced if the second arm's plan does not incorporate the first arm's completed outcome.
  - Cross-View Spatial Hallucination: Reject samples where the agent becomes confused by third-person 'Spatial Inversion' and commands the wrong arm. If the image shows a robot's right arm on the left, and the agent identifies it as 'Left Arm' due to its position in the pixels, the sample must be purged. This prevents training models that rely on 2D pixel-alignment rather than 3D hardware-grounding.
  - Kinematically Impossible Handover: Reject handover sequences where the target 'handoff point' is outside the reachable overlap zone of both arms. If the left arm places an object at a coordinate where the right arm cannot reach, the handover is fundamentally broken. The selection process must verify that the 'Transfer Coordinate' lies within the valid intersection of both arm reach-spheres.
