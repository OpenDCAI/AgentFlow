# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  * **Overlap sufficiency.** Accept the trajectory only if the paired observations share enough structural content to support correspondence, including at least one stable anchor and the target or its support surface. Operationally, verify that the target object or target-supporting region can be localized in one view and plausibly transferred into the other through shared scene context. If the only overlap is a blank wall corner with no relation to the target, the trajectory fails even if both images come from the same room.
  * **Single grounded answer.** Accept only if a reviewer could identify one clearly correct grounded referent, point, or region after following the trajectory. During filtering, explicitly ask whether two independent solvers would converge on the same answer without extra assumptions. If two candidate points remain equally plausible after full reasoning, the sample must be rejected.
  * **Evidence chain completeness.** A valid trajectory must contain a full reasoning chain: anchor detection, referent disambiguation, view-change reasoning, and final grounding. The agent should confirm that none of these links is missing before synthesis proceeds. For example, if the correct object is known but the motion between views is unreadable, the chain is incomplete and the sample should not pass.
  * **Local-feature persistence.** Accept when the local feature or part being matched remains meaningfully recoverable across views. The agent should check whether the feature is visible directly or can be inferred from partial visibility plus anchor relations. A labeled corner that disappears entirely behind an opaque object with no inferable continuation should not pass.
  * **Distractor quality.** Accept when distractors are strong enough to prevent trivial solving but weak enough to preserve a unique solution. The agent should ensure that distractors share either category or nearby position, but not both so perfectly that the task becomes indeterminate. A good example is two similar suitcases with only one near the bed; a bad example is two identical suitcases both near the same bed with no other cue.
* **Rejection Criteria**:
  * **Category-only solvability.** Reject any trajectory that can be solved by simply naming the category without grounding the specific instance or location. If the sample remains answerable after removing all cross-view reasoning, it is too easy for this capability. A question like 'Where is the suitcase?' in a room containing only one suitcase is insufficient unless the second view matters.
  * **Noisy or inconsistent anchoring.** Reject when the anchor structure changes too much across views or when the anchors themselves are uncertain. The agent should drop examples where motion blur, cropping, or lighting destroys anchor consistency. For instance, a doorway visible in the first image but completely cropped out in the second may invalidate the correspondence chain.
  * **Irrecoverable occlusion.** Reject when the intended target is fully hidden in a way that does not allow justified inference. The agent must distinguish inferable partial occlusion from total disappearance without supporting evidence. If the marked point lies on a surface that is entirely absent in the second view, the sample should not be kept.
  * **Multiple equally valid correspondences.** Reject if more than one candidate remains valid after all available constraints are applied. During selection, explicitly test whether anchor relations, object identity, and local geometry actually collapse the candidate set to one. If two corners on a symmetric object remain indistinguishable and the question expects one label, reject the trajectory.
  * **Synthetic shortcut leakage.** Reject any sample where annotations, camera framing, or candidate layout accidentally reveals the answer without reasoning. The agent should look for suspicious cues such as the correct label always being closest to the image center or the only sharp point among blurry distractors. A sample with that kind of annotation bias trains shortcut behavior rather than grounded correspondence.
