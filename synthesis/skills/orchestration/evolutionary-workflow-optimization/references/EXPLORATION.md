# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Proactively identify 'Performance Gap' nodes where a standard single-agent workflow consistently yields low accuracy, F1 scores, or security gaps on complex tasks. You must execute trial runs using a basic configuration to record baseline failures, ensuring that the environment provides a clear 'Error Surface' for the optimizer to act upon. A concrete edge case involves triggering an intentional timeout or loop over a convoluted schema requirement to guarantee the baseline workflow generates a traceable crash artifact for optimization.
  - Implement a 'Post-Event Outcome Harvesting' strategy by querying the environment's history for instances where the agent's prediction or plan failed to match the final ground truth or real-world result. You must explicitly log the 'Outcome Delta' between the agent's recommendation and the actual state change (e.g., a triage that missed a disaster). An important example is harvesting data from a 'flash flood' event to see if the sensing agents reached their population targets, which serves as a reinforcement signal for the next policy update.
  - Evaluate 'Reinforcement-Driven Threshold Discovery' by systematically adjusting internal decision parameters (like 'Risk-Weight' or 'Cost-Limit') across a set of synthetic scenarios. You must record how incremental changes in these 'Knobs' impact global reliability and the critical success index (CSI) within the environment. For instance, in a weather-response agent, test five different rainfall intensity thresholds to find the specific point where false alarms are minimized without increasing catastrophic misses, logging this as the 'Optimal Operational Policy'.
  - Conduct 'State-Aware Red-Teaming' by generating adversarial tasks that attempt to bypass current safety filters or logical constraints to expose latent vulnerabilities in the workflow. You should observe if the agent's current instructions allow for unsafe tool combinations (like reading a secret and then making a network call) and record the successful 'Exploit Path'. A robust edge case is a simulation where a 'Search' tool returns malicious plan-injections; the explorer must record if the current supervisor identifies the hijack or if it needs a new evolved oversight rule.
  - Initialize a 'Coalitional Attribution Grid' when aiming to evaluate component bottlenecks across a multi-part workflow like Planning-Reasoning-Action. You must execute ablation or coalitional trial runs (using methods like Shapley values) to measure the marginal delta in performance whenever a specific component is modified or upgraded. An important edge case involves observing negative synergies, where upgrading the 'Reflection' agent actually degrades performance because it introduces hallucinations, logging this to prevent wasteful resource allocations.
  - Map out the 'Mutation Space' of the workflow by identifying which components are candidates for structural updates versus linguistic constraints versus model reassignment. You must determine if a failure can be solved by adding a new worker (Structural Mutation), refining existing instructions (Linguistic Mutation), or swapping a compute model (Resource Mutation). For example, explicitly evaluate whether a math error was caused by weak reasoning logic (requiring a new 'Algorithmic' prompt) or just poor tool syntax (requiring a 'Schema Instruction' fix).
* **Target Trajectory Profile**:
  - The trajectory must explicitly contain at least two generations of the workflow: a 'Parent' (initial state) and an 'Evolved' (optimized state) that shows a measurable 'Adaptation Gain' in reliability. It is high-quality only if the changes between generations are visibly linked to the feedback from the evaluation or audit layer, showing a transition from passive analysis to decision intelligence. Any trajectory that abruptly solves the task on the second try without explicitly detailing the 'Optimization Computation' or 'Policy Update' between rounds constitutes a failed profile.
  - Successful profiles include an 'Explainable Adaptation Summary' where the Meta-Agent or Auditor agent explains why a specific decision threshold or prompt constraint was modified. The trace should show the logic deciding to change a risk-weight from 0.5 to 0.8 because the baseline was 'Too Conservative' regarding safety deltas. This provides a transparent audit trail that distinguishes deliberate, learning-based calibration from random parameter shifts.
  - A high-quality profile demonstrates 'Closed-Loop Reliability Calibration' where the system re-runs the optimized workflow against the original failure scenario to verify a 10% to 15% improvement in success. The log must show a 'Validation Turn' where the previously missed event (e.g., a 40mm/h rainfall) is now correctly flagged following the policy evolution. This ensures the synthetic data captures the full cycle of 'Fail -> Audit -> Evolve -> Verify' that defines real-world adaptive resilience.
  - The trajectory should capture 'In-Context Self-Tuning' where the system adds its own best previous answers (or blocked attack/failure paths) as demonstrations for the next operational round. The trace is excellent if it shows the prompt growing dynamically to include a 'Historical Performance Summary' that the system itself generated to guide future triage. This mirrors true self-improvement loops where an agent compiles its own offline experiences into optimized instructional artifacts.
