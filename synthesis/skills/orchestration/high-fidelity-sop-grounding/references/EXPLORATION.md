# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a 'Long-Context Protocol Ingestion' by providing the orchestrator with the full-text technical manuals, formulas, and feasibility rules (e.g., view adequacy checklists) in a single integrated context. You must verify that the environment provides a way to maintain semantic coherence across dense tables and branching logic, such as using structured markdown for document headers. An important edge case involves identifying where 'Prerequisite State' (e.g., finding an ED frame) is mandatory before a 'Target Action' (e.g., measuring a ventricle) can be initiated according to the text.
  - Implement 'Baseline Feasibility Probing' by executing specialized audit tools to determine if the raw source material supports the SOP's operational standards prior to tool dispatch. You must explicitly log the 'Suitability Score' for various environment artifacts, such as checking if a video frame is clear or a log file is complete enough for analysis. A concrete example is a medical agent calling a 'view_validity' tool to ensure the anatomical structure is visible; if the tool returns a negative signal, the explorer must record the 'Grounds for Deferral' to inform the refinement plan.
  - Conduct 'SOP-to-Tool Mapping' where you manually trace every 'Shall/Must' clause in the manual to a specific tool parameter or API field (e.g., mapping 'Measure at end-diastole' to a `frame_index` argument). You should identify hidden technical requirements, such as a manual that requires a specific unit (cm vs mm) or a specific timestamp format that is not mentioned in the user prompt. An essential edge case is finding a protocol that requires an 'Expert Review' for certain values, necessitating the exploration of an internal 'Escalation Worker' agent.
  - Enforce 'State-Aware Protocol Selection' by evaluating which specific handbook or chapter applies to the current environment state (e.g., deciding which guideline to use based on the detected view or detected error type). You must execute a reconnaissance command to identify the 'Current Regime' (e.g., identifying the ultrasound view is 'Parasternal Long Axis') before querying the guideline database. This ensures the agent avoids 'Domain Drift' where it applies the wrong SOP logic to a correctly identified entity, maintaining high-fidelity clinical or technical alignment.
* **Target Trajectory Profile**:
  - The trajectory must explicitly feature a 'Quality Gate' sequence where the agent performs an environmental suitability check before committing to a technical measurement or action. High-quality profiles show the agent identifying that the 'Feasibility Tool' returned a positive status (e.g., 'rv_base is measurable') as a causal prerequisite for the subsequent 'Take Measurement' call. A trajectory that jumps straight to measurements without verifying that the environment supports the manual's visibility requirements is a negative signal for this capability.
  - Success profiles include 'Grounded Refusal/Escalation' turns where the agent rejects a user-requested action because it explicitly violates a protocol constraint or enters an unfeasible state. The trace must show the agent citing the specific manual section (e.g., 'Per ASE Guideline 3.1...') as the reason for not performing the task. An excellent edge case involves an agent detecting poor image quality and autonomously deciding to 'Escalate to a Senior Specialist' rather than providing an ungrounded, low-accuracy numerical answer.
  - The trajectory must demonstrate 'Multi-Document Logic Synthesis' where the orchestrator resolves conflicts or dependencies between two separate guidelines or visit encounters. It is considered high-quality only if the agent retrieves a 'Baseline Value' from a past turn/visit (e.g., a previous BP reading) and uses it as a mathematical comparison for a current turn/visit following the SOP. This verifies the system can maintain 'High-Fidelity State Persistence' across several rounds of interaction, aligning with longitudinal clinical reasoning.
  - Successful traces reflect 'Actionable Directive Generation,' where the terminal output replaces the user's vague goal with specific technical parameters derived directly from the SOP. The log should show the agent converting a request to 'check health' into specific orders like 'Measure LVIDd and IVS per SOP-102.' A trace is high-quality if the final answer contains direct citations (e.g., [bmj24]) for every numerical claim, proving the orchestrator didn't rely on internal pre-training and instead grounded its answer in the provided context.
