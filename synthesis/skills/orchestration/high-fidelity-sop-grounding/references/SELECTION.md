# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The final answer must exhibit 'Environmental Justification,' meaning every success or refusal to measure must be traced back to a specific feasibility/quality observation in the trajectory. You must verify that the orchestrator analyzed the results of a prior audit tool (e.g., a `feasibility_checker`) before issuing its final clinical or technical interpretation. If an agent provides a measurement from a frame that was flagged as 'Low Visibility' in the logs, the trajectory must be rejected. This ensures the data trains for 'Safe-to-Answer' decision intelligence.
  - Selected traces must demonstrate 'Direct Clause Entailment,' where the specialist reviewer can verify that the agent's multi-step plan is 100% logically consistent with the ingested handbook. There must be zero 'Logic Gaps' where the agent performs a step that is not authorized or described in the SOP for the current state. A strong case involves an agent correctly identifying that a 'Standard View A' is required for 'Calculation B' and refusing to proceed because the current view is 'View C'.
  - The interaction must maintain 'Citation Consistency,' where every ActionItem or reasoning thought is annotated with a specific document ID or reference found in the environment repository. You are mandated to check that the cited IDs physically exist in the input context providing the 'Ground Truth' for the current sub-task. Any trace where the agent 'guesses' a citation or uses an ID that was never retrieved from the guideline database should be rejected as a citation hallucination.
  - Acceptance requires 'Instructional Precision,' where the agent's output parameters (e.g., 2 PM, 10mg, 4.1cm) match the exact numerical constraints discovered in the guidelines during exploration. Reviewers must cross-check the final answer values against the 'Search Guidelines' observations to ensure zero numerical drift or normalization errors. A high-quality trace demonstrates the orchestrator bridging the gap between a 'messy' environment and a 'strict' manual through precise parameter extraction.
* **Rejection Criteria**:
  - Reject any trajectory where the agent 'hallucinates' the protocol steps or feasibility rules instead of referencing the provided context block or audit tools. If the agent claims a measurement isn't feasible but the `feasibility_tool` observation clearly says it is, it represents a terminal failure of environmental grounding. Similarly, citing a rule ('Section 5.1 says X') that does not exist in the retrieved guideline snippet constitutes a fatal grounding failure.
  - Discard traces characterized by 'Constraint Neglect,' where the agent ignores a clear hard constraint in the SOP (e.g., 'Do not measure if glare is present') to satisfy the user's query faster. This includes 'Procedure Jumping' where the agent skips mandatory verification steps just to provide an answer. Success must be physically and logically anchored in the *entire* compliance trace; a correct answer reached through an illegal shortcut provides no training signal.
  - Reject trajectories where the agent provides 'Helpful but Vague' advice instead of 'Technical Directives' derived from the manual. If a manual specifies 'Check the Aortic Root diameter' and the agent tells the user to 'have a doctor look at the heart,' it has failed the high-fidelity translation mission. Synthesis must prioritize items where the agent uses the professional structural terminology (e.g., 'EDD', 'LVPW') found in the authoritative guidelines.
  - Reject any trace where the 'Refinement' turn is missing or compressed into a few uninformative tokens despite the task involving high uncertainty or image ambiguity. Professional SOP grounding requires 'Extended Deliberation' (R1-style reasoning) about state suitability before action. Traces that jump straight from a user question to an answer without an internal 'Feasibility Thought' or 'Manual Lookup' phase lack the audit trail necessary for high-stakes coordination.
