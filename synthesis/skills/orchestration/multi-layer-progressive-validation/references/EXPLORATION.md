# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify internal 'Stability Points' across the multi-tool workflow where the environment state reaches a logical milestone suitable for batch validation. You must evaluate the reliability of each tool and group them into 'High-Confidence Segments' where step-by-step checking would be wasteful. Record this segment to be validated only once at the end.
  - Audit the environment for 'Active Assistance-Seeking' triggers where an Executor can detect a transient error that bypasses standard checkpoints to alert the Orchestrator. Locate tool return signals that indicate a partial failure (e.g., parameter error) logging these as fast inner-loop correction opportunities.
  - Map out 'Systemic Collapse Signatures' where localized tool results indicate the overarching plan is fundamentally incompatible with state invariants. Record unique error patterns (like cascading data inflation or non-convergent results) that correctly force the Outer Loop to initiate a global plan revision.
  - Perform a 'Cross-Layer Dependency Audit' by mapping the flow of critical identifiers (IDs, timestamps). Expose points where upstream contamination (like a missing filter clause) quietly passes inner-loop checks but ruins downstream global metrics, establishing necessary boundaries for outer-loop review checkpoints.
* **Target Trajectory Profile**:
  - The trajectory must explicitly demonstrate a 'Step-Skip' pattern where at least 2-3 consecutive tool actions are taken without an intermediate validation observation, followed by a scheduled checkpoint where the agent addresses accumulated errors locally (inner loop).
  - High-quality profiles feature an 'Escalation Event' where a localized fix is attempted but ultimately fails against systemic logic constraints, prompting the Orchestrator to formally challenge the Planner for a complete global revision (outer loop).
  - The trajectory must utilize 'Graph Memory' to trace the 'Taint' of a cascading error back to its root cause among non-adjacent upstream steps. The agent must locate a data flaw in Step 1 only after noticing the impact in Step 4, then surgically revise the upstream node.
  - Successful traces demonstrate sub-agents proactively requesting validation only upon internal uncertainty, dynamically adjusting the validation frequency based on contextual confidence rather than blindly following rigid schedules.
