# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Each factual claim in the synthesized final answer must be 'Evidence-Traceable' to a specific line in the preceding tool observation logs. You must be able to point to the exact observation (e.g., an Arxiv snippet, or a Wiki population table) that provided the data for the corresponding claim. If the agent claims a paper title that never appeared in the logs, the trajectory must be rejected as an ungrounded hallucination.
  - The execution must follow 'Logical Entailment,' where every sequential step is a necessary prerequisite for the next or the final answer. You should confirm that the agent didn't perform 'brute force enumeration' (calling every tool) but instead followed a targeted path based on investigative turns. For instance, the agent should search for the relevant threshold or database ID *before* attempting to query it.
  - Selected traces must demonstrate 'Subgoal Completeness,' ensuring that no part of the original multi-part request was ignored during execution. You must verify that the 3-6 tool calls cover all implicit requirements mentioned by the user (e.g., if asked for dates AND locality, both must be retrieved, and all nested constraints satisfy the final filter). Any trace that exhibits 'premature stopping' must be discarded.
  - The trajectory must exhibit 'Discovery Accuracy under Distraction', where the orchestrator correctly filtered out plausible distractor tools based on precise schema understanding. Verify that the agent did not call tools that were marked as distractors unless there was a justifiable failure in the primary target tools. This confirms the coordination logic is resilient to noise.
* **Rejection Criteria**:
  - Reject any trajectory where 'No Tools Called' despite the prompt having clear tool-dependent requirements (e.g., finding real-time papers). This 'Discovery Bypass' indicates a catastrophic failure of the agent's orchestration triggers. This often happens when the model tries to answer from its own internal pre-training memory for a task that spans real, production-server state.
  - Reject traces where the agent makes 'Intuitive Leaps', attempting to solve a downstream parent node without first retrieving the necessary evidence for its prerequisite child nodes. If the agent identifies 'Alan Turing' before it has executed the searches to confirm the 'London population' and 'Princeton degree details' from the environment, the example fails the dependency topological constraint.
  - Discard traces where 'Incorrect Tool Parameters' caused a terminal system error that the agent failed to recover from during its turn. This includes passing a string to an integer field or missing a required 'database_id' that was clearly available in the previous observation. High-quality data requires the orchestrator to demonstrate 'Schema Hygiene' by honoring the JSON constraints.
  - Reject any trace where the agent's final answer contains 'Floating Hallucinations'—facts that are physically correct in the world but were never actually returned by the tools in the trajectory. This indicates the agent looked outside its grounded evidence chain (using memory) which violates the core principle of context-augmented orchestration. Every number or name in the final QA pair must be visible in a tool observation.
