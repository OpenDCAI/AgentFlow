# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Begin by harvesting candidate situations where Parallel Subtask Scheduling is the true bottleneck, looking for explicit instances of latent independence across multi-hop questions. Inspect tool documentation, worker descriptions, and environment affordances before writing any question so that the future task requires concurrent routing over separate domains.
  - Audit tool sets for semantic separation where different tools or workers possess specialized knowledge required for a single request, but the order of consultation does not logically matter. You must verify that the environment provides workers with distinct topic attributes, such as a 'Price Expert' and a 'Quality Expert', which can be utilized simultaneously.
  - Identify 'Global Constraint Anchors' by searching for environmental data points that act as mandatory prerequisites for all intended parallel sub-tasks, such as a global deadline or a project-wide budget. To execute this, the agent must query tools to ensure the shared context is established before broadcasting it dynamically to all parallel workers.
  - Evaluate the model's ability to estimate completion latency for its parallel sub-tasks to ensure position-aware synchronization without global system crashes. Look for tools offering predictable output token sizes, such as a localized lookup tool versus an extensive document summarizer, to gauge asynchronous limits.
* **Target Trajectory Profile**:
  - A good trajectory for Parallel Subtask Scheduling must explicitly contain a decisive branching or Promise-Dispatch-Sync point rather than a straight-line, repetitive serial solution. The branching should manifest as a concurrent sequence that issues background tool threads while the main task logic naturally progresses forward.
  - The trajectory must remain compact enough that the parallel capability signal is not drowned out by an overarching volume of minor, unrelated operations. Target traces between 2 to 6 critical actions to ensure each documented step functionally contributes to either the splitting or merging phases of the parallelized execution map.
  - The trace should capture 'Multi-Target Parameter Propagation,' demonstrating that the orchestrator provides the SAME global data (e.g., a Budget state) to every specialist running in parallel. You must observe the exact same data vector being transmitted in the JSON payload of concurrent sub-agent calls.
  - The final step must encapsulate integrating heterogeneous sub-results synthesized from independent concurrent threads into a single, cohesive terminal answer. A multi-round comparative analysis where concluding paragraphs precisely intertwine facts verified by distinctly dispatched entities serves as a perfect trajectory.
