# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify global structural bottlenecks where a task involves 'Nested Logic' or 'Multi-Layer Dependencies' that would likely cause a reactive agent to fail. You must scan the tool documentation for prerequisites that require data from an unrelated domain, such as a weather tool needing a coordinate from a separate location-lookup tool. A concrete edge case involves a task that looks simple but actually requires a 'root fact' to be discovered before five parallel sub-tasks can even be scoped, necessitating an upfront DAG approach.
  - Audit the environment for 'Parallelization Opportunities' by mapping which tools can be executed without overlapping input artifacts. You should purposefully search for multi-entity requests (e.g., 'Check the status of three different servers') to see if the environment allows simultaneous dispatches. An important example is finding a data lake where files are stored in distinct clusters, allowing you to plan a DAG where multiple 'File Agents' act as leaf nodes independently before a central aggregator node rejoins them.
  - Conduct 'Node-to-Edge Connection Audits' by manually tracing how the output of one tool (e.g., a JSON ID) is used as a required field in another tool's schema. You must log these specific parameter mappings as 'Ground Truth Edges' that the global planner must discover to succeed. A robust edge case is a tool that returns a list of items; you must check if the subsequent tool requires the *entire* list or a *specific filtered item*, as this determines the branching factor of the DAG.
  - Simulate 'Graph Failure Modes' by intentionally introducing circular dependencies in your experimental plans to see if the environment's validator catches them. You must record the error message (e.g., 'Cycle Detected') to understand the structural constraints of the execution engine. An important instance is attempting to plan a loop where the result of a summary is needed to start the original search, which violates the DAG property and must be flagged as an invalid planning strategy during the discovery phase.
* **Target Trajectory Profile**:
  - The trajectory must explicitly feature a 'Top-Down Architectural Pass' where the model outputs the entire vertex and edge set of a DAG before any tool observations are logged. A high-quality profile shows the agent drafting a full YAML or JSON representation of the tools and their dependencies (e.g., Node 1 -> Node 2). If the agent starts calling tools step-by-step and only discovers dependencies as it goes, it is a negative example of this global planning capability.
  - High-quality trajectories must demonstrate 'Global Utility Optimization' by choosing the shortest or most parallel path through the toolset to achieve the goal. The trace should show the agent rejecting a long serial chain (A then B then C) in favor of a branched DAG (A then [B and C] in parallel) whenever the schema allows. An edge case is an agent recognizing that even though two tasks look related, they share no data prerequisites and thus can be planned as independent root nodes in the same DAG.
  - The trajectory should capture 'Strict Dependency Fidelity' where every edge in the final plan corresponds to a real-world parameter flow discovered during exploration. The log must verify that the orchestrator didn't just 'suggest' a link, but specifically mapped 'Output_X of Tool_1' to 'Input_Y of Tool_2'. A successful profile avoids 'Floating Nodes'—tools that are selected but have no inputs linked to the user query or previous results—ensuring every part of the plan is causally justified.
  - Successful profiles must exhibit 'Fail-Fast Hierarchical Validation' where the agent's internal thought process checks for syntax, cycles, and connectivity within the plan. The trace is excellent if it shows the agent drafting a plan, checking it against the 'Acyclic' rule, and then surgically modifying an edge to resolve a potential cycle before final output. This demonstrates the model is not just mimicking a structure but is actively reasoning about the mathematical properties of the execution DAG.
