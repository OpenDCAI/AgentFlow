# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform 'Macroscopic Topology Identification' by executing high-level reconnaissance across the infrastructure to map major architectural phases (e.g., Network Segments, App Tiers, File systems). You must instruct the agent to query the environment mapping service first to understand the structural boundaries before issuing any task execution. An edge case involves identifying an isolated service 'island' that cannot be reached directly, requiring the agent to register a workaround or staging pivot in its mental model.
  - Prioritize 'Strategic Intents' over technical implementation during discovery to ensure the orchestrator operates exclusively as a high-level manager. Formulate potential actions as abstract blocks—like 'Configure Database' or 'Sweep Directory'—and map them to the declarative execution layer rather than scripting low-level API queries. A concrete example is recognizing that a 'Data Migration' intent is needed, even if the underlying storage mechanisms (SQL vs NoSQL) are entirely obfuscated by the execution framework.
  - Leverage 'Environment State Auxiliary Services' to offload granular technical logs and prevent catastrophic context window bloat during extended operations. Instruct the orchestrator to use a 'Summary and Parse' protocol that abstracts sprawling lists (e.g., 50 port IDs) into high-level status flags (e.g., 'Service Pool active'), hiding the noise from its immediate prompt space. An important case involves a massive JSON configuration output; the orchestrator should only ingest the single 'Deployment_Status: Success' flag while letting the persistent state backend store the full JSON block for downstream workers.
  - Audit 'Phase Prerequisites' by continuously checking for necessary identifiers, configurations, or operational tokens generated in previous macroscopic steps before attempting dependent tasks. You must verify that the state tracker successfully captured these logical keys and that the orchestrator actually queries for them when setting up the next declarative node's arguments. A useful edge case involves discovering an SSL certificate during the 'Provision Web Tier' phase and explicitly routing that generic credential into the abstract 'Setup Load Balancer' task immediately following it.
* **Target Trajectory Profile**:
  - The trajectory must feature a 'Planning-Execution Decoupling' structure where the Assistant emits declarative function calls or macro-tasks instead of generating scripts or atomic system interactions directly. This is clearly verified by observing the agent's action field containing high-level framework commands while the subsequent observation merely acknowledges state transitions. A rejected trajectory is one that mistakenly reverts to outputting massive Python loops or dense CLI strings at any step.
  - High-quality traces maintain 'Context-Efficient Sequencing', showing the orchestrator managing massive multi-step operational chains without approaching prompt token saturation. The trace should vividly demonstrate the orchestrator selectively requesting only the specific, immediate variables it needs from the environment state service for its next macro-decision. This proves the orchestrator is correctly offloading the heavy burden of previous tool logs into external memory structures rather than dragging them along.
  - Successful profiles include a 'Strategic Rationale' block that distinctly outlines why the orchestrator chose a particular macro-path over alternatives present in the topological map. The agent must logically declare its broader reasoning, such as explicitly noting that a secondary processing tier must be built first because the primary target lacks available compute resources. Providing this strategic intent audit trail confirms the agent is performing high-order navigation rather than random task dispatching.
  - Capture profound 'Asset Reuse Across Horizons' where identifiers or states generated in an exceptionally early operational epoch are accurately retrieved and applied in a completely disconnected final epoch. You must demonstrate the orchestrator securely interacting with the state backend to pull a value created in Step 2 to satisfy a mandatory input barrier located sequentially at Step 15. A trace failing to achieve this indicates severe memory erosion, proving the declarative model failed to correctly unify disconnected macroscopic sessions.
