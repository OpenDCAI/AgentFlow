# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Critical configuration variables necessitated in final-stage execution mechanics MUST stem irrefutably from 'Consensus Memory' inputs actively registered by asynchronous antecedent workers.
  - Traces must prove targeted 'Macro Orchestration', employing high-level prompts like 'Read recent discoveries posted to board' heavily favored over manual data piping string architectures.
  - The interaction provides clean 'Temporal/Historical Dependency', affirming an item’s or status's whereabouts is resolved entirely via evaluating timestamped operations logged within the out-of-context 'History Board'.
  - The accepted trace enforces drastic 'Contextual Integrity', minimizing cross-domain bloat during multi-agent handoffs by restricting transmissions exclusively to the refined values surviving inside the common blueprint array.
* **Rejection Criteria**:
  - Reject categorically traces replacing strategic state-blackboard utilization with immense manual command loops forcefully pumping dense context arrays through simplistic prompt chains.
  - Discard immediately interactions featuring robustly established 'Consensus Memory' structures completely ignored by final generation layers utilizing internal pre-training hallucination patterns to finish the goal.
  - Systematically exclude scenarios characterized by 'History Blindness', wherein an orchestrator repeatedly asks the user for the whereabouts of an asset completely documented inside its own prior state transitions.
  - Reject workflows suffering 'Information Saturation' failures from funneling completely unrefined, raw multi-megabyte log downloads straight into subsequent specialized sub-agents, bypassing necessary board sanitization completely.
