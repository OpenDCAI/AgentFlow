# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The trajectory is acceptable only if the 'Orchestration Complexity Level' is logically justified by the Axis-Audit (Depth, Parallel, etc.) recorded in the exploration step. There must be an observable correlation between the structural demand and the chosen MAS size. For example, if the 'Parallel' axis is 1, the system must accept a single-agent delegation (Low DoM) or direct solve; if the axis is 4, it should accept a parallel MAS (High DoM). This ensures the synthetic data represents 'Pareto-Optimal' coordination behavior.
  - Selected traces must exhibit 'Axis-Grounded Verification,' where the final deliverable's quality can be traced back to the specific coordination mechanism chosen (e.g., a Moderator agent successfully catching a poisoned note on the Robustness axis). You must verify that the 'Verification Protocol' (Intermediate vs. Final evaluation) was implemented as described in the calibration requirements. A strong case involves a MAS identifying a hallucination in Step 2 through an explicit 'Verification Edge' that was missing in the SAS baseline. This validates that the MAS approach provided genuine value.
  - The orchestrator must demonstrate 'Global Reasoning over Trajectory Reasoning' by using Holistic Orchestration (generating the entire graph at once) rather than incremental step-by-step additions. You should cross-check the 'agent' block to ensure all sub-agents and their edges are defined together in the first turn. Any trace that 'incrementally' adds agents one by one is rejected in favor of the 'MAS-Orchestra' holistic paradigm. This ensures the data trains for global system-level holistic reasoning.
  - The interaction must maintain 'Logical Entailment' between the DoM configuration and the final performance gain. Reviewers are mandated to check if a 'High DoM' MAS actually improved the correctness or reliability compared to the single-agent trial. An edge case is the orchestrator successfully identifying that a 120B reasoning model can handle the 'Depth' as a SAS, whereas a 7B model would have required a multi-agent 'Self-Refine' loop. This proves the calibration logic is aware of both 'Task Complexity' and 'Model Strength'.
* **Rejection Criteria**:
  - Reject any trajectory exhibiting 'Unjustified Agent Proliferation' or 'Over-Engineering' where a complex multi-agent system is created for a trivial or strictly sequential task. If the path to the answer is a straight-line CoT with no parallel branches and the model creates 5 agents, it represents coordination waste. This is a common failure where models 'hallucinate' team value without structural proof. High-quality data requires that 'More Agents is All You Need' only when the structure demands it.
  - Discard traces where the 'Robustness' gain is claimed but no adversarial signal was actually neutralized in the trajectory. If the orchestrator adds a 'Moderator' agent but the environment context contains no conflicting notes or poisoned info, the skill is not being exercised. The synthetic data must include a 'Conflict' or 'Adversary' that requires the multi-agent checkpoint to survive. Failure to provide a 'Competence Edge' challenge makes the MAS configuration ceremony rather than capability.
  - Reject trajectories where the 'Orchestrator' attempts to use SAS for tasks with High Parallelism (e.g., axis value > 4) and subsequently fails due to length limits or context saturation. If the system stays at 'low DoM' for a task that physically requires 5 separate searches, it demonstrates 'Complexity Blindness'. Success must be achievable within the constraints of the chosen paradigm; if the SAS 'fails' and the agent doesn't scale to MAS, it is a negative orchestration pattern.
  - Reject any trace that fails to utilize the 'Function-Calling Abstraction' for sub-agents, instead outputting raw code-level execution or internal sub-agent logic inside the orchestrator's context. The orchestrator must only see the sub-agent 'Signature' (e.g., `SCAgent`, `WebSearchAgent`) and its parameters. If the orchestrator begins 'doing' the sub-agent's reasoning in the thinking section or the main response, it violates the 'Holistic Orchestration' principle where sub-agents are treated as black-box functions.
