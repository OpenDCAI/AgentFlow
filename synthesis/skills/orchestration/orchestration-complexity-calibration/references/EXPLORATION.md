# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a 'Structural Axis Audit' by mapping the user request against four core dimensions: Depth (longest sequential chain), Breadth (number of dependencies per node), Parallelism (independent sub-goals), and Horizon (need to track intermediate answers). You must quantify these values by scanning the prompt for keywords like 'and then' (Depth), 'compare these four things' (Parallelism), or 'from the results of both' (Breadth). For example, a request to 'Search for X, Y, and Z then summarize' results in a Parallel value of 3 and a Depth value of 2, which acts as the 'structural signature' for your calibration decision. This ensures the orchestration density is derived from the task's architecture rather than arbitrary preferences.
  - Establish 'Sub-Agent Competence Thresholds' by performing a trial call or a metadata query to determine if the baseline worker (e.g., a standard 7B model) identifies the current sub-task as 'challenging' or 'beyond context'. You must log if the sub-task requires specialized tools (like multi-turn search) that a SAS cannot manage without getting lost in its own execution details. A concrete edge case is a task that looks like basic math but requires verifying 10 different documents; you must flag this as an 'At-the-Edge' task where MAS gains are likely to emerge over SAS. This separates tasks that can be handled by a single 'smart' model from those requiring a coordinated 'team'.
  - Probing for 'Adversarial Signals' in the environment by scanning retrieved context for conflicting identifiers, metadata notes ('Note: verify this'), or multiple versions of the same variable. You must explicitly count the number of potential 'Misinformation Nodes' in the current project state to define the task's Robustness axis. An important example is finding a data lake where folder 'New' and folder 'Old' both contain a 'final_v1.xls' file; you should record this as a High-Robustness requirement to justify adding a verification agent to the plan. This prepares the orchestrator to deploy 'moderation' as a specific functional sub-agent.
  - Conduct 'Holistic Plan-Level Prototyping' by attempting to draft the entire multi-agent graph in your internal thoughts (the 'Thinking' section) before committing to a Low-DoM or High-DoM track. You must verify if the nodes and edges can be constructed as a Directed Acyclic Graph (DAG) in one pass, or if the logic is too fuzzy, which may require an initial 'Research Stage'. A useful edge case involves a task with 10 sequential dependency steps (Depth=10); your prototype should reveal that as a SAS-leaning task since a 10-node MAS graph introduces too much credit-assignment noise. This ensures the orchestrator reasons at the 'plan level' rather than at the 'trajectory level' during calibration.
* **Target Trajectory Profile**:
  - The trajectory must explicitly demonstrate a 'Decision to Scale' turn where the orchestrator evaluates the axis-based complexity and chooses a specific DoM. It is high-quality only if the 'Thinking' block contains a comparison, such as 'This math task is high-depth but serial, so I will stick to a single powerful CoTAgent (SAS mode) to minimize cost and error propagation'. Any trajectory that blindly spawns agents for simple serial tasks or uses a single agent for highly parallel/adversarial tasks is a negative example. This demonstrates active calibration of resources toward the Pareto frontier.
  - High-quality profiles clearly distinguish between 'In-Domain' execution and 'Edge-of-Competence' coordination. The trace is excellent if it shows the orchestrator recognizing that while it *could* solve the task itself, the sub-agent's specialized workflow (e.g., DeepSearch) provides a tangible benefit for this specific 'Breadth' or 'Horizon' requirement. An essential edge case is the orchestrator deciding to delegate to a 'SCAgent' (Self-Consistency) specifically because the user asked for high confidence in a numeric result, showing quality-driven scaling.
  - Successful traces must display 'Structural Alignment' where the number of parallel branches or sequential nodes in the generated MAS reasonably mirrors the Axis-values found in the exploration phase. For instance, if the Parallel value is 4, the trace is superior if the orchestrator dispatches 4 concurrent sub-agents in a holistic graph. This proves the orchestrator is not just 'hallucinating' a team but is functionally mapping the team size to the task's inherent breadth. A rejected trace is one where the graph complexity appears random or disconnected from the prompt's requirements.
  - The trajectory should capture 'Efficiency-to-Accuracy Balancing' where the final thought block mentions the cost vs. performance trade-off. You must verify that the orchestrator acknowledges using a 'Low DoM' for cheaper, faster results when SAS suffices, or 'High DoM' for accuracy gains when sub-agent individual strength is thin. A useful example is an orchestrator selecting a 'SCAgent' only after determining that a 'CoTAgent' would likely struggle with the specific arithmetic complexity, showing deliberate calibration against model limits.
