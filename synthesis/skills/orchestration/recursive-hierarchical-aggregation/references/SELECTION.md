# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The trajectory is strictly acceptable only if the 'Total Input Volume' navigated across the entire hierarchical tree is objectively proven to be at least 3x larger than the terminal synthesis agent's single context threshold. You must be able to visually point to minimally two discrete, functioning layers of data reduction occurring in the provided trace. If 1,000 logs are accurately chopped into 10 domain summaries, which are subsequently squeezed into 1 final answer, the mandatory hierarchical structure is irrefutably satisfied.
  - Selected traces must boast 'Targeted Aggregation Accuracy', meaning the ultimate root-level response successfully hybridizes totally non-overlapping variables originating from distinctly different leaf chunks into a single unified insight. If Sub-Region A flags a power warning and Sub-Region B flags a thermal issue, the root synthesis must logically calculate an imminent hardware meltdown. This validates that the 'Meta-Analysis' value achieved by the orchestration layer is fundamentally stronger than the sum of its isolated parts.
  - The trace must document 'Parameter-Based Chunking', guaranteeing that sub-agent tool dispatches harness pinpoint arguments like start/end line indices or precise X/Y bounding boxes to definitively establish their processing scope. You must rigorously verify that the central orchestrator is not lazily sending identical context to every sub-worker in the pool. Any trajectory permitting sprawling, overlapping data chunks without an express technical justification must face immediate rejection.
* **Rejection Criteria**:
  - Reject any trajectory where the orchestrating agent capriciously creates sub-tasks that are sufficiently small to have been successfully processed in a singular, flat turn with zero chunking. If the total dataset is a mere 500 words and the agent awkwardly splits it into five 100-word blocks, this constitutes unnecessary 'Over-Engineering' that provides nil value. The overarching objective of this distinct skill is to resolve genuine, hard computational bottlenecks, mandating rejection of artificially tiny tasks.
  - Discard instantly any run where the highly anticipated 'Summary of Summaries' simply acts as a mindless, word-for-word string concatenation of the preceding intermediate reports. The absolute final tier MUST orchestrate a legitimate top-level synthesis, such as computing grand totals, pinpointing global risks, or smoothing dense jargon into a digestible unified theory. If the root agent strictly outputs 'Report 1: X... Report 2: Y...', the intended 'Hierarchical Compression' mechanism failed entirely.
  - Reject categorically any trace suffering from 'Context Overload' at the terminal root node, wherein the orchestrator recklessly forces too many sub-summaries into the final step, blowing past its context maximum. This unequivocally flags a fatal 'Depth Calculation Failure', insisting the orchestrator should have dynamically provisioned a tertiary intermediate reduction layer. If fifty sub-reports are shoved into the ultimate agent resulting in severe truncation or hallucinated gibberish, the structural scalability has undeniably failed.
