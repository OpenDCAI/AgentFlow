# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Sample the total environment volume by executing a wide-scope baseline command (e.g., list all files, measure image dimensions) before initiating the synthesis plan. You must explicitly calculate the degree of overflow by comparing the total object count or pixel density against the documented token or perceptual limit of the designated worker agents. For instance, if an image is 10k x 10k pixels and the vision tool maxes out at 1k x 1k, you must log the necessity for a grid-based spatial partition to ensure the orchestrator is grounded in the environment's true scale.
  - Identify 'Semantic and Structural Breakpoints' in the dataset to determine how the massive context should be partitioned, avoiding the dangerous splitting of singular logical events across multiple processing chunks. You should actively look for chronological timestamps, discrete project folders, or physical map legends that allow you to group tightly related artifacts together prior to worker dispatch. A concrete edge case involves a long multi-step error trace; you must forcefully ensure all lines of that specific error remain bound within a single chunk so the leaf-node agent can accurately identify the local root cause.
  - Audit the available worker pool to identify which agents are capable of performing first-tier 'Granular Extraction' versus second-tier 'Abstract Synthesis'. You must consult the agent metadata to verify domain focus, matching a 'Code Reader' strictly to repository leaf chunks and a 'Summary Director' to the root tier. An important edge case occurs when no specialized agent exists for a specific data type, mandating the orchestrator to deploy a generalist worker strictly constrained by a hyper-specific extraction prompt to maintain extraction fidelity.
  - Perform a 'Data Heterogeneity Audit' to evaluate if disparate segments of the global context require drastically varying reduction strategies, such as mixing structured database querying with unstructured visual defect scanning. You must purposefully sample diverse items from across the raw source pool to proactively determine if the leaf-node processing tier must be a heterogeneous mix of specialized tool-callers. This ensures the foundational layer of the aggregation hierarchy respects the native technical formats of the original artifacts rather than forcing a clumsy homogenization.
  - Calculate the required 'Aggregation Depth' to determine the exact number of recursive summary layers needed to reduce the massive data blob to a token-safe final target state. You must execute mathematical logic—evaluating (Total Context / (Chunk Size * Reduction Ratio))—to assess whether a simple one-tier map-reduce is sufficient or if a deep 'Summary of Summaries of Summaries' is required. A robust test case involves a dataset so large that a single summary layer still vastly exceeds the final compiler's context window, crucially demanding a middle-tier 'Consolidator' layer to prevent crash failures.
* **Target Trajectory Profile**:
  - The trajectory must explicitly showcase a structured 'Decomposition-to-Recomposition' paradigm where a monolithic input is visibly sliced into isolated sub-calls before being causally merged. It is considered high-quality only if the orchestrator distinctly logs its exact partitioning math (e.g., 'Processing pixel quadrants A through D independently...') immediately prior to the inaugural parallel dispatch event. Any trajectory attempting to brute-force a massive dataset or dense visual artifact in a single naive LLM turn completely invalidates this orchestration capability.
  - High-quality traces must contain a robust 'Parallel-to-Sequential Reduction' topology where the leaf-tier of extraction tasks executes concurrently to drastically minimize global operation latency. The logged trace must portray multiple expert agents receiving distinct data chunks simultaneously, succeeded chronologically by a root agent receiving their unified outputs. An excellent edge case features one specific sub-chunk gracefully failing, followed by the orchestrator intelligently re-dispatching solely that isolated chunk rather than pointlessly restarting the entire massive hierarchy.
  - The recorded trajectory should vividly capture an 'Abstraction Delta' that proves the semantic density of information elevates as it systematically travels up the processing hierarchy. The execution log is ideal if 'Observation Tier 1' showcases extremely raw numbers or localized coordinates (e.g., 'Warning logged at line 450'), whereas 'Observation Tier 2' distills this into a broad organizational trend (e.g., 'Systematic latency observed in the database module'). This explicitly generates an auditable paper trail proving the active compression of sprawling details.
