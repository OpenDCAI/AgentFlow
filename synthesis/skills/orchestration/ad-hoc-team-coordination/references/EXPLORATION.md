# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Perform a recursive 'Teammate Metadata Scan' using the get_available_agents action to identify the specific skills, cost rates, and current assignment loads of all participating human and AI workers. You must log these capabilities as the primary constraints for your task-allocation matrix, ensuring that a 'Human-Only' or 'AI-Expert' requirement in the task graph is strictly matched to a valid worker profile. For example, if a node requires 'Legal Certification,' you should verify if the 'External Counsel' worker currently in the pool possesses that specific attribute before assigning the task. This ensures the coordination is grounded in the actual, non-stationary capabilities of the team.
  - Execute proactive 'Stakeholder Intent Elicitation' by sending messages to the stakeholder agent (Client/Management) to extract specific weights for multi-objective preferences (U). You must log the initial priority list—such as balancing cost, speed, and quality—and monitor the communication store for 'Change-Points' where these weights might shift during the workflow. An important edge case is when a stakeholder moves a 'Compliance' weight from 0.1 to 0.6 mid-task; you must explicitly acknowledge this shift to justify re-planning the subsequent tool sequences. This separates baseline execution from true preference-aware management.
  - Audit 'Task Graph (G) Feasibility' by comparing the estimated hours and required skill IDs of the task nodes against the current throughput of the worker agents. You must identify potential bottlenecks by calculating the 'Wait-Time Delta' for dependent nodes if a critical-path worker is already at max capacity. A concrete scenario involves a manager identifying that the 'Human Reviewer' is the only one who can sign off on a task, requiring the scheduling logic to prioritize the reviewer's upstream dependencies to minimize idle time. This ensures the workflow architecture is optimized for real-world resource scarcity.
  - Implement 'Dynamic Resource Tracking' by using the Inspect(T) action to read-only worker logs and artifact registries (X) during execution. You must capture observations where a worker's output (e.g., a code snippet or a draft) fails a hard constraint (H) or verification check, triggering a 'Stop and Pivot' reasoning block. A robust edge case involves a manager agent observing that an AI worker consistently produces 'Low Quality' output, prompting a strategic decision to re-assign the task to a human expert at the next available timestep. This justifies the manager's role as the active overseer of team quality.
* **Target Trajectory Profile**:
  - The trajectory MUST feature a 'Team Churn Response' event where an AI or human worker joins or leaves the environment, leading to an immediate modification of the task assignments. A high-quality profile shows the manager agent acknowledging the new arrival (e.g., 'Agent X has joined with Skill Y') and then calling AddTask or AssignTask to integrate them into the workflow. If the manager agent ignores a new, more efficient expert and continues using sub-optimal workers, the trajectory is a negative example of this capability. This pattern demonstrates the agent's ability to coordinate in ad-hoc, changing team structures.
  - High-quality trajectories must contain a 'Multi-Objective Re-balancing' turn where the agent changes his execution strategy in response to a stakeholder preference update. The trace should show the agent proposing a 'Fast' plan, receiving a message from the stakeholder to 'Save Money,' and then using RemoveTask or AssignTask to switch from an expensive expert to a cheaper, slower alternative. This proves the orchestrator is not just following a static script but is dynamic and reactive to shifting preferences ($U$). This level of adaptation is a core pillar of the manager agent challenge.
  - The trajectory should capture 'Hierarchical Strategy Reasoning' where the manager explains why a specific decomposition (DecomposeTask) or delegation was chosen to mitigate a bottleneck. The log is excellent if it shows the agent identifying a 'Resource Contention' (e.g., two tasks needing the same human) and resolving it by re-sequencing the dependencies with AddEdge. An essential edge case is a manager realizing that a task is too complex for its assigned AI worker and autonomously splitting it into smaller sub-tasks for a larger group of specialists. This ensures the synthetic data models strategic managerial foresight.
  - Successful profiles include 'Proactive Stakeholder Management' turns where the agent reaches out to clarify ambiguity before cost is incurred. The log should show the agent identifying a conflict between two constraints (e.g., 'Speed vs. Budget') and asking the stakeholder for a tie-breaking decision. A rejected trajectory is one where the agent blindly picks a path that violates one of the objectives without seeking guidance, as this reflects poor organizational hygiene. This highlights the agent's role in maintaining transparent human-on-the-loop oversight.
