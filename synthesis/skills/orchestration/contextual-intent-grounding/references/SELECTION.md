# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The trajectory is acceptable only if the 'Inferred Constraint' used by the agent can be objectively traced back to a specific observation in the exploration turn. You must be able to point to the exact line in a previous tool output (e.g., a header row in a CSV) that defines the format used in the final action. For example, if the agent uses a currency symbol in the final answer, that symbol must have appeared in at least one retrieved reference entry. This ensures the data represents grounding rather than pre-training hallucination.
  - Selected traces must demonstrate a 'Parameter-Level Dependency' where at least one non-obvious argument in the final tool call was derived from an environmental artifact. This means the tool call would likely have failed or been inconsistent if the agent had not performed the prior observation. A strong case involves an agent correctly identifying a 'Project ID' or 'Parent Folder ID' that was never mentioned in the prompt but was discovered by looking at siblings. This validates that the orchestration logic is physically coupled to the environment state.
  - The trajectory must provide a clean 'Contextual Divergence' from generic defaults, proving that the agent chose a specific (and correct) formatting or logical path over a standard LLM default. For instance, if the model standardly uses 'John Doe' as a placeholder but the environment uses 'Doe, John', the trace is only acceptable if the agent follows the environment's 'Last, First' convention. This metric ensures the synthetic data specifically trains for environment priority over internal bias. Any trace that falls back to common defaults despite available evidence should be rejected.
  - The agent must demonstrate 'Hierarchical Awareness' by placing new artifacts in a location that preserves the discovered structural logic of the system. This is verified by checking that the 'parent_id' or 'path' in the final action is a logical continuation of the paths observed during the tree-traversal phase. An edge case is an agent recognizing a month-based folder system and autonomously creating a '2025-05' folder to house a new file because it doesn't exist yet. This proves the agent understands the 'Meta-Rule' of the environment state.
* **Rejection Criteria**:
  - Reject any trajectory where the agent 'guesses' the correct format or parameters successfully without ever calling a tool to see the existing state. This signifies a 'data leak' or a trivial task where the agent's internal knowledge matches the environment by accident, which provides no training signal for the capability. A common edge case is a prompt that happens to use a format (like ISO dates) that is common in both the LLM's memory and the environment. These should be discarded in favor of tasks with unique or idiosyncratic environment styles.
  - Discard traces where the agent reads the context (e.g., reads the header) but then fails to apply those discovered rules in the subsequent action. This represents 'Observation Neglect,' where the agent gathers evidence but still follows its own internal shortcuts or makes formatting errors. For example, if the agent sees that the spreadsheet uses 'In Progress' but it writes 'Active' in the next step, the link is broken. The synthesis must be strictly faithful to the evidence retrieved to be useful for grounding.
  - Reject trajectories where the 'Reference Artifact' is too ambiguous to provide a definitive rule, leading the agent to make an unverified choice anyway. If the existing data contains three different date formats, the agent cannot 'ground' its intent, and the task is poorly designed. A high-quality trace requires a clean, recognizable pattern in the environment. If the agent makes a 'best guess' in a noisy environment without acknowledging the ambiguity or seeking a definitive template, the trace lacks the necessary orchestration hygiene.
  - Reject traces where the solution depends on 'Global Knowledge' that is not accessible via tools or environment state (e.g., guessing a corporate-specific acronym). Any logic used to fill a field must be derivable from the combination of the prompt and the observed files. If the agent 'magically' knows a project code that was never logged in any search result or file-read, it represents a synthetic failure. The evidence chain must be 100% complete within the recorded trajectory artifacts.
