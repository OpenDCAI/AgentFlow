# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Proactively search for 'Reference Siblings' when the task objective involves adding, updating, or syncing data to an existing collection or environment. You must execute a read or list command on objects that are logically related to the target destination, such as looking at 'Version 1.0' of a file when tasked to create 'Version 2.0'. A concrete edge case is when a user asks to 'add a new user to the system'; you should first query existing user profiles to see if there are hidden mandatory fields like 'Department ID' that aren't mentioned in the prompt. This ensures that the exploration produces a 'Style Guide' derived from actual data.
  - Map the 'Structural Conventions' of the environment by performing a deep directory or database tree traversal before initiating any write actions. You must identify if the environment follows a specific hierarchical naming pattern (e.g., date-based folders or ID-based partitions) by logging the paths of at least 3-5 existing items. For example, if you find that all existing project notes are stored in 'projects/YYYY/MM/title.md', record this pattern as a hard constraint for the new task. This avoids the common failure mode where an agent places a file in a generic root directory when a structured sub-folder system is already in use.
  - Perform a 'Schema-to-State Audit' where you compare the formal tool documentation against the actual values found in common objects. You must explicitly log cases where the real-world data uses more restricted values than the API technically allows, such as an API that accepts any string but a sheet that only uses 'TRUE/FALSE'. An important edge case is finding a database where a 'Contact' field is always formatted as a hyperlink; you must note this formatting requirement to ensure the synthetic synthesis matches reality. This strategy separates shallow technical compliance from deep contextual grounding.
  - Audit 'Environmental Templates' such as `.md` files, header rows, or sample records to discover implicit documentation that the user has provided. You must search for files named 'template', 'example', 'readme', or 'sample' within the current workspace to see if they contain instructions or placeholders for the task at hand. A useful example is finding a 'budget_template.xlsx' that defines the math formulas expected for new entries, which you must extract to ensure the agent's synthesized entries are functionally complete. This identifies instructions that are 'on-path' but not in the prompt.
* **Target Trajectory Profile**:
  - The trajectory must explicitly show a 'Survey Before Action' sequence where the agent retrieves the state of surrounding objects before attempting to create the target object. It is high-quality only if the observations from the survey phase are visibly used to construct the parameters for the subsequent tool call. A trajectory that jumps straight to a 'Create' or 'Post' action without looking at siblings or templates is a negative example of this capability. This pattern demonstrates the orchestrator's foresight in gathering context rather than relying on default behaviors.
  - A successful profile includes a 'Pattern Inference' step where the agent's internal reasoning/thoughts correctly describe the logic it found in the environment. The agent should state something like 'Observation of entries 1-5 shows that the date must be in YYYY-MM-DD format, so I will format the new entry accordingly.' An edge case is a trajectory where there are conflicting patterns, and the agent identifies the most recent one as the authoritative template. This provides a clear audit trail showing that the agent's final action was grounded in its preceding observations.
  - The trajectory should capture an 'Ambiguity Resolution' event where the agent chooses a specific path because it discovered a matching artifact in the environment. For instance, if the user asks to 'update the site' and there are two sites, the trace is excellent if it shows the agent checking both and finding a 'Last Updated' flag that aligns with the user's intent. This shows the agent using the environment as a source of truth for disambiguation. A rejected trajectory would be one where the agent simply picks a target at random or asks the user for help without exploring first.
  - High-quality trajectories must remain compact and avoid 'Information Flooding' by selectively reading only the relevant reference headers or sample rows. The trace should demonstrate the agent using precise tool arguments (e.g., `range='A1:Z5'`) to fetch just enough context to see the format, rather than dumping 10,000 rows. A useful edge case is the agent using a 'Search' tool to find a specific existing item that matches the user's domain, effectively using the search as a 'style lookup' mechanism for the broader task.
