# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify 'Expert Signal Divergence' by searching for environment states where specialized tool outputs or agent roles (e.g., Fundamentalist vs. Sentiment Analyst) are likely to provide contradictory or complementary evidence. You must record these tension points—such as a positive market sentiment vs. a negative financial margin—as critical triggers that force the orchestrator to initiate a hierarchical refinement loop rather than a simple summary. A concrete edge case involves two agents providing identical answers but for conceptually conflicting reasons, which you must flag for mandatory logical reconciliation to avoid hidden semantic inconsistencies.
  - Differentiate between 'Granular Transformation' workers and 'Broad Generation' workers by identifying roles suited for specialized subsystem refinement, such as a 'Coder' role dedicated to transforming abstract stubs into executable modules. You must verify that the environment provides specific metrics (e.g., SI unit registries or Python REPLs) that these transformation workers can use to validate their localized refinements during the loop. An important example is an engineering agent noticing that a generator provided a 'one-line formula,' prompting the deployment of a specialized coder to add logging, CLI, and unit tests to that specific node.
  - Audit for 'Archetypal Mode-Collapse' by comparing the outputs of single-loop sequences (Generator-Reflector) against multi-role ensembles to determine if the simplistic loop is failing to explore the design space. You must observe triggers where a single-agent response results in minimal sub-task stubs or missing requirements, which serves as the justification for scaling the orchestration to a 9-role multi-agent system (MAS). A robust edge case involves the orchestrator detecting that a 'Reflector' is providing vague 'Good job' feedback, necessitating the injection of a 'Meta-Reviewer' to enforce harder criteria.
  - Capture 'Requirement Traceability Seeds' by normalizing a project's technical handbook (Cahier des Charges) into a persistent list of unique IDs (e.g., SR-01, SR-02). You must monitor if agents correctly map these IDs into a sharedDesign-State Graph's metadata fields (linked_reqs) throughout the refinement interaction. A concrete edge case involves an agent providing a valid physical component but failing to link it to a specific 'Shall' requirement, requiring the supervisor to force a refinement turn centered specifically on traceability documentation.
  - Map 'Pareto-Optimal Mutation Space' by requiring the Generator role to propose multiple distinct variants (e.g., Min Cost, Max Performance, Lightweight) instead of a single solution. You should record the specific physical parameters that distinguish these variants to provide the 'Ranking' agent with a multi-dimensional selection surface. A useful example is creating a version that uses high-efficiency solar cells vs. one using cheap lead-acid batteries, ensuring the refinement process evaluates real engineering trade-offs rather than just stylistic differences.
* **Target Trajectory Profile**:
  - The trajectory must demonstrate a 'Multi-Role Evaluative Topology' where at least three distinct non-generative roles (e.g., Reflector, Ranker, Meta-Reviewer) process a shared artifact before a terminal decision is reached. A high-quality profile visibly shows the Meta-Reviewer providing a 'Detailed Summary' for improvement that is technically different from the Ranker's score, proving that multiple independent reviews are shaping the outcome. If the orchestrator terminates based on a single 'Success' message from a single critic, it is a negative example of coordinated refinement.
  - The trace should explicitly display 'Node-by-Node Selective Refinement' where a transformation worker (like a Coder) iterates through discrete components of a complex graph (like the Design-State Graph) to improve fidelity. For instance, the profile is excellent if it shows a 'Coder' role receiving a 5-line stub and outputting a 50-line executable module with argparse and logging. This demonstrates the system is 'deepening' the design through specialized action rather than just 'polishing' existing text strings.
  - A successful profile includes 'Instruction-Driven Iteration' where the outputs of one refinement phase (Meta-Review) physically constrain the planning for the next supervisor-led turn. The log must show the Supervisor issuing specific directives derived from the previous critique (e.g., 'Fix the panel area term in Node 1') which the Generator then acts upon. This establishes a causal chain of improvement where the system converges toward 100% requirement satisfaction through documented, evidence-based feedback loops.
  - The trajectory must showcase 'Syntactic and Semantic Stability' where the multi-agent exchange maintains perfect JSON validity (M1) even under high context-window load (60,000+ tokens). The trace is high-quality if the 'Reflector' and 'Meta-Reviewer' agents handle conflicting evidence (e.g., solar irradiance values) by citing the specific 'Cahier des Charges' sections to prune hallucinations. An essential edge case is the orchestrator detecting a 'Stochastic Drift' in the model's output at high temperature and using its supervisor role to force a low-temperature 'Correction Turn' to restore schema integrity.
