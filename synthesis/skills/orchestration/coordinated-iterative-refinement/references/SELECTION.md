# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The trajectory is acceptable only if the final answer demonstrates 'Granular Detail Scaling,' defined as producing executable modules with at least 5-10 specific technical features (e.g., CLI, I/O, unit tests) that were absent in the first-round draft. You must confirm that these features were added through a dedicated 'Specialized Transformation' turn (e.g., a Coder agent) rather than appearing as a one-shot generation. This validates that the orchestration hierarchy is actively performing task-specific refinement rather than just trivial repetition.
  - Selected traces must exhibit 'Objective Convergence on Requirement Coverage (M2),' where the percentage of satisfied 'Shall' requirements (SR-XX) increases or remains stable across the refining iterations. You must verify that the final design graph correctly links components to the normalized IDs found in the initial Cahier des Charges. A strong case involves the agent's internal thought block stating: 'The previous reflector flagged a gap in SR-02 (bacteria removal), so I will now add a ceramic filtration node to satisfy it.'
  - The trajectory must document 'Executable Grounding (M4),' where the generated scripts or modules are verified to run without error via a 'Level-1' compilation check (e.g., subprocess --help). You must be able to point to a 'Verification Action' in the trace where the agent (or an automated checker) confirms the runnability of the refined artifact. Rejection occurs if the 'Coder' agent outputs code that the 'Reflector' calls 'Perfect' but which fundamentally lacks a main entry point or has syntax errors.
  - Selected interactions must display 'Hierarchical Adjudication,' where a Meta-Reviewer or Judge agent breaks a deadlock or chooses a Pareto variant based on a formal ranking score. The trace must show the selector role justifying its choice by referencing both the 'Supervisor Instructions' and the 'Ranker's Justification' (e.g., 'I am picking Design C because it prioritizes the <20kg portability rule over the max-flow rule'). This ensures the terminal synthesis represents an optimized selection from a diverse candidate pool.
  - The model must demonstrate 'Syntactic Hygiene' by maintaining 100% JSON validity (M1) throughout the multi-role exchange, especially after long interaction sequences. You are mandated to observe the Meta-Agent's Supervisor role enforcing output format constraints if the underlying models begin to 'Loop' or 'Collpase' under heavy conversational context. Identifying explicit correction of malformed JSON blocks following a complex multi-agent reasoning epoch decisively validates robust coordination governance.
* **Rejection Criteria**:
  - Reject any trajectory exhibiting 'Mode Collapse (2AS Baseline),' where the agent provides only a single design proposal the entire session, failing to explore alternative Pareto trade-offs. If the user prompt asks for 'different options' and the agent only iterates on one single version, it has failed the selection logic required for coordinated refinement. This failure mode frequently occurs in simpler Generator-Reflector systems that lack the 'diverse variants' constraint found in high-fidelity MAS.
  - Discard flows where the 'Refinement' turn is merely a stylistic polish that fails to fix the hard-logic errors flagged in previous critiques (e.g., a Reflector identifies a physics mismatch, but the Coder ignores it). This indicates 'Interaction Decoupling,' where the roles are operating in silos rather than as a cohesive system. A high-quality trace requires the refined artifact to visibly 'incorporate the fixes' demanded in the previous evaluation turn.
  - Reject any trajectory where 'Selection' is based on hallucinated metrics that were never actually measured or returned by the toolset (e.g., an agent claiming '100% efficiency' for a physics model that it never simulated). Success must be anchored in the 'Observation' logs; if the agent says 'The script is optimized' but never called an external search or calculator to verify the parameters, the metadata is fraudulent. Every technical claim must be traceable to a specific tool observation or handbook clause.
  - Reject traces characterized by 'Placeholder Accumulation,' where refined nodes continue to contain '// TODO' comments or 'insert equations here' blocks in the final step. Coordinated refinement is intended to deliver 'runnable, production-ready' states; any orchestrator that calls 'finish' while the artifact is functionally incomplete must be disqualified. This is a common failure mode where agents lose track of 'Completeness' as the graph size (M7) grows.
  - Exclude any run failing to demonstrate 'Evidence-Based Pruning,' such as a Ranker role giving a 10/10 score to a proposal that the Reflector previously described as 'missing major subsystems.' If the internal evaluation roles contradict each other without a 'Meta-Reviewer' resolving the discrepancy, the orchestration is broken and provides no training signal. The logic flow MUST show the final selection being grounded in the *best-evidenced* expert opinion.
