# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify 'Tool-to-Agent' Domain Synergies by grouping tools with strong operational dependencies (e.g., a Web Search API and a Page Browser) into a single specialized sub-agent role. You must define clear boundaries for these sub-agents, such as a 'Local Expert' for private database tools and a 'Web Expert' for public engine tools, to prevent action-space overlap. For example, if both tools can find a person's name, you must decide which agent takes priority based on source reliability (Private vs. Public).
  - Perform a 'Macro-Task Decomposition Audit' where you break down a complex user prompt into high-level 'Information Needs' that can be mapped to specialized workers. You must verify that the environment permits a parent-child delegation structure where the parent transmits a natural language query and the child returns a refined evidence list. A concrete edge case involves a task where two sub-agents must work sequentially (e.g., Local finds the ID, then Web finds the History), which you must log as a mandatory hierarchical constraint.
  - Establish 'Knowledge-Refinement Protocols' to extract directly contributing evidence from the technical snapshots provided by tool calls. You must simulate a 'Refiner' step that calculates the embedding similarity between a tool result (e.g., an HTML snippet) and the sub-agent's reasoning thought to filter out noise. An important example is an agent browsing a webpage with 10,000 words but returning only the 3 sentences that actually answer the specific sub-query to the parent planner.
  - Audit 'Exploration Efficiency' by comparing the success rates of a flat tool-use agent against a hierarchical delegation agent in high-noise environments. You should intentionally introduce 'Web Search Noise' to see if the Root-Level Planner can stay on mission when only receiving refined summaries from the Leaf-Level Web Agent. A robust edge case involves a scenario where the Web Search is much harder than the Local Search, requiring you to record if the system spends too much time on the 'easy' source while neglecting the 'hard' one.
  - Map 'Evidence Concatenation Rules' that define how findings from different knowledge sources should be merged by the root coordinator. You must explicitly log where local knowledge (professional/targeted) acts as a baseline that web knowledge (comprehensive/timely) must supplement or verify. An essential case is finding a conflict between a local manual and a web forum, where the exploration must define which source the Planner should treat as the authoritative truth.
* **Target Trajectory Profile**:
  - The trajectory must explicitly contain a 'Root-to-Leaf Delegation' action where the Planner calls a specialized sub-agent (e.g., `<web_search_agent>`) instead of a low-level tool (e.g., `<web_search>`). It is high-quality only if the Planner provides a refined sub-query to the agent that represents one specific part of the original problem. Any trajectory where the Root agent attempts to call more than 5-10 low-level tools directly for a multi-source task should be rejected as a 'Flat RL' anti-pattern.
  - A successful profile includes a 'Knowledge Refining Observation' where the result returned to the Planner is a bulleted list of 'Factual Evidence' rather than a raw dump of tool outputs and sub-agent thoughts. The trace should show the Planner receiving a clean block of text (e.g., 'Evidence from Local: ID is 123') and then using that evidence to inform the next delegation step. This demonstrates a 'Thin Context' at the root level, preserving the context window for complex synthesis rather than technical log-parsing.
  - The trajectory must demonstrate 'Cross-Supplementation Reasoning' where the Planner identifies a knowledge gap in one source and adaptively calls a different specialized agent to fill it. For instance, the trace is excellent if it shows the Local Agent failing to find a 2024 citation, followed by the Planner immediately pivoting to the Web Agent to retrieve the timely update. This highlights the coordinator's ability to manage 'Disparate Knowledge Horizons' through hierarchical routing.
  - The trace must contain a 'Conflict Resolution Turning Point' where the Planner receives contradictory info from two sub-agents and uses its reasoning block to decide which is more reliable. You must verify that the Planner explicitly notes: 'Local Agent is more reliable for private company data, so I will prioritize its finding over the conflicting Web result.' This ensures the synthetic data captures the high-stakes decision-making required for enterprise deep search.
