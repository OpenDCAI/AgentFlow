# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The trajectory is acceptable only if the 'Refined Evidence' in the Root's observation can be directly traced back to a tool-call in a Sub-Agent's (unseen or nested) trajectory. You must verify that the information didn't just 'appear' in the Planner's context but was functionally gathered by a leaf-node agent acting as a specialized expert. For example, if the Planner mentions a 'LinkedIn profile,' the underlying Web Agent must have executed a search or browse action in its specific domain.
  - Selected traces must demonstrate 'Action-Space Partitioning,' where the Root agent only chooses between 2-4 sub-agent roles while the Sub-agents choose between 2-5 local tools. This confirms the hierarchy effectively lowered the 'Branching Factor' of the decision process compared to a flat list of 10+ tools. A strong case involves a Planner using a single `<all_search_agent>` tag to launch a parallel investigation, demonstrating macroscopic coordination.
  - The final answer must achieve 'Multi-Source Grounding,' where the answer synthesis incorporates facts from both the Local and Web specialized branches. Reviewers must confirm that at least 50% of the gathered evidence for the final QA pair originated from each distinct sub-agent branch when the prompt requires it. If the final answer only uses web data for a question that explicitly mentions 'internal records,' the delegation logic is flawed.
  - The trajectory must provide 'Evidence Contribution Scores' (explicit or implicit) where the Refiner step filtered out irrelevant tool results from the sub-agent's trace. This is verified by checking that the Root's observation does not contain the 'Hard Negatives' or 'Hallucinated Thoughts' typically seen in the sub-agent's raw execution. For instance, if a search returned 5 results but only 1 appears in the Root's log, it proves the refinement capability is active.
* **Rejection Criteria**:
  - Reject any trajectory where the Planner 'directly copies' the sub-agent's temporary conclusion or hallucinated hypothesis instead of analyzing the evidence artifacts. This signifies 'Hierarchical Laziness,' where the parent blindly trusts a child's potentially incorrect summary rather than synthesizing the ground-truth facts. The Root must always perform its own independent reasoning over the refined evidence blocks provided by the leaves.
  - Discard traces characterized by 'Context Flood' at the root level, where the system provides the sub-agent's entire 1,000-word trajectory to the Planner without any refining. This violates the 'Tiered Context' principle, leading to token exhaustion and confusion at the high-level planning stage. High-quality synthetic data for this skill requires an observable 'Refiner' filter between tiers to protect root-level reasoning capacity.
  - Reject trajectories where the 'Planner' attempts to solve the task using its own pre-trained memory for facts that are clearly labeled as residing in the local or web knowledge sources. If the Planner provides the 'father of X' without ever calling the relevant sub-agent, it represents a synthetic leakage. Success must be physically anchored in the evidence retrieved by the specialized leaf agents.
  - Reject any trace where sub-agents are given 'Direct Master-Slave' names (Agent 1, Agent 2) without domain-specific specialization (Local vs. Web). This makes the delegation arbitrary and fails to test the the 'Capability-to-Domain' mapping. The hierarchy must be functional (mapping tools to experts) to provide the appropriate training signal for enterprise Deep Search.
