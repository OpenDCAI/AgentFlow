# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Knowledge-Consistent Plan Fulfillment: Accept only those trajectories where the generated plan and subsequent actions are verified against external technical documentation (RAG source). You should confirm that if the wiki says a feature requires a specific setting, the agent enabled that setting prior to acting. For example, a bug reproduction trace is only valid if it correctly identified the game version constraints from the wiki.
  - Shortcut-to-Reliability Ratio: Accept trajectories where the use of 'Command-Line' or 'Menu-Shortcut' actions exceeds 30% of the total navigation steps for setup-heavy tasks. You must verify that these shortcuts directly replaced actions that would otherwise have been high-risk spatial interactions. A path that successfully triggers a crash through 5 commands is higher quality than one that fails after 20 manual clicks.
  - Multi-Cluster Milestone Verification: Accept only traces that achieved at least three distinct 'Milestone Guards' (e.g., Setup, Command Entry, and Event Trigger). You should cross-check the action history to ensure the agent did not 'skip' to the end through lucky guessing. For instance, accept a flight booking trace only if the agent is seen verifying the 'Flight Time' milestone before setting the 'Alarm' milestone.
  - Character-Fidelity Command Audit: Accept only trajectories where typed commands or technical identifiers (like HS codes or HEX values) are character-perfect relative to the provided documentation. You should perform a character-level comparison between the Wiki source and the agent's input log. If a command has a syntax error that the agent didn't correct, the seed must be discarded for technical inaccuracy.
  - State-Aware Termination Convergence: Accept trajectories that terminate immediately upon encountering the 'Authoritative Success Signal' (e.g., a crash, a confirmation code, or a success modal). You must ensure no 'phantom actions' occurred after the goal was reached. A successful trace shows the agent observing the 'Final State' and calling the completion function with a reason grounded in that observation.
* **Rejection Criteria**:
  - Plan-Execution Divergence (Off-Plan Wandering): Reject any trajectory where the agent significantly deviates from the structured 'Step Clusters' without a grounded reason like an environmental blocker. This indicates a loss of long-horizon focus and state-decay. If the agent starts clicking 'News' links while in the middle of a 'Bug Reproduction' setup, the seed is rejected.
  - Shortcut Hallucination Error: Reject traces where the agent attempts to use a command or shortcut that does not exist in the current software version or environment. This indicates a failure of knowledge integration (RAG) where the agent relied on generic training data over the provided wiki. For example, trying to use a `/teleport` command in a version that only supports `/tp` is a terminal failure.
  - Recursive Loop Stagnation: Reject trajectories where the agent spends more than 5 consecutive turns in a 'Menu Loop' or 'Command Loop' (e.g., repeatedly clicking 'Back' and 'Enter' on the same page). You must identify this as a failure of 'Decision Making' and environmental understanding. If the agent cannot figure out a menu after three attempts, the long-horizon path is considered broken.
  - Manual Spatial Failure (Aiming/Clicking): Reject cases where the agent attempts a difficult 3D physical task (like placing a block or clicking a moving target) and fails multiple times, leading to task abortion. The agent should have used a command shortcut or an ROI-refinement skill; failing a manual task in a long-horizon plan indicates low dexterity. For instance, failing to place 'Water' 3 times in a row results in seed rejection.
  - Unverified Intent Hallucination: Reject traces where the agent claims the task is complete (FAIL/FINISH) based on a 'Loading' screen or a transient popup before the terminal state is persistent. You must ensure the 'Answer' is derived from a durable UI update, such as a log file entry or a status code. If the agent says 'Bug Reproduced' but no crash actually occurred in the system logs, the trajectory is a hallucination.
