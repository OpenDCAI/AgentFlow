# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Semantic Action-Result Comparison: The agent must compare the UI state before and after every interaction to generate a textual abstraction of the outcome. During exploration, identify the target element, monitor for structural UI shifts, and summarize the delta into a concise action result. For example, clicking 'Find Gym' revealing a list translates to an internal memory update of 'Nearby gym list revealed'.
  - Long-Term Core Data Distillation: Identify and extract specific high-value variables from the viewport that are essential for future sub-goals to store in the LTM module. Scan the rendered screen for task-relevant proper nouns, structural metadata, or numerical values needed later. For instance, detecting the 'Founding Date' in a CV and discarding aesthetic boilerplate text.
  - Source Material Semantic Mapping: Before interacting with the target application form, the agent must parse the source document and map variables to potential GUI labels. Create a logical mapping dictionary linking source text to possible dropdowns or text boxes. For example, mapping a profile's 'Abstract' section directly to an application's 'Executive Summary' multi-line text input.
  - Widget-Specific Interaction Mapping: For every piece of mapped data, probe the destination application to identify the corresponding interaction protocol required to insert the data. Execute probing clicks to see if a field requires basic typing or a complex multi-click grid traversal. For instance, confirming whether the 'Start Date' from a resume requires manually typing the string versus clicking through an interactive calendar grid.
  - Cross-App Information Boundary Mapping: Probe application transitions to ensure that memory entries remain uncorrupted during OS-level state changes. Walk the interface from source app to the home screen and into the sink app while periodically querying the loaded variable array. An edge case involves confirming that a background application switch does not overwrite the agent's active short-term data extraction context.
* **Target Trajectory Profile**:
  - Memory-Recall Handoff Trace: A valid trajectory must showcase a clear info handoff where data extracted in Step N is utilized in Step N+M. Document the exact state mapping where a variable is localized then subsequently applied. For example, capturing a LinkedIn page where 'Apex Systems' is bolded, tracking it into LTM, and then showing it rendered inside Word.
  - Structured Entity Log Management: The trajectory must exhibit a rolling stack of action results preventing context bloat alongside persistent entities. Organize the recorded outputs so older extracted variables are safely maintained independent of recent ephemeral navigation steps. For instance, successfully recalling a 'Phone Number' even after performing 15 purely navigational steps to find the messaging app.
  - Page-Wise Sequential Fulfillment: The trajectory must record the orderly population of required GUI fields based on extracted memory variables prior to navigating away. Document state-deltas for each filled form or message blank ensuring the progression maps to local layout logic. For example, entering Name, Size, and Options consecutively in a cart form before triggering the checkout submit button.
  - Stable Success Persistence: The terminal state must demonstrably verify the final required application is actively hosting the transferred abstraction correctly. Capture the final 'Success' screenshot showing the exact data populated natively within its new housing context. For example, verifying a successfully sent SMS screen visibly contains the exact verification code copied from an email app.
