# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Depth-Threshold Success Verification: Accept a trajectory only if success is achieved at a functional depth of two or more navigation levels from the home screen. You should verify that the agent interacted with at least one intermediate 'Categorical' menu button before reaching the final goal element. For example, a task to find 'Customer Service' must show clicks through both 'Profile' and 'Help Center' to be considered hierarchical exploration.
  - Semantic Justification Accuracy: Accept only those traces where the agent's internal thought process accurately predicts the sub-menu's contents before clicking it. You must ensure the reasoning text matches the functional purpose of the clicked node, such as 'Entering Settings to find Privacy toggles'. A failure to provide this link between the goal and the hierarchy indicates a 'lucky click' rather than a reasoning-based discovery.
  - Pixel-to-Hierarchy Grounding Consistency: Accept only trajectories where the terminal interaction point (the leaf function) is located strictly within the bounding box of the element discovered during the search. You must cross-check the final action coordinates against the XML metadata of the deep-page element to ensure characterizes character-perfect grounding. For instance, if the agent clicks the center of the 'Turn off auto-play' toggle after 4 menus, the trajectory is valid.
  - Instruction-Navigation Coherence: Accept unique instances where the user prompt is intentionally vague or missing 'Next-Step' labels, forcing the agent to rely on GUI-reasoning. You should verify that the user did not provide the full path in the question, ensuring the agent had to perform the discovery itself. A task like 'Find the contact' in a messaging app is better than 'Click Account then Help then Contact' for this specific skill.
* **Rejection Criteria**:
  - Single-Hop Triviality Rejection: Reject any trajectory where the target function is prominently visible on the application's first screen or in a uniquely labeled navigation bar. If a user can click 'Customer Service' directly on the landing page via a huge icon, the case fails to measure hierarchical exploration capability. These shallow tasks should be assigned to the 'Base' capability instead of this complex reasoning skill.
  - Hallucinated Search Persistence: Reject traces where the agent claims it is 'exploring' a page but repeatedly clicks on background decoys or non-interactive text labels. You must ensure every exploratory action is performed on an element with the 'Clickable' or 'Focusable' XML attribute. Clicking three times on a static logo while claiming to search for a menu is a terminal failure in environment understanding.
  - Unrecovered Dead-End Looping: Reject trajectories where the agent enters an incorrect menu and stays there, performing redundant clicks or scrolls, without ever backtracking. The agent must show the 'Self-Reflection' required to identify that a branch is a failure and return to the main hierarchy. If the agent gets 'stuck' in the Storage settings while looking for Privacy, the seed is discarded for lack of recovery logic.
  - Guideline-Bypass via Search-Bar: Reject any case where the agent bypasses the hierarchical structure by using a global search bar if the intention was to test 'Hierarchical Navigation'. While efficient, search-bar usage collapses the complexity of the app's structural reasoning which this skill is designed to evaluate. For instance, if the agent types 'Timer' in a search box instead of navigating the Settings tree, it fails the reasoning-depth requirement.
