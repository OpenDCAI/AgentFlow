# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - State-Grounded Verification Check: Accept a trajectory strictly if verifiable log parameters prove the intended functional target feature was physically executed within the new environment. During rigorous review, formulate one explicit sentence detailing the unarguable confirmation signal and an adjacent sentence cataloging the precise final trigger action. Do not accept superficial 'visual resemblance' paths lacking durable commitment signals representing the absolute completion state.
  - Non-Trivial Adaptation Burden Constraint: Accept unique trajectories ensuring the unfamiliar or developer-specific layout genuinely serves as the central barrier to task execution. Trace the causal path backward, investigating whether a completely naive model executing rote generic app-analogy predictions could trivially stumble into success. Cases must categorically fail under brute-force lexical proximity testing to accurately test sophisticated cross-platform adaptive capability.
  - Platform-Invariant Path Efficiency: Accept strictly the navigation variants that achieve the finalized target leveraging a logical path length optimally aligned with the specific active platform conventions. Scrutinize the trace for 'Platform Hallucination' faults, wherein the agent foolishly attempts a Mobile-only tab cycle iteration against a native Desktop Web interface. A premier sample seamlessly navigates down a Desktop side-panel hierarchy directly intercepting the outcome without attempting mobile gestures.
  - Evidence Density Verification Threshold: Accept instances maintaining substantial temporal evidence to entirely reconstruct the nuanced architectural paradigm shift governing major decision sequences. Mandate the presence of a minimum of one highly informative topological observation prior to the decisive action, and an anchoring observation subsequent to it. Trajectories recording simply 'App opened' followed immediately by 'Target clicked' are structurally bankrupt and strictly barred from entering synthesis pipelines.
  - Reproducible Paradigm Constancy: Accept purely those workflow cases capable of being identically replayed utilizing the exact underlying cross-version logical structure by alternate annotator models. Execute a rapid secondary verification trajectory confirming the identical structural divergence cues propagate in sequential order and identical limits govern final success boundaries. If the application environment structurally mutates daily rendering the cross-platform comparison obsolete, firmly reject the seed.
* **Rejection Criteria**:
  - Single-Hop Obviousness: Immediately reject trace elements where the agent achieves the relocated or unfamiliar target completely instantly via the inaugural starting screen lacking navigation depth. Assess critically whether a human operating with zero context beyond step one could effortlessly blindly interact correctly; if affirmative, the sequence is disastrously shallow. Giant, uniquely labeled and centered 'Continue' buttons surviving layout updates offer absolutely zero resistance for measuring deep hierarchical adaptation.
  - Stale Prior Stagnation Dependency: Reject unequivocally instances where the execution log proves the agent maliciously attempted interacting with coordinates solely valid within historic platforms or previous versions currently housing empty space. This starkly signifies an absolute failure to dynamically perceive and dynamically map current real-world rendered pixels. Clicking repeatedly at X=10 where a 'Checkout' toggle formally resided—now functioning as an advertisement banner—mandates immediate sequence rejection.
  - Shortcut and Layout Contamination: Reject any scenario wherein unsupported brute-force heuristics inherently bypass the carefully structured application adaptation workflow entirely utilizing external leakage. Actively test if employing simple Search-Engine snippets external to the interface yields the target answer natively unassociated with navigating the dense UI. Providing offline answers via text retrieval destroys the core GUI-based unearthing mechanic fundamental to this benchmark constraint.
  - Platform-Action Mechanics Mismatch: Flag and reject trajectory phases demonstrating the agent blindly dispatching action syntaxes patently unsupported by the active terminal constraints. Vigorously ensure the agent obeys the explicitly constrained interactive capabilities governing the environment, such as preventing localized two-finger pinches against generic terminal webpages. Any instance dispatching a hardware 'Back Menu' native gesture onto an HTML-only browser portal registers as an irrecoverable terminal execution failure.
  - Broken Causal Chain Dynamics: Discard trajectory blocks possessing undocumented logic jumps, post-hoc inferred validations, or operations blatantly detached from properly logged antecedent optical observations. Process the sequential steps microscopically searching for actions lacking empirical reasoning foundation originating from freshly discovered interface geometry. Navigating accurately into a deeply obscured sub-setting immediately sans prior visual hints highlighting that path invalidates the continuity requirement.
