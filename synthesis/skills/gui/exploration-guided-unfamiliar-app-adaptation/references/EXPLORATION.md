# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Baseline Navigation Prior Collection: Start exploration by collecting exploration videos, prior screen traces, and transition graphs where success depends strictly on developer-specific navigational routes. Enumerate the immediately actionable regions, then note which local cues demonstrate that the app architecture differs from standard conventions. For example, discard a seed if it never forces the agent beyond relying on basic analogies from a different app, as it will not exercise true unfamiliar-app adaptation.
  - Cross-Version Delta Mapping: Systematically compare the current application layout with historical baseline screenshots to identify coordinate shifts, icon redesigns, or structural labeling updates. You must enumerate the elements that have drastically moved (e.g., from the footer up to a hidden hamburger menu) and document the newly introduced ambiguity. An edge case involves identifying when a persistent button has been entirely removed and replaced by a generic swipe gesture, forcing the agent to map a new interaction primitive.
  - Platform Divergence Auditing: Perform a systematic sweep of the interface to locate OS-specific native patterns, mapping elements between varying form factors. Record how functional nodes cluster differently across platforms, explicitly noting if 'Account Settings' live in a permanent left-hand side-menu on Desktop Web versus a nested 'Profile' bottom-tab on Mobile. A concrete example is verifying that the 'Long Press' action on a mobile client is functionally identical to a 'Right Click' interaction mapped in the desktop website.
  - Context Chaining through Exploration: Collect three or more route clues from prior exploration traces that jointly justify the target choice in the new environment. Record those clues in the precise sequence they become available, drafting one note describing the new visual paradigm and a secondary note explaining how it alters the agent's path sequence. A highly robust exploratory path might combine a relocated label, a subtle relative position shift, and a redefined prior navigation breadcrumb to successfully achieve the target.
  - Shortcut Rejection and Prior Overreliance Rehearsal: Before accepting a seed, simulate an agent strictly relying on a stale prior (e.g., clicking where the button used to be) and confirm this shortcut fails gracefully. Document the failed shortcut attempt as a negative branch to highlight the necessity of active environmental verification. For example, explicitly note if an agent clicks an identically named 'Settings' tab in the new app version that functionally leads to a completely unrelated feature set.
* **Target Trajectory Profile**:
  - Minimum Meaningful Horizon: A high-quality trajectory must contain at least 4 meaningful state-changing actions, as zero-to-one hop cases rarely expose structural unfamiliarity faults. Count solely the interactions that progressively gather new structural evidence concerning the unfamiliar hierarchy or directly advance the objective path. Paths that start and rapidly end on the identical static screen absent of acquiring topological evidence must uniformly be rejected.
  - Evidence-Rich Adaptive Transitions: The trajectory must deeply reveal why the uniquely chosen path successfully adapted to the new UI, rather than proving the agent stumbled into the correct sector luckily. Retain strictly those traces where pivotal transitions visibly supply a fundamental piece of architectural logic regarding the new layout conventions. A remarkable trace actively captures the profound turning point where a previously obfuscated control suddenly conceptually aligns with the agent's updated mental model.
  - Cross-Dimension Grounding Verifiability: The high-quality adaptation trajectory must definitively prove that the agent verified the new element's functional equivalence before committing to the terminal action. Calculate the semantic consistency between what the legacy element achieved and what the new layout element provides to ensure identical mapping. For example, a successful trace clearly highlights the agent inspecting a radically redesigned 'Submit' mechanism in Web-format, verifying its functionality, and meticulously executing via exact target center-coordinates.
  - Adaptive Error Recovery Logic: The trajectory should organically incorporate a 'self-correction' turn if the agent initially attempts to enact a stale visual or platform prior resulting in a dead-end mismatch. Meticulously document the internal reflection juncture wherein the agent recognizes the button has migrated, forcing a fresh visual sweep. A concrete case showcases an agent failing to utilize a legacy 'Legacy Mode Login' pathway, perceiving its absence, and adaptively migrating entirely to the new 'SSO Authentication' flow.
  - Stable Termination Anchor: The trajectory must intrinsically possess a razor-sharp concluding condition perfectly tied to the execution of the functional goal transferred from the prior trace. Extensively outline the very first internal state or screen at which the target feature is unquestionably reached and resolved. If the objective is technically accomplished but the agent sporadically continues migrating through irrelevant mobile tabs, the trajectory is deemed noisy and isolated for rejection.
