# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Hostile Interference Audit. Systematically scan the screen for non-native UI elements like pop-up advertisements, newsletter sign-ups, or cookie consent banners that partially or fully obscure interactive zones. You must document the bounding box of these overlays and search for a corresponding 'Dismiss', 'Close', or 'Decline' node to clear the path for the primary objective. For example, if a 'Live Chat' bubble covers the submit button, prioritize a 'Minimize' action on the chat widget first to reveal the underlying target.
  - Pre-filled State Conflict Inspection. Prior to entering high-stakes text strings, you must perform a dedicated check of the input field's current buffer to detect pre-populated or stale text leftovers. Record whether a field contains placeholder ghosts or physical characters like '#' or default user IDs which might cause character-level corruption during typing. A concrete case is noticing a search box has 'Last Search' text still present, necessitating a select-all and delete sequence to ensures a clean input environment.
  - Widget Initialization Verification. Execute test interactions on complex widgets like date-pickers, sliders, and canvases to identify their internal state machines and formatting requirements. You should document how the widget reacts to different input formats—such as 'YYYY-MM-DD' versus 'MM/DD/YYYY'—by observing the immediate success or failure signals in the local pixels. For instance, input a year-first date and monitor if the cursor jumps back to the start, which indicates a format mismatch requiring a strategy pivot.
  - App-State Delta Comparison. Compare the screenshot after an interaction with the intended state to identify cases where the app did not respond or 'ignored' the command due to hidden blockers. You should look for invisible loading progress bars or disabled state attributes in the metadata that explain a 'No-Op' result from a valid click. A successful strategy involves clicking 'Save' and then verifying if a success toast appears; if not, you must sweep for an un-filled 'Required' field that is preventing the transition.
  - Visual Outcome Fidelity Check. Perform a holistic pixel-level comparison between the 'Ready' state and the environment following a critical terminal action to confirm the visual essence of the goal matches the screen. You should specifically check for attributes like color shifts (light to dark mode), coordinate changes (dragging a file), or text updates that prove success. For example, if a user wants to 'Hide comments', you must verify the comment container has disappeared rather than just a 'Hide' button being clicked without a result.
* **Target Trajectory Profile**:
  - Obstacle-Aware Progression Trace. A high-quality trajectory must clearly document the detection and removal of an environmental obstacle, such as a pop-up or modal, before the primary goal is attempted. You should count the 'Dismiss' action as a valid, context-aware turn that demonstrates environmental mastery rather than a distraction. A valid trace records: 'I see a pop-up blocking the menu; I will close it now' followed by the successful menu interaction in the subsequent step.
  - Sanitized Input Accuracy. The trajectory must showcase the agent clearing or overwriting pre-populated text in a field to ensure the final input matches the user's intent with 100% character fidelity. You should verify that the 'Action Log' captures the backspace or 'Select All' event specifically when pollution is present. A gold sample shows the agent observing '#' in a color box and removing it before typing the requested hex code, preventing an 'invalid format' error.
  - Corrective Format Resilience. For tasks involving specific data formats (like dates or currency), the trajectory should record the agent's transition from a failing format to a successful one based on on-screen feedback. You must provide evidence that the agent identified a format hint—such as a tooltip or placeholder—after its first attempt failed. Success is defined by the final observation where the widget state is verified as 'Accepted' following the format correction.
  - Persistent Success Verification. The trajectory must conclude with an explicit 'Verification Turn' where the agent identifies the visual anchor of completion (e.g., a green checkmark, a dark theme, or the presence of a new file). You should ensure the final step is a grounded observation that reconciles the result with the original prompt. For instance, the final step says 'I can see the Portuguese text in the header, confirming the language change' rather than just a generic 'Task finished'.
