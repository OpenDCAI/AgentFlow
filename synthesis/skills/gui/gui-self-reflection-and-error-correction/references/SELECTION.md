# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Sanitization-to-Success Correlation. Accept only trajectories where the clearing of a pre-filled field was causally necessary to avoid an incorrect final string in the application. You must perform a character-count audit to confirm that the agent's input, if appended to the existing text, would have failed the task. For example, a trace that clears '#' before typing '#FFEE00' is accepted, while one that types '#FFEE00' on top of a '#' is rejected for sloppiness.
  - Overlay Dismissal Efficacy. Accept unique instances where the dismissal of a pop-up or modal was the primary reason a previously obscured target became interactable. You should cross-check the bounding box metadata of the pop-up at Step N against the target widget's visibility at Step N+1. A valid case demonstrates that the target button was 0% visible before the dismissal and 100% visible after, proving safety-aware governance.
  - Format-Sensitive Grounding Precision. Accept trajectories where the agent correctly identifies a widget's format requirements (e.g., MM/DD/YYYY) through exploration of the interface's grey placeholder text or error messages. You must verify that the agent's thought process explicitly mentions the format hint located on the screen. An acceptable trace shows the agent observing 'YYYY/MM/DD' and immediately adjusting its typing plan to match this local constraint.
  - Durable UI State Verification. Accept only those traces where the final step includes a grounded observation of a persistent UI change that is not a transient toast or loading icon. You should verify that the visual change (e.g., the screen is now black for dark mode) is visible in the final terminal screenshot. A successful trace will identify a specific UI landmark that proves success, such as the 'Language: Portuguese' label being rendered in the footer.
  - Error-Correction Recovery Logic. Accept cases where the agent recovers from its own misclick or a minor system lag by re-verifying the state and re-executing the action. You should conduct a turn-by-turn audit to ensure every corrective action followed a visible failure (e.g., clicking a button that didn't respond). For example, if a click on 'Save' didn't trigger a change, a valid trace shows the agent clicking it again after a brief 'Wait' turn.
* **Rejection Criteria**:
  - Input Buffer Pollution Failure. Reject any trajectory where the agent's final action resulted in corrupted data due to ignoring pre-existing text in a field (e.g., resulting in '##EDC55E'). This indicates a failure of self-reflection and state-awareness during the execution phase. If the final screenshot shows the input box containing a messy, doubled-up string, the seed must be discarded for lack of precision.
  - Overlay-Induced Hallucination. Reject traces where the agent claims it clicked a button that was clearly obscured by a pop-up or system modal in the current screenshot. You must perform a visibility check on the target coordinate to ensure it was not covered by a 'High-Z' index element. If the agent 'clicks through' a modal to a hidden button without closing the modal first, the trajectory is a grounding hallucination.
  - Blind Template Continuation. Reject cases where the agent continues its pre-planned sequence (e.g., following a tutorial) after the website has crashed or returned to the home screen. The agent must show 'Perception Drift' detection by acknowledging the sudden disappearance of the task environment. Any trace that clicks 'Next' on a blank desktop or a generic Google home page following an app crash is invalid.
  - Format-Ignoring Redundancy. Reject trajectories where the agent repeatedly inputs a date or value in a failing format despite a visible error message on the screen indicating a specific alternative is required. This 'Looping-Trap' demonstrates a lack of reflection on environmental feedback. For example, if the UI says 'Use MM/DD' and the agent types 'DD/MM' three times, the seed is an irrecoverable planning failure.
  - Superficial Success Hacking. Reject any trajectory where the agent claims the task is 'done' because it clicked a final button, but the screen pixels do not show the intended change. You must perform a comparison verify the 'Visual Essence' of the goal was achieved. Claming 'Language changed' when the text is still in English is a terminal failure of outcome verification and must be removed from the synthesis pool.
