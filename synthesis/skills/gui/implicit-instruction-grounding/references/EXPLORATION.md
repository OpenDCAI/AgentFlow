# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Semantic Instruction Variation Probing: For every identified widget, do not simply record the literal label as the command. You must generate a 'Semantic Cluster' of at least 5 instructions using diverse language, such as replacing 'Checkout' with 'Pay now,' 'Finalize my order,' or 'Complete the purchase' to test the unification capability. A concrete example involves checking if a 'Home' icon correctly reacts to phrases like 'Return to dashboard' or 'Go back to the start' in a multi-app environment.
  - State-Level Multi-Goal Discrimination: Identify states where the agent is presented with multiple valid functional widgets, such as 'Filter', 'Sort', and 'Search' icons appearing in the same header. You should generate separate trajectories for each intent within the same screenshot to verify the agent's ability to discriminate instructions among neighboring targets. For instance, in a shopping app, the agent must prove it can accurately hit 'Sort' when asked for price ordering and 'Filter' when asked for category refinement without mis-clicking.
  - Action Topology Dependency Scoping: Systematically audit for 'state-gated' elements that require a precursor action, such as a 'Submit' button that only activates after a 'Terms' checkbox is ticked. You must record the visual signal of the blocker and the successful sequence required to satisfy the environment's internal logic. For example, if adding a product to a cart, log the requirement to select a 'Size' first, ensuring the skill captures the topological relationship between widgets.
  - Visual Similarity Pairwise Auditing: Locate instances where the UI uses visually redundant icons for different functional roles, such as multiple identical 'Add' buttons in a product list. You must document the surrounding parent-child hierarchy or sibling text nodes that distinguish these buttons from one another. A concrete case is a grid where 'Add' buttons exist for both 'Shirt' and 'Pants'; the trajectory must show the agent using the adjacent vertical label to anchor the correct button.
  - Layman Context to Symbol Mapping: Perform a sweep of symbol-only buttons and assign multiple natural-language intents to them based on their context. You should verify how the agent maps a 'Gear' icon to 'Change my password' or 'Check version' when no text is present. For example, record the mapping of a 'Message bubble' icon to 'Contact support' versus 'View chat' to ensure instructions remain robust across different app domains.
  - Instruction-to-State Conflict Probing: Intentionally craft instructions that are slightly misaligned with the current screen state (e.g., asking to 'Delete' when the button is labeled 'Remove') to measure the agent's reliance on semantic logic over literal overlap. You must record the successful resolution where the agent chooses the semantically closest widget despite the lexical gap. An edge case involves the agent correctly ignoring a 'Trap' button that matches the user's word but fails the functional requirement, such as a 'Settings' icon that only leads to 'Display' when the user wants 'Account'.
* **Target Trajectory Profile**:
  - State-Level Mastery Horizon: A high-quality trajectory must demonstrate the agent's ability to handle at least 3 distinct tasks originated from the same starting screen state. You should verify that for each different instruction (e.g., Filter vs Sort), the agent's first step targets the correct unique widget without hesitation. A failure would be any trace that clicks the same 'prominent' icon regardless of the differing task descriptions.
  - Non-Literal Mapping Success: The trace must definitively show the agent clicking a button whose label does not appear in the user's question, proving semantic unification. You must document the internal reasoning where the agent connects the user's casual word (e.g., 'Reset') to the GUI's technical label (e.g., 'Clear All'). For instance, a gold trace should show 'Instruction: Start over; Action: Click Clear All' with a thought block justifying the functional mapping.
  - Topological Prerequisite Fulfillment: The trajectory should record the agent identifying a dependent terminal action and navigating to the necessary pre-condition widgets first. You must verify that the agent interacted with the 'Parameter' widget (like Size or Color) before attempting to click the 'Action' widget (like Add to Cart). A successful trace documents: 'The Add button is likely blocked until I pick a size; selecting Large first' as the core logic.
  - Sibling-Text Grounding Trace: For environments with repetitive widgets, the trajectory must capture the agent's visual audit of the surrounding sibling elements (headers, names, or prices). You must provide evidence that the agent's click coordinate was uniquely chosen because it shared a parent container with the semantic identifier mentioned in the prompt. A trace for 'Delete item B' must show the agent scanning Item B's label before clicking the adjacent Delete key.
  - Refusal of Plausible Mismatches: The trajectory should show the agent identifying 'Distractor' widgets that match the word in the instruction but fail the logic of the current GUI state. You must record the agent's internal dismissal of a visually salient but incorrect button in favor of the truly functional target. For example, an agent looking for 'Account help' should explicitly ignore a prominent 'Help' icon if it only leads to 'App version' info.
