# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Instruction-Widget Semantic Convergence: Accept trajectories only if the agent successfully maps at least three semantically divergent instructions to the same unified widget (UWIU). You should verify that the internal reasoning block correctly identified phrases like 'Reset' and 'Start over' as functional equivalents for the 'Clear All' button. For example, the trajectory is valid if it succeeds despite the instruction intentionally avoiding the words used in the on-screen labels.
  - Multidimensional Discrimination Fidelity: Accept cases where the agent correctly isolated the target widget from a dense cluster of semantically similar 'Neighbor' icons (MWAM). You must check that the click coordinates fall perfectly within the bounding box of the 'Sort' icon when the instruction was price-related, while 'Filter' icons remained unclicked. An acceptable trace shows zero coordinate jitter between instructions, hitting the exact pixel center for each distinct task.
  - Structural Sibling Grounding Accuracy: Accept only those traces where the choice of a duplicate button (e.g., 'Add' in a list) is explicitly justified by identifying a unique sibling text node (e.g., a product name). You should cross-check the action log to ensure the agent's 'Thinking' phase mentioned the adjacent identifier before executing the click. For instance, in a pizza menu, the agent must state 'Selecting Add specifically for Margherita' to avoid the trivial 'lucky click' rejection.
  - Topological Sequence Verification: Accept trajectories where the agent correctly recognized and satisfied a widget's prerequisite state (e.g., selecting a size before clicking Add). You should perform a state-delta audit to prove that the agent interacted with the mandatory pre-condition widget prior to the terminal action. A valid case shows the agent observing a 'Size required' prompt and adaptively correcting its plan to select the parameter first.
  - Intent-Specific Grounding Precision: Accept only trajectories where the agent's click on a symbolic icon (without text) is preceded by a thought block explaining why that icon fits the user's intent. You must verify that the agent's 'World Model' of icons (e.g., bell = notifications) aligns with the specific application domain used in the task. For example, if a 'Heart' means 'Save' in this app, the agent must explicitly state this before clicking for a 'Save for later' task.
* **Rejection Criteria**:
  - Lexical Overlap Bias Trap: Reject any trajectory where the agent only succeeds when the instruction contains a direct word-for-word match with the UI label. This indicates a failure of semantic unification and suggests the agent is a simple string matcher. For example, if the agent clicks 'Clear All' when told 'Clear all,' but fails when told 'Wipe my filters,' the seed is rejected.
  - Neighbor-Icon Mis-mapping: Reject traces where the agent clicks a widget that is visually or semantically similar to the target but does not fulfill the specific sub-instruction (e.g., clicking 'Filter' instead of 'Sort'). This is a terminal failure of action discrimination (MWAM) in a state-level mastery test. If the user asks for 'High to Low price' and the agent clicks the generic 'Search' bar instead of the 'Sort' button, the case is discarded.
  - State-Agnostic Blind Execution: Reject cases where the agent attempts to interact with a widget without checking if its pre-conditions are met, leading to an avoidable error popup or no-op. The agent must show proactive environment auditing to satisfy the topology of the interaction. For instance, clicking 'Confirm' on a blank form instead of filling the required 'Name' field first is a failure of state-verified competency.
  - Semantic Hallucination Divergence: Reject trajectories where the agent's internal thought process claims a widget does one thing (e.g., 'This opens home') while the actual GUI action leads elsewhere (e.g., 'Opens settings'). You must verify that the agent's understanding of the widget's function is semantically consistent with the GUI metadata. If the agent misidentifies a 'Pencil' icon as a 'Trash' icon, the seed is irrecoverably broken.
  - Single-Hop Triviality Shortcut: Reject any trace where the target is so visually dominant (e.g., the only button on screen) that no implicit grounding or semantic resolution was actually required. You should ensure the environment contains at least two functional competitors to ensure the task measures 'Mastery' rather than 'Lucky Guessing'. For example, if there is only one icon on the whole screen, the task is too shallow for this skill.
