# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Containment-to-Accuracy Scoring (Composite Score): Accept only trajectories where the 'Composite Score'—the product of the ROI containment rate and the conditional grounding accuracy—exceeds a 70% threshold. You must verify that the ROI deduction phase (Stage 1) successfully enclosed the target element *and* the grounding phase (Stage 2) hit the coordinates. For example, a trace that identifies the correct region but misses the click by 10 pixels is a failure and must be discarded.
  - Euclidean Stability Verification: Accept only traces that achieve a 'Stable Cluster' termination where the final several predictions are geographically consistent within a 50-pixel radius. You should check the coordinate history in the action log to ensure the agent didn't finish while its predictions were still 'jittering' or oscillating between two elements. A valid case demonstrates that the refinement process successfully converged on a single, reproducible coordinate.
  - Asymmetric Pruning Logic Validity: Accept trajectories that utilize asymmetric cropping to focus on the target while preserving local context as per Algorithm 2. You must verify in the action logs that the boundaries were shifted inward significantly more on the side farthest from the target signal. For example, if the target p is on the left, the agent should have aggressively pruned the right-hand side of the previous bounding box.
  - Upscaling-Driven Precision Check: Accept only cases where the final grounding action was performed on an upscaled image (e.g., 3x scaling) and the resulting coordinate remains correct when mapped back to the original full-screen resolution. You must perform a coordinate translation back-check to ensure no mathematical drift occurred during the scaling process. A successful trace shows perfect pixel alignment between the upscaled target and the original-screen's bounding box.
  - App-Context Reasoning Consistency: Accept only those instances where the grounding model's choice is explicitly justified by identifying the application (e.g., 'In Figma, this icon signifies Share'). You must ensure the agent's internal reasoning block mentions the application context or visual traits like 'blue button color' or 'border shape' to avoid 'lucky clicking'. A failure to provide this semantic link results in the trajectory being treated as unverified.
* **Rejection Criteria**:
  - Attentional Fixation Loop: Reject any trajectory where the agent performs redundant, high-confidence clicks on a salient distractor while ignoring relevant user instructions or visual cues that contradict the choice. This indicates that the search policy has become 'stuck' on an incorrect visual prior. For example, if the agent repeatedly clicks a 'three-dots menu' for settings when a 'gear icon' is clearly visible and closer to the goal, the trace is a failure.
  - Deterministic Training Bias (Gear vs Dots): Reject traces where the agent's internal reasoning shows it is selecting an element based on a 'generic habit' rather than the current visual reality (e.g., picking a three-dots menu because it usually means settings in other apps). You must check for 'Prior overriding Perception' where the agent ignores a clear label or specific instruction. If the user asked for the 'Round' button and the agent clicks the 'Square' one because it's the usual location, discard the seed.
  - Instructional Over-Correction Failure: Reject cases where a 'Rewrite Agent' produced an instruction that was so specific it caused the grounding agent to over-focus on the wrong detail (e.g., looking for a label that doesn't exist). You must ensure the final instruction used for grounding did not introduce hallucinations that caused the agent to miss the visual target. For example, if the rewrite says 'Click the Save button' but the button only has a floppy icon, the resulting miss is a terminal failure.
  - Search Horizon Exhaustion (Emax Override): Reject any trajectory where the agent reaches the 'Error Threshold' (Emax) and performs a 'Forced Zoom-In' that clips the target element. This indicates a breakdown in the bidirectional search logic where the error recovery was insufficient to re-center the ROI. If the target is visible in step 2 but clipped in step 4 due to successive out-of-bounds predictions, the trajectory is a ground-truth failure.
  - Single-Shot Grounding Hallucination: Reject sequences that achieve success by 'guessing' the coordinates on a high-resolution 4K screen without any ROI refinement or zoom stages. This violates the 'multi-stage' requirement of the skill and fails to provide data for the adaptive refinement capability. A 4K task must show the agent actively zooming to be considered a valid demonstration of fine-grained widget grounding.
