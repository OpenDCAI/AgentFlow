# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Asymmetric ROI Deduction Strategy: Instead of symmetric cropping, adopt a targeted pruning approach that removes the screen region farthest from the initial grounding signal. You must calculate the distances from the predicted coordinate p to all four ROI boundaries and contract the boundary with the largest distance by a defined reduction factor (e.g., 10%). This ensures the search space is refined while preserving as much surrounding context as possible near the predicted target. For example, if p is in the far right of the screen, aggressively prune the left 20% of the canvas to reduce visual clutter.
  - Bidirectional Recovery Probing: Incorporate a 'Zoom-Out' or 'Re-centering' policy to handle cases where the grounding head produces an out-of-bounds prediction. You must monitor if the predicted coordinate p falls outside the current ROI and, if so, trigger a uniform expansion of the boundaries (e.g., 5% outward) to restore a broader view. This recovery mechanism prevents the agent from becoming permanently 'stuck' in a wrong sub-region, as seen when a model fixates on a distractor that looks like the target. For instance, if the agent thinks the 'Save' button is just off the top edge, expanding the ROI upwards allows for re-localization.
  - Stable Cluster Convergence Polling: Maintain a sliding window of the last several in-bounds predictions to identify when the visual search has stabilized on a target. You must verify that at least three consecutive predictions fall within a tight Euclidean distance threshold (e.g., 50 pixels) before terminating the ROI deduction phase. This prevents redundant zoom-in steps when the model already demonstrates high confidence and spatial consistency. An example occurs when three consecutive crops all center on the same 'Wrench' icon, signaling it is time to transition to fine-grained clicking.
  - Contextual Application-Context Extraction: Prior to final grounding, perform a holistic scan of the ROI or the header region to identify the active application identity. You must explicitly look for window titles or branding cues (e.g., 'Figma', 'Chrome', 'Salesforce') to ground the semantic meaning of ambiguous icons. For example, identifying the app as 'Figma' allows the agent to correctly treat a 'blue box' as the 'Share' button rather than a generic graphic, boosting accuracy through semantic alignment.
  - Adaptive Visual Scaling Calibration: Implement a 'Scale Agent' that upscales the final ROI crop to a higher resolution (e.g., 3x bicubic interpolation) before dispatching the final click action. You must determine the optimal magnification factor based on the target element's size relative to the ROI to ensure fine-grained features like icon borders or text labels are distinct. A concrete case is upscaling a tiny 12px checkbox to 36px, which significantly reduces coordinate jitter and improves grounding head performance.
  - Sequential State-Delta Logging: For every crop or zoom interaction, document the visual change in informational density and target relative positioning to build a 'Decision Path' for synthesis. You should record if a zoom-in successfully removed distractors or if it caused the target to be partially clipped, requiring a repositioning step. For instance, log the moment the '针头' (needle) target first becomes distinguishable from background noise after the second ROI contraction.
* **Target Trajectory Profile**:
  - Scale-Aware Multistage Horizon: A high-quality trajectory must contain at least 2 distinct ROI refinement stages before the final grounding action to prove the agent overcame spatial dilution. You should count the transitions from full-screen to intermediate-ROI to final-grounding-crop as the core evidence of multi-stage reasoning. A path that succeeds in a single hop on a 4K screen is likely a 'lucky click' and should be evaluated for lower quality compared to a structured search.
  - Unidirectional Continuity with Error Tolerance: The trace should predominantly show the search space narrowing, but must allow for 'Zoom-Out' events if they result in superior final target containment. You must verify that every outward expansion was causally triggered by a prediction that was previously ambiguous or out-of-bounds. For example, a gold trace might show [Full Screen -> ROI A -> Out-of-bounds -> ROI B -> Target], demonstrating robust error recovery through bidirectional logic.
  - High-Density Grounding Fidelity: The final step in the trajectory must demonstrate a 'near-zero' Euclidean offset between the predicted coordinate and the geometric center of the target widget. You must verify the grounding accuracy on an upscaled image to confirm the agent hit the intended pixel cluster rather than an adjacent distractor. A successful trace on a tiny icon cluster should show the cursor hit perfectly between the 'Archive' and 'Flag' boundaries, directly on 'Pin'.
  - Functional-Semantic Alignment Trace: The trajectory logs must include the internal thought process where the agent identifies the 'App Context' and its influence on the element description. You should verify that if the agent identifies 'Figma', it subsequently describes the target using Figma-specific terminology in its internal reasoning. For instance, the log should state 'App identified as Figma; target is likely the primary blue share button' prior to the ROI deduction action.
  - Deterministic Termination State: The trajectory must end with a crisp success signal where the final coordinate physically overlaps with the ground-truth bounding box in the environment metadata. You should identify the specific terminal screen (e.g., a resulting dialog or a state-change toggle) that proves the precise widget was successfully triggered. A trajectory that clicks and then waits without a verifiable state change should be rejected as a potential grounding failure.
