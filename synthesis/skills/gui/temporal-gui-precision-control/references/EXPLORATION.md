# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Temporal Anchor Identification: Scan the user interface for explicit timers, countdowns, progress bars, or textual 'Wait' instructions to establish the required interaction window. You must explicitly log the start and end values of any detected clock-based widget in your observations to calculate the necessary synchronization delay. For example, if a message says 'Please wait 5 seconds,' record the current timestamp to determine exactly when the next valid action can be taken.
  - Duration Probing Actions: Perform intentional 'Hold' or 'Long Press' sequences on buttons, toggles, and interactive canvas regions to determine if the GUI outcome is dependent on persistent state. You should record the visual differences or server responses between a simple tap and a 5-second hold to map duration-sensitive affordances. A concrete example is holding a 'Submit' button for 3 seconds to see if a hidden 'Advanced Mode' menu appears in the UI tree.
  - State-Stability Monitoring: Observe the environment during intervals where no agent input is provided to identify content that only appears after a period of environmental inactivity. You must log the exact moment a previously invisible artifact, such as a password or a session token, renders on the screen without a triggered event. For instance, remain on a 'Loading' screen for 10 seconds and document if a secret code replaces a 'Waiting' spinner, which signifies a patience-based seed.
  - Frequency Calibration Probing: Test the UI's response to high-speed repetitive actions by executing rapid-fire clicks or sequence-based keyboard inputs to find the threshold for 'Fast Action' success. You should attempt to click a single element 3-5 times in quick succession and note if the system counts them as separate events or a single combined action. A concrete case is clicking an 'Unlock' star three times in under one second to see if it triggers an 'Achievement' password.
  - Reactive Coordinate Tracking: For moving targets or dynamic layouts, sample the target's screen position at multiple high-frequency intervals to estimate its velocity and future trajectory. You must document the coordinate shifts over time to build a motor-control plan that accounts for the latency between the agent's decision and the physical click execution. For example, if a circle moves 10 pixels per frame, pre-aim your click at a point where the circle will be in the next 100 milliseconds.
* **Target Trajectory Profile**:
  - Verified Temporal Sequence: A high-quality trajectory must show a clear 'Wait' or 'Duration' event that causally precedes the final successful state transition. You should document the screen state during the delay to prove that the agent was monitoring the clock rather than just pausing randomly. For example, the path should record 'Timer at 3s,' 'Timer at 1s,' and then the 'Reveal' state to validate temporal adherence.
  - Duration-Grounded Success: The trajectory must demonstrate that the final answer was only accessible because the agent maintained a specific physical interaction state for the required amount of time. You must capture the 'MouseDown' and 'MouseUp' timestamps in the action log to verify the hold duration matches the task's constraints. For instance, a file must be successfully 'Unlocked' only after a recorded 3000ms hold, otherwise the seed is discarded.
  - Dynamic Target Interception: For moving targets, the trace must record the target's coordinates at the exact moment the click was initiated to prove precise reactive coordination. You should ensure the log shows the intersection of the cursor's target pixel and the moving object's bounding box. A valid trace would show the bullseye moving at X=100 and the agent clicking X=100 simultaneously, demonstrating pixel-perfect timing.
  - Frequency-Dependent Completion: If the task requires rapid repetition, the trajectory must show a burst of actions with sub-second intervals that the system identifies as a single successful fulfillment. You should count the number of 'Action' events in a single step-block and verify they meet the frequency requirements of the environment. For example, a trace showing three distinct clicks in a 500ms window proves the agent overcame the temporal bottleneck.
