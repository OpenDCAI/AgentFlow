# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Causal Timing Link: Accept only trajectories where the goal achievement is a direct and logical result of the timing-based action, such as a password appearing only after a wait. You should verify that the target data did not exist in any screenshot taken prior to the completion of the temporal condition. For example, if a password is found via search instead of waiting for the reveal, the trajectory does not test temporal coordination and must be rejected.
  - Precision Threshold Adherence: Accept cases where the agent's action occurred within a verifiable margin of error relative to the required GUI timer or target velocity. You must check that the 'Action Delay' or 'Click Position' falls within the software's designated tolerance window (e.g., +/- 100ms). A concrete example is accepting a click on a moving target only if it hits the center 50% of the object while it is in motion.
  - Stable Dynamic Verification: Accept only traces that contain a 'Milestone' observation during the waiting or holding phase, such as a timer reaching zero or a progress bar completing. This proves the agent correctly responded to the environmental clock rather than getting lucky with a random delay. For example, accept a 'Bullseye' task if the UI tree records a 'Hit Count: 3' after the precision interaction.
  - Duration Verifiability: Accept only trajectories where the 'MouseDown' and 'MouseUp' actions are recorded as a single persistent state in the environment's action metadata. You should verify that the environment recognized the 'Hold' rather than interpreting it as two separate clicks. A valid case should show a continuous duration attribute in the action record, confirming the agent maintained the required physical state.
* **Rejection Criteria**:
  - Static Logic Bypass: Reject any trajectory where the agent reaches the goal using a static navigation shortcut that ignores the intended temporal challenge. If the password could be found in the page's source code or meta-tags without waiting, the case is too shallow for this skill. For example, clicking an 'Instant Reveal' button that bypasses the '3-second wait' removes the temporal reasoning burden and must be discarded.
  - Premature Termination: Reject traces where the agent stops its action or ends the 'Wait' session before the environmental clock has reached the success state. You must ensure the agent did not 'finish' while the timer was still counting down or while the button was still being held. For instance, a 2.5-second hold for a 3-second task is a failure in precision and cannot be used as a gold seed.
  - Temporal Hallucination: Reject cases where the agent claims to have 'waited' or 'held' but the action logs show instantaneous clicks or no meaningful delay. You must perform a timestamp audit to ensure the delta between actions corresponds to the claims made in the reasoning block. If the agent says 'I waited 10 seconds' but only 1 second passed between logs, the trajectory is a hallucination and is rejected.
  - Uncalibrated Reactive Failure: Reject trajectories where the agent attempts to click a moving target but misses significantly or fails to account for object velocity. This indicates a failure in visual-motor synchronization that does not provide a high-quality example of successful precision control. For example, clicking where the Bullseye *was* instead of where it *is* results in a 'miss' that cannot support synthesis of success data.
