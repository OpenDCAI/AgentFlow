# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Set Boundary and Sentinel Identification: Systematically scan the interface to find the physical limits of the data set, such as identifying the 'Total Items' label, the final page number in a pager, or the 'End of List' message. You must record these sentinel values as anchor points for the iteration loop to prevent infinite scrolling or premature termination. For example, if a table says '1-10 of 226', the agent must calculate that at least 23 pages of navigation are required.
  - State-Delta Iteration Probing: Perform a single test interaction (e.g., clicking 'Next' or expanding a node) to document the visual changes that indicate a successful progress shift. You should record the specific UI delta, such as a changing page number or a newly revealed sub-item, to build a 'Success Verification' signal for each iteration step. A concrete case is verifying that the first row's ID changes after clicking 'Next', proving that the table has successfully transitioned to new data.
  - Bidirectional Scroll Calibration: Probe the scrolling behavior of the list or document to identify if items can be missed due to 'Scrolling Down Bias' or layout occlusion. You must execute both upward and downward scroll actions to verify the full range of visible items and find the 'Scroll Home' position. For instance, scroll to the absolute bottom of an infinite list to trigger all lazy-loading events, then return to the top to establish a clean starting vector for extraction.
  - Iterative Variable Extraction Mapping: Identify the specific data fields in a single row or card and map them to their corresponding coordinate-based extraction paths. You should record if the data is a static text label or a link that requires an additional click to reveal detailed info. An example is documenting that a customer name is at X=100 in every row, allowing the agent to generate a consistent motor plan for bulk collection.
* **Target Trajectory Profile**:
  - Set-Integrity Progress Log: A high-quality trajectory must maintain a 'processed set' in memory, providing a turn-by-turn log of which items have been handled. You should verify that the agent explicitly mentions the current index or item ID during each step of the loop. For example, the trace should record 'Processing row 12 of 50' to demonstrate that the agent is tracking its completion rate against the total set boundary.
  - Clean Loop Termination: The trajectory must conclude with an explicit verification that the 'End of Set' sentinel has been reached, such as a disabled 'Next' button or a search returning 'No Results'. You must provide a final screenshot or XML check showing that no relevant items remain in the interface. A valid trace stops immediately after processing the last item, avoiding redundant blank clicks or unnecessary UI sweeps.
  - Handling Unexpected Interjections: The trace should document how the agent recovers its 'Iteration State' if a system popup or app crash resets the view midway through a loop. You must show the agent re-navigating to the last known 'unprocessed' item rather than starting from zero or skipping to the end. For instance, if the app crashes at item 15, the recovery trace must show the agent scrolling back to item 16 to resume the task.
  - Consistent Motor-Action Density: For bulk tasks, the trajectory should exhibit a high density of purposeful interactions with minimal navigation overhead between items. You should optimize the path to move directly between repetitive targets once the UI pattern is grounded. A gold sample shows the agent executing 'Click-Type-Save' for each row with pixel-perfect consistency, proving it has mastered the repetitive interface pattern.
