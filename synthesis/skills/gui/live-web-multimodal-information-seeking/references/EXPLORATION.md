# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Stateful DOM Hierarchy Mapping: Systematically explore the application to mapped out how deeply embedded information (like HS codes or ECCNs) is distributed across dynamically loaded tabs or modal dialogs. You must record the DOM index triggers and the subsequent screen states to identify the exact interaction sequence required to reveal hidden data nodes. For instance, determine if clicking an 'Export Info' label renders new HTML content or merely shifts visual focus within the existing viewport.
  - Event-Driven Metadata Auditing: Prioritize the identification of interactive elements that trigger high-fidelity information retrieval, such as 'Download Data', 'View More Details', or 'Expand Section' widgets. You should perform test clicks to verify if the server-side response yields the terminal factual answer or requires further navigation hops. A concrete example involves checking if a 'Merchant License' is a static text field or an interactive link that opens a separate verified PDF registry.
  - Context-Management Continuity Sweeping: When navigating between search engines and target merchant portals, the agent must verify the persistence of the session context (e.g., query parameters, filters). You should explicitly document the 'History' of transitions to ensure that information extracted from Step 1 (like a Part ID) is correctly carried over and grounded in Step 5. An edge case involves identifying if a website clears its search filter when a user switches between 'Product' and 'Compliance' view tabs, requiring a re-entry action.
  - High-Fidelity Browser Use Integration: Utilize advanced browser context management to identify the relationship between rendered pixel coordinates and structured DOM elements for improved extraction accuracy. You must record the 'Thinking-Action-Observation' loop metadata, noting where traditional scraping failed to capture dynamically loaded e-commerce attributes. For example, logging that a price only appears after the browser executes an AJAX-based 'shipping calculation' event triggered by an interactable dropdown.
  - Cross-Site Trust Boundary Identification: Explore the navigational relationship between a merchant landing page and its official registration artifacts (WHOIS, SSL, Business Registry). You must record the coordinate paths for certificate viewers and footer-based registries to enable automated identity verification workflows. An example is documenting the exact steps to open the SSL certificate details panel from the browser's address bar icon to verify the issuing CA and organization name.
* **Target Trajectory Profile**:
  - Deep-Extraction Procedural Integrity: A high-quality trajectory must demonstrate the agent navigating through at least two levels of sub-pages or interactive tabs before achieving the final extraction. You should count only those actions that reveal new, relevant data clusters associated with the target entity (e.g., Part Number -> Specs -> Compliance Tab). A trace that retrieves information directly from a search engine snippet is prohibited, as it fails to test deeply embedded data retrieval.
  - State-Stable Semantic Mapping: The trajectory must record the precise extracted text string being mapped to its on-screen functional label (e.g., Mapping 'EAR99' to 'ECCN'). You must verify that the character-level attributes of the final answer match the pixels rendered on the terminal screen node. A valid trace shows the agent observing the label 'Clearance Date' and successfully extracting the adjacent date string without hallucinating format changes.
  - Stateful Interaction Continuity: For multi-step information seeking, the trace must show the agent maintaining the target intent (e.g., 'ECCN find') despite being redirected to landing pages or verification prompts. You should document the 'Memory' step where the agent recalls the target ID after a significant environment shift. A gold sample trace record the 'Part Number' at step 1 and the final 'Classification' extraction at step 12 across different domain URLs.
  - Deterministic Success Verification: The trajectory must terminate with an explicit observation of the final factual answer appearing in the viewport, accompanied by a 'done' command containing the extracted data. You must identify the specific coordinate or DOM index that provided the authoritative evidence. For example, a successful search for an HS code ends by pinpointing the exact cell in the customs table where the code is displayed.
  - Optimal Multi-Action Turn Chaining: High-quality trajectories should utilize the 'multi-action' capability (e.g., input text and click in one turn) to optimize the interaction horizon for deeply buried data. You should calculate the efficiency ratio and ensure the agent isn't performing redundant 'Verify' or 'Wait' turns unless mandated by server latency. A successful trace navigates directly to the 'Compliance' tab post-search in a single efficient hop.
