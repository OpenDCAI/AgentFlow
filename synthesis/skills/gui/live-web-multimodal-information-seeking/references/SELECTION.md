# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Stepwise Accuracy F1 Threshold: Accept a trajectory only if every individual tool call in the action list achieves an F1 score of at least 0.5 with the ground truth interaction. You must verify that the index selection for elements like 'Expand Specifications' is mathematically accurate within the DOM tree. For example, if the agent clicks the 'Next' button instead of the 'Details' tab, the trajectory must be rejected despite achieving a partial state transition.
  - Deep-Embedded Data Fulfillment: Accept only those instances where the final answer was previously invisible or 'Dynamically Loaded' and required a physical interaction to render. You should conduct a pixel-check on the initial screenshot to prove that the answer was not already available on the homepage or search snippet. An acceptable case is one where the HS code only appeared after 'Click to Expand' was executed by the agent.
  - Thinking-Memory Format Alignment: Accept trajectories exclusively follow the R1-style output format: 'Thinking -> Evaluation -> Memory -> Next Goal -> Action'. You must verify that the 'Thinking' block describes the semantic search logic and the 'Memory' block stores the extracted variables from previous steps. A trace that lacks a clear 'Evaluation' of the previous goal's success should be discarded for lack of process awareness.
  - Verified State Transition Convergence: Accept the trajectory only if the final screenshot reveals the 'Authoritative Source' of the data (e.g., a specific PDF file or a table on a registry site). You should ensure the agent's final observation successfully pinpointed the requested fact from surrounding UI noise. For instance, accepting a merchant verification only if the SSL certificate modal is visibly open on the screen during the terminal turn.
  - Difficulty-Grounded Reasoning Density: Accept only those cases that represent 'Moderate' or 'Difficult' samples where standard MLLM performance is historically below 80%. You must prioritize trajectories that overcome complex DOM structures or dynamic content blockers. A trace for a 'Simple' one-click retrieval should be demoted in favor of cases requiring multi-tab navigation and variable-linked search.
  - Process Reweight Value Scaling: Accept trajectories where the most critical decision-making occurs in the later steps of the horizon (the 'Extraction Phase'). You must verify that the agent demonstrated high precision during the final retrieval turn, as this step typically involves the highest informational density. A valid case shows the agent accurately extracting a 10-digit customs code from a crowded grid as its terminal action.
* **Rejection Criteria**:
  - Search-Snippet Shortcut Contamination: Reject any trajectory where the agent 'guesses' the factual answer using its internal general knowledge or Google search snippets without visiting the target deep-page. This indicates a failure to test GUI-grounded extraction. If the HS code is found in the search result description and the agent finishes without clicking the link, the seed must be discarded.
  - Indiscriminate Data/DOM Dumping: Reject any trace where the agent simply outputs a full-page OCR dump or DOM tree export as the answer instead of pinpointing the requested fact. The final answer must be a short, factual string (e.g., '10.50' or 'EXEMPT') representing active extraction. Providing 'Here is the textual markdown of the page' as an answer results in immediate rejection.
  - Redundant Verification Looping: Reject trajectories where the agent repeatedly opens and closes the same sub-menu or re-checks the same search results due to a lack of state memory. You must ensure the agent moves unidirectionally toward the goal. A trace where the agent clicks 'Compliance' three times without observing the data already rendered on the page is a terminal planning failure.
  - Step-Level Inertia/Partial Success: Reject cases where the agent achieves a partial extracted string but fails to capture the full technical value (e.g., extracting '4407' instead of the full HS code '4407.11.00'). You must perform character-level validation against the ground truth pixels. If the user asks for a merchant's 'Registration Date' and 'Status' but the agent only provides the date, the seed is incomplete.
  - Captcha/Interaction Block Failure: Reject trajectories where the navigation is dominated by redundant clicks attempting to circumvent a persistent interactive blocker like a slider captcha or a login wall. The goal is information seeking; if the trace spends more than 3 steps stuck on a non-retrieval task, it should be removed. For example, a trace that clicks 'Verify' five times without success is rejected for lack of strategic pivoting.
  - Mismatched App-Context Grounding: Reject cases where the agent identifies the 'App' correctly (e.g., a registry site) but extract information from a visually salient 'Distractor' record (e.g., the wrong company name). You must cross-reference the extracted variables with the user's initial constraints. If the user asks for 'TechCorp' results and the agent extracts info for 'TechGroup' because it was on top, the trajectory is discarded.
