# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement State-Action Gap Perturbation by intentionally executing 'uncertain' actions in a simulation to create discrepancy-rich trajectories for the agent to analyze. You should use a simulator to perform a sequence and then 'jump' the agent to a middle step with an incomplete history log, forcing it to use perception to fill the causal holes. For example, in a navigation task, stop the trace abruptly and ask the agent to identify which specific turns were taken to reach the current intersection.
  - Execute Multi-Sample Consistency Probing where the agent generates several different historical theories for a single current observation to identify the most logically sound path. You must require the explorer to find 3-5 disparate 'Back-track' routes and then use a consensus mechanism to select the one that matches hard environment constraints. A concrete edge case involves distinguishing between a 'Login Timeout' and a 'Wrong Password' result when both lead to a blank input field.
  - Perform Chronological Trace Distillation by isolating 'high-difficulty' trajectories where initial attempts failed, creating 'Failure-Success' pairs that highlight the moment of state divergence. You should archive the specific observations that corrected a false belief about the environment's recent history. For instance, record the exact moment an agent realized a 'Click' didn't fire, necessitating a reconstruction of its progress-tracker from that point.
  - Deploy Implicit Dependency Auditing to scan current environment metadata (like a DOM or a coordinate map) for artifacts of previous actions. The agent must systematically search for 'toggled' states (like a checkbox) or 'breadcrumbs' (like a recently opened tab) that prove a specific action occurred. A concrete example is detecting a 'Downloaded' toast message to confirm that a previous 'Export' action was successful despite a subsequent screen change.
* **Target Trajectory Profile**:
  - The target trajectory must exhibit a 'Reflective Loop' where the agent halts its forward progress to generate a 'Back-track Summary' of the preceding steps. Concretely, the trace should show a specific block labeled <think> where the agent reasons about how the current visual state relates to the goal and its presumed history. If the agent notices its current coordinate is (50, 20) but it planned to be at (10, 10), the trajectory must show it recalculating the intervening path.
  - Each trajectory should include a 'Causal Discrepancy Resolution' where an unexpected observation triggers a correction of the internal state. The log must record the precise action that led to the confusion and the subsequent 'Back-tracking' logic used to identify the culprit. For example, if a 'Save' button is disabled, the agent should reconstruct the history to realize it forgot to fill a mandatory required field earlier.
  - A high-quality profile demonstrates 'Retrocausal Grounding' by linking reconstructed actions to specific UI or environment coordinates. Instead of saying 'I clicked something,' the trajectory must pinpoint the exact Resource ID or X/Y coordinate that was likely triggered to produce the current state. This is visible when the agent explains: 'I am on the Dashboard; therefore, the previous step at [100, 200] must have been the Home button.'
  - The sequence must terminate with a 'Forward Repair Plan' that directly utilizes the reconstructed history to advance toward the goal. The trace should show the agent bridging the 'Known Past' with the 'Projected Future' to ensure the plan remains coherent. A sharp trajectory avoids starting the task from scratch; it resumes from the most advanced valid state identified during the reconstruction process.
