# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the 'Back-tracked History' is mathematically and logically reachable from the task's starting state using the available action space. You must run a topological validator to ensure the inferred sequence of moves is a valid path in the environment's state-transition graph. If the agent claims it clicked a button that was not rendered in the previous simulated state, the seed is rejected as a retrocausal hallucination.
  - Accept a trajectory only if the 'Reconstructed Plan' resolves a specific state-tracking error that was present in the agent's initial 'naive' view. There must be verifiable evidence that the agent's internal model was 're-synchronized' with the environment's truth. A valid seed shows an agent correcting a 'Task SR' failure by successfully identifying a missed step through back-tracking analysis.
  - Accept only if the simulation logs prove that the 'Retrocausal Thought' block resulted in a more efficient forward plan than a baseline 'Zero-Shot' recovery attempt. The selection unit should check if the agent saved steps by building on its reconstructed history rather than repeating discovery actions. For instance, recognizing a search was already performed and moving directly to the 'Download' link.
  - Accept only if the agent's 'Thought-to-Action' mapping is consistent across the transition from back-tracking to forward planning. You must audit the JSON payload to ensure the variables extracted during the history reconstruction (like a dynamic User ID) are correctly passed into the next tool call. If the agent identifies 'Context X' but then performs 'Action Y' which is irrelevant, the planning logic is broken.
* **Rejection Criteria**:
  - Reject seeds where the agent exhibits 'Linear Blindness,' characterized by blindly following a pre-set plan even when the environment has clearly diverged. If a button click fails and the agent continues to narrate the plan as if it succeeded, the back-tracking capability is absent. A concrete failure is an agent that 'confirms' an item is in the cart when the observation shows an 'Out of Stock' error.
  - Discard any trajectory where the 'Back-tracking' is purely rhetorical and produces no change in the subsequent action sequence. Proper reconstruction must lead to a 'Self-Correction' event in the execution log. If the agent says 'I made a mistake' but repeats the same exact mistake in the next step, the seed is noise and lacks the required self-evolving strategic depth.
  - Reject trajectories containing 'Miracle Corrections' where the agent fixes a state discrepancy without a visible perception-based reasoning trace. The agent must not use 'God-view' knowledge from the simulator's backend; it must derive the history from the provided screenshots or observations. If the agent knows a hidden password without a preceding 'read' or 'reconstruct' step, it is a data-leak violation.
  - Reject any seed where the reconstructed actions use inconsistent terminology or coordinate spaces compared to the current exploration environment. This indicates the agent is reciting a memorized legacy trajectory rather than planning in the active sandbox. For example, claiming it clicked a 'Next' button while the current application uses a 'Continue' button with a different ID.
