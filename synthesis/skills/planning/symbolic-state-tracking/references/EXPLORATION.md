# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Begin by searching for raw seeds where the core challenge is symbolic object relations or spatial states whose truth values change after each move. First, inspect the environment description and identify which facts, resources, spatial relations, or external data fields can change during execution. For example, in a weak seed the task may look hard in prose but the decisive variable never changes, so it should be discarded immediately.
  - Force the exploration policy to uncover at least one dependency chain before you stop searching. Start from the goal, work backward to the enabling preconditions, and record which earlier actions or tool calls would be required to make those preconditions true. For example, if a later transfer needs a free gripper or a specific location mapped out, the trajectory must explicitly surface that enabling dependency.
  - Map symbolic variables to logical constants by analyzing the environmental description for recurring action-precondition pairs, particularly if tokens are intentionally obfuscated. You must systematically relate any 'alien' or randomized string back to a standard placeholder (e.g., interpreting 'Zorp' as 'hand-empty') to track the hidden structural shifts. This step ensures that exploration is robust against variations in nomenclature.
  - Identify all decision hubs (like T-junctions or intersections) and require the agent to update a mental map or coordinate tracker upon hitting them. The agent must systematically mark these coordinates as high-priority nodes in an internal scratchpad to differentiate them from simple corridors or linear lists. For example, when exploring a building, the agent identifies the elevator lobby as a hub because it connects to multiple distinct wings, forcing a spatial state variable update.
  - Prefer environments that contain at least one plausible but wrong branch to verify robust state memory. During exploration, intentionally probe an attractive shortcut and note why it fails under the environment rules, testing whether the state tracker correctly flags a contradiction. For example, attempting to place a block on an occupied space or taking a shortcut through a wall creates a strong contrastive seed for later synthesis.
* **Target Trajectory Profile**:
  - The target trajectory must exhibit a sequence in which each action explicitly unlocks a later precondition by changing a tracked symbolic relation, coordinate, or path state. Concretely, the trajectory should show at least one early step that is only valuable because it acts as an enabler for a future goal, not because it looks locally optimal. Cleaning a glass, freeing a gripper, or satisfying an abstract string precondition all fit this profile.
  - A good trajectory should expose both progress and risk by containing structural dependencies that are fragile to poor sequencing. It should contain enough structure that one can point to the exact moment where a wrong or premature action would have caused physical infeasibility or a logical contradiction. If moving a block to a specific region seals off the remaining workspace permanently, the seed is ideal because it punishes stateless planning.
  - The trajectory must demonstrably divorce logical operation from linguistic priors when working with generalized environments. If terms are obfuscated in the task, the trajectory must show strict adherence to the new terminology sequence without reverting to default English verbs. This confirms the sequence works by causal state tracking rather than textual guesswork or language model bias.
  - The sequence must exhibit a clear pattern where every set of movement or transformation actions is followed by an internal state update (a mental sketch or predicate list) that reflects the new configuration. The trace should show the agent 'seeing' its own location or object layout move from configuration A to configuration B on its internal pad. A good profile shows the agent calculating that after three 'forward' moves, it has reached geometric coordinate (2,3).
  - The final trajectory should be neither trivial nor unnecessarily bloated to maintain evaluation clarity. Aim for a sequence long enough to reveal the core state-tracking capability, but short enough that every step structurally matters and can be rigorously audited. A precise six-to-twelve step plan with corresponding state-updates is usually optimal for testing step-by-step sequential logic.
