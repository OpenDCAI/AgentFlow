# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept a trajectory only if it contains verifiable evidence that the planning capability is utilizing true state logic. First, check that the key decision points are causally linked to the environment state updates, retrieved evidence, or explicit symbolic constraints. If changing the order of the actions randomly still magically produces the same acceptable answer, then state tracking is not really required and the seed must fail.
  - Accept only seeds where the planner's intermediate record can be audited against formal preconditions. Every major action should be logically explainable by an immediately preceding observation or symbolic state effect, without jumping straight to the final state. If an agent performs an action without structurally possessing the enabling clear/empty state in its records, the trajectory must be scrapped.
  - Accept only if the agent successfully achieves goals even when semantic bias hallucination is controlled for. The plan must show the agent using provided definitions correctly even when they are counter-intuitive to normal language, confirming objective state tracking. For example, if a domain rule says that 'Attack' requires 'Harmony', the plan is only valid if it correctly tracks and respects that bizarre relationship.
  - Accept a trajectory only if the internal mental states or coordinate sketches generated during reasoning preserve the exact spatial configuration or graph logic of the original environment. You must verify that the base grid or rule set in the 'mental state' matches the original environment exactly across all steps. If an agent's sketch accidentally 'erases' a wall to create a shortcut that doesn't exist, the seed must be rejected.
  - Accept only if the trajectory supports robust question writing with dense state-tracking constraints. The data trace must contain enough specific relational interactions to target a strict sequence request where predicates like CLEAR, ON, and coordinate facts matter dynamically. The resulting required sequence must also be unique or heavily bounded by the starting state layout, leaving no room for vague answers.
* **Rejection Criteria**:
  - Reject any seed that exhibits contextual gaslighting, where the agent provides an incorrect plan and justifies it with nonsensical semantic logics. For instance, if an agent justifies 'stacking block A' because it 'loves block B' rather than utilizing standard 'ON/CLEAR' physical dependencies, the trace represents a failure in objective planning. Such answers completely ignore the simulated physics and state updates.
  - Reject any trajectory that hides crucial information outside the recorded sequence, breaking the chain of symbolic state transitions. The approved sequence must emphatically not depend on unstated assumptions, teleporting objects, or skipping nodes that circumvent standard rules. If a block is magically placed at the bottom of a stack without unstacking the objects above it, the logic is totally broken.
  - Reject trajectories with meaningless decoration, infinite feedback loop cycles, or strictly redundant steps. Removing middle actions should noticeably corrupt the feasibility constraints of the goal if the trajectory is properly lean and sharp. Endless repacking or picking up and dropping the same block without advancing toward the terminal goal indicates a failure of the state tracking logic.
  - Reject any seed where the agent's internal sketch or tracking vector identifies its location at a point that contradicts the cumulative effect of its previous actions. If an agent has turned left twice but its state shows it facing the original direction, it has lost its orientation and the trajectory is useless for training. Claiming to be at the target while the tracker shows the agent three tiles away is a massive error.
  - Reject any seed whose formal steps cannot be mechanically and objectively verified. The final plan or answer must be cleanly validated against explicit matrix transits, spatial grids, or strict PDDL-like rule bases. Simple judgments by formal tone, narrative prose, or stylistic plausibility are grossly insufficient for verifying a capability based solely on formal predicate truth updates.
