# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify the 'Logical Pivot Points' in the environment description by searching for conditional formulas or recursive definitions that are prone to 'off-by-one' or initialization errors. You must systematically flag steps where the plan's starting state or boundary conditions could diverge from the provided examples. For instance, in a sequence generation task, explicitly check if the starting index is 0 or 1 by dry-running the very first step of the logic.
  - Perform 'High-Entropy Symbolic Mapping' by translating the user's natural language constraints into distinct symbolic variables before constructing the plan. You should relate terms like 'digit', 'number', or 'index' back to their programmatic counterparts to ensure the plan targets the correct level of data granularity. A concrete example is verifying whether a 'range' includes the upper bound by simulating a small, two-item range calculation.
  - Construct 'Representative Input-Output Seeds' from the provided problem description to serve as the ground truth for the simulation phase. You must choose inputs that are small enough to be traced manually but complex enough to trigger all major branches of the intended logic. For example, if the goal is to filter items, select an input set where at least one item satisfies the condition and one is a 'near-miss' that should be rejected.
  - Analyze 'Multi-Step Dependency Chains' to identify which upcoming actions rely on the successful completion of a specific prior state change. You should map out the 'Internal State' of your plan at each step to catch hidden dependencies that may be unstated in the prompt. An edge case involves recognizing when a recursive step requires a value that has not yet been calculated or stored in the plan's cache.
* **Target Trajectory Profile**:
  - The trajectory must feature an 'Internal Dry-Run Trace' where the agent narratively simulates a sample input against its own plan or code. This is documented by a step where the agent states 'Simulating for input X: Step 1 yields Y, Step 2 yields Z.' A good profile shows the agent identifying a logic flaw during this trace, such as a missing initialization or a variable mismatch, leading to a revised sequence.
  - Each trajectory should exhibit 'Symbolic Parity Checking' by comparing the final simulated output with the expected result provided in the user's examples. The agent must explicitly state 'The generated output matches/does not match' before proceeding to finalization. A concrete indicator of a sharp trajectory is the agent catching a semantic error, like confusing 'even numbers' with 'even digits', during the matching step.
  - The trace profile must include 'Corrective Iteration cycles' where a negative simulation result triggers an immediate return to a revised planning or coding stage. You should see a clear transition from 'Plan A (Wrong)' -> 'Simulation (Mismatched)' -> 'Refinement' -> 'Plan B (Correct)'. This confirms the agent is using simulation as a gatekeeper for quality rather than just as a descriptive exercise.
  - The final trajectory should be 'Procedurally Auditable,' meaning every change in the plan's logic must be directly justified by the findings of the preceding simulation. The agent must avoid making generic improvements; instead, it should say 'The simulation showed X failed, so I am changing Y.' An example is updating a loop's start index specifically because the simulation revealed the first item was skipped.
