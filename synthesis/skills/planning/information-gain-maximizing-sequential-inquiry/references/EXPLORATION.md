# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Attribute Set Extraction: Begin by systematically identifying all discrete attributes (keys) and values associated with the pool of candidates in the environment. You must generate a frequency map of every attribute to calculate its potential 'splitting power' across the dataset. For instance, in a medical diagnosis arena, you would list all symptoms reported by patients to see which ones are unique to specific rare conditions versus which are common to all.
  - Candidate Density Estimation: Calculate the current size of the 'valid candidate' set and determine the entropy of the distribution. After every hypothetical inquiry, you must predict the new set size to ensure the chosen question noticeably compresses the search space. An edge case is if every candidate shares the same value for a chosen attribute (e.g., all 10 items are 'Blue'), the explorer must immediately discard that attribute as it provides zero information gain.
  - Search Space Pruning Verification: Perform trials of 'Shortcut Inquiry' where you skip high-level categories and jump to specific features to see if it causes a dependency break. You must document if a specific question order reveals a 'Hidden Constraint', such as a user having a limited understanding of a technical term, necessitating a fallback description. In a tech-spec search, if the agent asks about 'Clock Speed' and the user is confused, the exploration should mark that attribute for future 'hinting' support.
  - Sequential Path Unrolling: Execute multiple exploratory routes through the decision graph to identify the 'Average Path Length' to success for different starting questions. You should prioritize the path that maintains the highest 'Purity' at each node, ensuring that the final recommendation occurs at the earliest possible depth. For example, in a car search, testing whether starting with 'Price' or 'Body Type' results in a narrower final set after three moves.
  - Interaction naturalness grounding: Analyze which inquiries naturally facilitate a conversational flow by clustering related attributes together. You must verify if asking about 'Finish' immediately after 'Color' feels more intuitive to a human than jumping to 'Price', without sacrificing the mathematical efficiency of the split. This ensures that the generated trajectories remain coherent and don't feel like a randomized interrogation.
* **Target Trajectory Profile**:
  - Information-Gain-Ordered Trace: The target trajectory MUST show a sequence where the attributes addressed first have the highest potential to narrow down the candidate set. Concretely, the agent should justify its choice by noting how many candidates will likely be eliminated by the question. A profile that asks about 'Model Number' before 'Category' is suboptimal and should be flagged.
  - Discriminative Step Progressions: The trajectory profile must clearly show the 'Current Pool Size' diminishing at every turn of the inquiry sequence. You should see a progression where Turn 1 eliminates 80% of candidates, Turn 2 eliminates 50% of the remainder, and so on. A good trace results in a 'Converged Set' of 1-3 items within 5-7 interaction turns.
  - Expert-to-Layman Translation Nodes: The profile must include 'Clarification Hooks' where the agent provides common value examples (hints) alongside high-gain technical questions. The trajectory should show the agent proposing values like '256GB or 512GB' when asking about storage. This verifies the agent is planning for human understanding while pursuing mathematical efficiency.
  - Constraint-Satisfaction Checkpoints: Every inquiry in the trace must be grounded in the user's previously stated preferences, ensuring the agent doesn't ask 'Is it red?' if the user already said they only want 'Natural' colors. The log must cross-reference previous observations to prune future attribute lists. A sharp trajectory avoids repeating any attribute logic that was implicitly satisfied by an earlier choice.
  - Terminal Convergence Logic: The trajectory must conclude with a definitive 'Recommendation' or 'Diagnosis' action once the search results reach a sufficiently unique cluster. The agent should explicitly state that it has narrowed the options down to the most relevant items based on the preceding path. A termination state occurs when asking more questions would result in marginal or zero additional information gain.
