# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Plan Efficiency Ratio: Accept a trajectory only if the number of turns used to reach the goal is significantly lower than a linear search or a randomized inquiry. You must calculate if the agent reached the target in O(log N) turns relative to the candidate set size N. If a plan takes 10 turns for a set of only 15 items, the information gain was not maximized and the seed must be rejected.
  - Attribute Purity Verification: Accept only if the selected inquiry attribute at Step N is indeed the one with the highest information gain given the set remaining from Step N-1. You must programmatically verify that no other available attribute would have created a more balanced or effective split of the remaining candidates. If the agent asks about a 'special feature' when a 'primary category' was available but unqueried, it is rejected.
  - Logical Attribute Ordering: Accept only if the sequence of inquiries flows from general high-level discriminators to specific low-level details. The selection unit must verify that the agent didn't ask 'What kind of button?' before asking 'What kind of device?'. Rejection occurs if the plan exhibits 'Attribute Jumping', where it cycles between unrelated features without exhausting the current level of complexity.
  - Hint Accuracy Grounding: Accept only if the common values (hints) provided during the inquiry are extracted directly from the top-k most frequent values in the current candidate set. The selection unit must cross-reference the suggested values against the real dataset. If an agent suggests 'Blue' as a popular color when none of the remaining items are blue, the grounding is broken and the seed is discarded.
  - Consistency of Interest Mapping: Accept a trajectory only if the final recommendation/diagnosis perfectly satisfies the 'Wanted', 'Unwanted', and 'Optional' interest states tracked throughout the sequence. You must check that no item with an 'Unwanted' attribute was recommended. If the user said 'No Liquid' and the agent recommended a liquid soap, the planning logic is considered a failure.
* **Rejection Criteria**:
  - Redundant Inquiry Loops: Reject any seed where the agent asks about an attribute whose value was already implicitly determined by a previous answer. For example, if the user said they are looking for a 'Vegan' product, the agent should not later ask 'Does it contain beeswax?' if that knowledge is already in the domain rules. This avoids 'Double-Querying' and proves true causal state tracking.
  - Hallucinated Attribute Values: Reject trajectories where the agent presents an inquiry regarding an attribute that does not exist in the environment's catalog. This includes agents 'inventing' features like 'battery life' for a product that doesn't have a battery (e.g., a scarf). Every question must be anchored in the symbolic metadata of the actual potential outcomes.
  - Zero-Split Interaction: Reject any trajectory turn where the selected attribute has only one possible value for all remaining candidates. Asking 'Do you want a 4-door?' when all remaining cars in the search pool are already 4-door models provides zero information. A valid plan must only ask questions that have at least two plausible outcomes that divide the pool.
  - Instruction-following Mismatch: Reject any seed where the agent fails to verbalize the specific planned attribute-value pairs defined by the decision-tree plan. If the plan says 'Ask about Color' but the agent's action is 'Ask about Price', the execution of the planning artifact has failed. This ensures strict adherence between the strategic roadmap and the functional output.
  - Premature Terminal Action: Reject any trajectory that provides a 'Final Recommendation' while the candidate set size is still large enough (e.g., >20) that further splitting is possible and necessary. The agent must show persistence in narrowing the search until a meaningful 'family' or individual item is reached. Recommending a generic set without enough inquiry is considered a lazy planning failure.
