# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Information Dependency Mapping: Begin by selecting task environments where critical plan variables are completely unknown until retrieved through consecutive tool interactions. The agent must systematically identify which facts or constraints are missing and trace what specific tool calls would be required to acquire them iteratively. For example, if designing a travel itinerary, the agent notes that flight availability is fundamentally unknown without querying an external API, creating a strict procedural anchor for the trajectory.
  - Hierarchical Database Layering: Construct the environment using multi-grained data silos where initial tools provide broad context and subsequent tools allow high-fidelity focal inspection. The exploration policy must actively transition from a 'global browse' API to a 'semantic clip search' API to finally a 'raw frame inspection' API as the search space narrows. An edge case occurs when the global summary provides a plausible but slightly incorrect assumption, forcing the exploration to actively verify details via targeted deep-dives.
  - Heterogeneous Silo Profiling: Analyze the structural nature and content density of each available knowledge repository. Document whether a specific tool provides foundational definitions (Textbooks), procedural standards (Guidelines), or relational hierarchies. Translate Lexical Frequencies into aligned queries (e.g., using jargon for Research APIs, layman terms for Wiki APIs) to ensure optimal tool-fetch capabilities.
  - Plausible Negative Branching: Prefer environments that contain highly attractive but ultimately invalid options to test the agent's ability to reject bad information. During the retrieval phase, the agent should intentionally evaluate a shortcut option, observe its failure via the tool output, and document the specific constraint it violated. A concrete example is probing a direct flight route that appears optimal but returns a 'no pets allowed' flag, creating a pivot point for later data synthesis.
  - Scratch-Pad Memory Consolidation: Maintain an explicit, structured working memory state throughout the exploration to aggregate scattered tool outputs into a unified situational map. After every targeted retrieval, the agent must update this compact record to reflect what new decisions are unblocked and which alternatives are now permanently pruned. For instance, log the victorious candidate city after searching three different weather APIs.
* **Target Trajectory Profile**:
  - Targeted Retrieval Alternation: The target sequence must exhibit a clear alternation between active tool-based acquisition and internal notebook consolidation before finalizing the overarching plan. The trajectory must show at least one early step that is solely valuable because it extracts a prerequisite ID or variable needed for a later tool call.
  - Adaptive Granularity Escalation: The trajectory should explicitly demonstrate a progression from coarse-grained queries to high-fidelity focal verification as information density increases. The log must verify that the agent did not just parrot an initial coarse summary, but successfully used a detailed inspection tool to validate a specific detail. A strong example shows the agent querying 'Is there a car?' using a broad tool, and then invoking a secondary pixel-check tool to confirm 'What is the license plate number on the car?'.
  - Source-Specific Query Orchestration: The target trajectory must exhibit a clear planning step where distinct search queries are mapped to specific, categorized knowledge tools. Concretely, the trace should show the agent generating different lexical strings for the same entity based on where it is searching. An example is the agent searching 'S3 gallop symptoms' in a textbook silo but 'S3 gallop clinical utility' in a research silo.
  - Inspectable Dependency Provenance: Every single decision in the finalized plan must be causally linked to a visible state response or retrieved fact from the tools. The QA trace must leave a legible trail where an auditor can see exactly which JSON response or text block provided the justification for the subsequent move. For instance, 'choosing Hotel B' is directly supported by the prior API output indicating 'Hotel A violates minimum stay requirements'.
  - Optimal Tool Selection: The chosen sequence of actions must represent the most efficient discovery path without getting bogged down in redundant or pointless tool usage. The final trajectory should be short enough that every retrieval step materially advances the agent's contextual knowledge, avoiding infinite loop traps. A failure case is an agent that calls a 'weather API' ten times for the same city without advancing to the 'book flight' stage.
