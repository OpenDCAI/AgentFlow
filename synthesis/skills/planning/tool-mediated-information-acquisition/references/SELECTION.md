# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Verifiable Tool-Grounded Work: Accept a trajectory only if it contains absolute proof that the plan's components were sourced through explicit tool calls rather than the agent's internal general knowledge. You must mandate that the final decision points were actually present in the recorded sandbox output variables. If an agent outputs a perfectly valid real-world itinerary but never executed the required API search, jump the seed.
  - Hierarchical Depth Completion: Accept only seeds where the agent demonstrates discovery across at least two distinct levels of granularity or separate API endpoints. You should verify the sequence shows a transition from a broad discovery operation (like a keyword search) into a specific filtering or inspection action (like requesting a specific ID's details).
  - Query-to-Silo Alignment Score: Accept a trajectory only if the phrasing of each query logically matches the typical document structure of its assigned silo. You must verify that technical, bibliographic-heavy queries are directed at Research/Guideline tools while simplified, broad queries are sent to Wiki/Textbook tools. If a query like 'detailed stats on page 4' is sent to a knowledge graph, the seed is rejected as structurally incoherent.
  - Auditability of Intermediate Records: Accept only if the agent's intermediate reasoning correctly aligns with and processes the raw data returned by the prior observation. The selection script must confirm that when an API returned 'True', the agent's subsequent thought block factually acknowledged the positive state before moving forward.
  - Unique Solution Bounding: Accept only if the trajectory's retrieved facts bound the environment so tightly that the generated answer is arguably the sole logically optimal plan. There must be enough acquired constraints to filter out all generic responses. If multiple perfectly acceptable plans remain after all the information is gathered, the environment is insufficiently constrained.
* **Rejection Criteria**:
  - Hidden Private Knowledge Bleed: Reject any trajectory that implicitly relies on unstated assumptions, private LLM weight knowledge, or external tool-outputs that are missing from the raw log. The approved sequence must emphatically not depend on facts like recognizing a famous movie quote if the 'Wikipedia Tool' was never invoked.
  - Superficial Semantic Copying: Reject seeds where the agent provides different queries for various tools, but the queries themselves are just superficial rewordings without a change in 'search level' or 'technical depth'. If the difference between two queries is just a synonym, the agent is not performing attribute-aligned Tool Planning, it is just generating noise.
  - Redundant Search Looping: Reject trajectories loaded with decorative, irrelevant, or circularly repeated tool calls that provide no new data to the agent's workspace. If a middle action (like searching for the same item twice) can be stripped from the record without altering the feasibility or insight of the final plan, the trace lacks critical sharpness.
  - Granularity Stalking: Reject instances where the agent repetitively invokes highly expensive, fine-grained inspection tools broadly without first using a coarse-grained summary to narrow the target area. Planning agents must demonstrate computational efficiency, so using 'pixel-verify' on the entire dataset instead of a 5-second clip signifies poor orchestration logic.
  - Superficial Semantic Difficulty: Reject any seed where the core technical challenge relies solely on confusing vocabulary or deliberately obfuscated user prompting rather than missing environmental data. If normalizing the entity names alone solves the task without requiring API calls, the capability is not being accurately represented.
