# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Metric vs. Non-Metric Structural Diagnostics: Begin by analyzing the cost matrix or adjacency graph to determine if the environment follows Euclidean (metric) rules or asymmetric (non-metric) rules. You must explicitly check if the distance from A to B is equal to B to A and if the triangle inequality holds before selecting a search strategy. For example, in a routing task, identifying that B-to-A takes twice as long due to a one-way street forces the explorer to look for asymmetric-safe algorithms.
  - Scale-Driven Memory Constraint Mapping: Analyze the number of variables (n) or nodes (V) to determine if the problem exceeds local memory thresholds for specific solver types (e.g., neural OOM transitions). You must classify the problem as 'Small' (n < 1k), 'Medium' (1k < n < 10k), or 'Extreme' (n > 100k) to tailor the pruning strategy. A practical step is noting that a TSP with 10M nodes requires hierarchical reduction (e.g., POPMUSIC) rather than a flat search to remain executable.
  - Structural Irregularity Probing: Identify if the graph structure is 'Uniform' (randomly distributed points) or 'Structured/Adversarial' (SAT-induced, Hypercube, or non-metric). You must use diagnostic queries to check for high-density local clusters or non-local dependencies that might deceive simple greedy search solvers. For instance, in an MIS problem, if the graph is SAT-induced, the exploration must target deep logic conflicts rather than just picking nodes with low degrees.
  - Lookahead and Branch-and-Bound Verification: Implement a localized DFS probing strategy to evaluate the solvability of a small sub-problem before committing to a massive execution run. The explorer should intentionally project forward to identify if a specific variable assignment creates a contradiction in a distant part of the graph. A concrete case is checking if assigning a facility at location X makes fulfilling Customer Y's demand impossible due to cascading capacity limits.
  - Algorithm-Selection Reasoning: Explicitly evaluate multiple metaheuristic frames (e.g., Simulated Annealing vs. Large Neighborhood Search) based on the specific problem constraints. You must justify why a chosen algorithm is better suited for the current distribution, such as selecting LNS for jobs with complex precedence constraints in scheduling. For example, if a problem has many local optima, the agent should prioritize an algorithm with a strong restart or noise-injection mechanism.
* **Target Trajectory Profile**:
  - Hybrid Neural-Symbolic Signature: The trajectory must exhibit a sequence where a neural module provides initial probabilities or Steiner points, followed by a symbolic algorithm performing legal construction. Concretely, the path should show the agent using a GNN as a guide while using a classical solver (like LK3 or SCIP) for the final hard-constraint satisfaction. A good profile shows the neural prediction saving search time while the symbolic check ensures 100% validity.
  - Scale-Agnostic Reduction Traces: The trace must include 'Kernelization' or 'Partitioning' steps where a massive problem is broken into solvable chunks or reduced to a hard core. You should see the agent state 'The 1M node graph is too large; I will use a local reconstruction window of 100 nodes to refine the tour.' This confirms the agent understands how to manage extreme-scale computational bottlenecks effectively.
  - Structural-Aware Backtracking: A high-quality profile demonstrates the agent rejecting a partial solution because a non-local structural check (e.g., SAT-logic or hypercube path) failed. The trajectory should include 'Thought' blocks like 'Even though Node 5 looks locally optimal, it violates the global hypercube parity constraint needed for the Steiner Tree.' This shows the agent is optimizing the search using global structure awareness.
  - Diverse Permutation Evaluation: Valid trajectories must show a sequence of candidate evaluations where multiple configurations (Variable Neighborhoods) are tested. The path should show the agent trying a 3-opt swap, identifying that it didn't decrease the cost in a non-metric space, and then attempting an alternative relocation move. A sharp trajectory concludes by presenting the best configuration found as a provable local or global optimum.
  - Constraint-Grounding Success Indicator: The final plan must conclude with a 'Holistic Verification' step where the proposed answer is checked against every capacity, precedence, and topological rule. The agent should explicitly confirm that no vehicle exceeded capacity or that all terminals are reachable in the generated tree. This ensures the output is a functional planning artifact, not just a textual suggestion.
