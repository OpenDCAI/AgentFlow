# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Functional Unit Identification: Scan the interaction history for chains of 3-5 primitive actions that consistently result in a unified state change, such as navigating from a home page to a specific deep-linked dashboard. The planner must isolate the specific starting action (e.g., a click on the 'Marketing' tab) and the terminal verification (e.g., reaching the 'All Reviews' list) to define the logical boundaries of a potential macro. An edge case occurs when the trajectory involves accidental scrolls or redundant hovverings, which must be filtered out to ensure the functional unit remains lean and task-oriented.
  - Repetitive Pattern Detection: Analyze the task instruction or action trace for set-based operations or lists of entities that require identical processing steps across different data inputs. If a user asks to 'Review orders #101, #102, and #103,' the agent should look for a common trajectory segment that can be parameterized with an Order ID variable. A concrete example is a sequence of 'Go back -> Enter ID -> Search' which repeats multiple times, signifying a perfect target for programmatic abstraction and reuse.
  - State-Dependent Variable Mapping: Map the specific input strings used in a successful trace to identifies which elements should be variable arguments in the macro versus fixed constants. You must verify if these parameters, like a search box ID, are static within the session or if they need to be fetched dynamically from the DOM during the exploration. For instance, if a search-box ID changes on every load, the exploration should attempt to locate it by a semantic tag like 'name=search' rather than a hardcoded number to ensure the skill is reusable.
  - Verification Checkpoint Mapping: Define the intermediate environment observations that verify the completion of a sub-task, such as a 'Success' banner or an updated cart count. The trajectory must explicitly record these state-changes so the later verification phase can use them as hard gates for confirming the validity of the new programmatic skill. If an 'Add to Cart' macro is proposed, the exploration must confirm that the count in the top-right corner incremented before designating the sequence as a valid skill-seed.
* **Target Trajectory Profile**:
  - The trajectory must exhibit a 'Hierarchical Transition' where a long sequence of primitive tool calls is replaced by a single macro-block with clear input/output parameters. Concretely, the trace should demonstrate a 50% or greater reduction in plan length when the new skill is applied. For example, a 10-step manual navigation to an admin panel should be condensed into a single `goto_admin()` programmatic call.
  - A good trajectory should include at least one 'Parameterized Loop' where the same macro-skill is invoked multiple times with different values (e.g., different product names). This proves the induction isn't just a static macro but a flexible program capable of handling varied user inputs. A failure to show this indicates the skill is 'over-fitted' to one specific case and is not truly a composable action.
  - The trajectory must be documented using 'Clean Episode' logic where invalid tries or error-causing actions are removed from the record. Each step must show a direct, successful state transition so that the induced program does not learn to repeat the mistakes of the exploration phase. For example, if the agent clicked the wrong button first, that step must be stripped before synthesizing the final plan artifact.
  - Include a 'Termination State Audit' where the final mission-goal is achieved only after the specific programmatic skills have been successfully executed. The trajectory should show that the agent reaches the 'send_msg_to_user' state and that the user's complicated, action-dense request is fulfilled. A sharp trajectory will conclude by verifying the enviornment state (e.g., 'all 5 reviews were processed') against the user's original multi-part objective.
