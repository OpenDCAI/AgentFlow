# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Implement a 'Causal Backbone' mapping by tracing terminal dependencies between actions in a successful symbolic plan. This requires the agent to systematically list every predicate (e.g., 'holding', 'clear', 'is-open') that acts as a mandatory bridge between adjacent steps. For example, in a transport mission, the 'is-at' predicate for the robot must match the 'is-at' predicate of the target item before any pick-up is explored.
  - Execute 'Pre-condition Probing' at every step of the exploratory trajectory to identify hidden 'Negative Constraints.' The agent must explicitly ask 'Given current observations, is the planned action X strictly executable?' before recording the step. A concrete example involves checking if a robot's gripper is currently occupied before attempting a secondary 'Open Door' action, identifying a state bottleneck that requires a repair branch.
  - Execute 'Prefix Simulation' where the agent performs only a partial sequence of the plan and stops at a high-entropy state to generate 'Discrepancy Branches.' You must manually flip the truth values of predicates (e.g., clearing a block or closing a door unexpectedly) and force the explorer to find a restorative path to the goal from the corrupted state. This ensures the exploration data captures the transition from 'error detection' to 'plan recovery'.
  - Establish 'Post-condition Verification Markers' by documenting the exactly visible evidence that confirms a task's success (e.g., seeing the item inside the container). The agent must analyze the environment description to identify which sensors or tool observations (e.g., 'Observation: Microwave contains carrot') satisfy the terminal effect of the action. This creates a ground-truth library of success/failure states for the synthesis phase.
  - Verify 'Reachability Integrity' after injecting environmental perturbations using a depth-first search (DFS) over the symbolic state space. If an injected change (like a locked door) renders the goal impossible, the exploration must backtrack to find a valid graph route. For instance, if Room A is blocked, the agent explores a detour through Room B, documenting the graph revaluation logic.
* **Target Trajectory Profile**:
  - The trajectory MUST exhibit a 'State Divergence Event' where the pre-condition check of a planned action returns False due to enviornmental constraints. Concretely, the trace should show the agent identifying that it cannot proceed with step N because step N-1 left the environment in a state that conflicts with the next action's requirements. For example, 'Holding tool' vs 'Need free hand to open gate'.
  - Each trajectory must include a 'Grounded Repair Sequence' that differs from the original plan's remaining steps, specifically tailored to address the discrepancy. The sequence should show the agent inserting enabling actions (like putting down a held item or unlocking a door) that were not present in the naive initial plan. A high-quality profile concludes by verifying the goal is reachieved from the fixed state.
  - The planning artifact should be formatted as a 'Self-Reflective Template' consisting of Initial State -> Proposed Action -> Pre-condition Violation Detection -> Reflection/Reasoning -> Revised Plan. This ensures the synthetic data captures the internal monologue behind the replanning decision. An example is an agent stating 'I am holding the plate, so I cannot grab the glass; I must reposition the plate first.'
  - Ensure 'Predicate Grounding' where every action in the revised plan is justified by the current truth of its preconditions in the perturbed environment. The trajectory should include 'Thought' blocks that explicitly correlate the repair action with the missing state factor (e.g., 'Using Robot B to open the door because Robot A's hands are full'). This confirms the logic follows symbolic causal laws rather than random guessing.
  - The sequence must exhibit 'Multi-Agent Efficiency Evolution' where the planner refines its strategy over several tasks to minimize redundant moves. The logs should show the agent re-ordering actions in its second attempt (e.g., 'Open door BEFORE picking up carrot') to avoid the state collision identified in the first run. This demonstrates the transition from reactive repair to experience-driven optimization.
