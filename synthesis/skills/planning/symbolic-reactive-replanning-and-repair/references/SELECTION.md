# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the 'Reflective Logic' correctly identifies a legitimate 'Pre-condition Violation' or 'Path Blockage' based on the environment rules. Verifiers must cross-reference the agent’s claim (e.g., 'I cannot pick X') against the environment state (e.g., 'Is_Holding == True'). If the agent claims a violation that doesn't exist to generate a longer plan, the seed is rejected as noise.
  - Accept only if the 'Revised Plan' is successfully validated by a symbolic plan checker as a sound path to the goal given the new environment states. You must verify that the new action sequence satisfies every predicate in the symbolic domain (e.g., PDDL). If the repair plan still contains a logical error (e.g., trying to place an item it never picked up), the trajectory is discarded.
  - Accept only if the 'Repair Complexity' is non-trivial, requiring at least two restorative actions or a multi-hop graph detour before successful goal completion. This ensures the capability is being tested on its reasoning depth rather than trivial retries. For instance, a simple 'retry' after a 10% failure rate isn't enough; the agent must change the structure of its plan.
  - Accept a trajectory only if the 'Post-condition Verification' block accurately flags a failure based on the observation following a task. If the robot dropped an item and the observation shows 'Item_on_Floor', the agent must detect the 'Post-condition: In_Hand == False' error. If it proceeds as if success occurred, it represents a failure of state-tracking and must be rejected.
  - Accept only if the 'Goal Set' is identical before and after the perturbation to systematically isolate the 'Reaction and Repair' capability from generic task switching. The agent must show persistence in pursuing the original high-level instruction despite the structural change. If the agent changes its goal to something easier because the first one broke, it is rejected.
* **Rejection Criteria**:
  - Reject any seed where the 'State Divergence' already fulfills the terminal goal condition, rendering replanning trivial or unnecessary. If a falling block accidentally lands in its target position, the agent has no work to do. The capability requires a conflict that creates an obstacle, not a lucky environment transition.
  - Reject trajectories where the agent continues with the 'Original Plan' despite a clear predicate contradiction in its reflection or observation. This 'Execution Inertia' indicates the agent is merely reciting text without utilizing its condition-checking mechanisms. For example, attempting to place an item into a closed microwave after the pre-condition check found it closed.
  - Reject any trajectory that resolves the conflict through 'Teleportation' logic or undocumented edge hallucination that bypasses standard domain mechanics. All restorative moves must correspond to valid available tool calls or movement actions. For instance, if an agent 'magically' opens a door without performing the 'open' action, the seed is invalid.
  - Reject seeds where the 'Environment Change' is purely cosmetic and does not logically affect the viability of the ongoing plan. If a room's wall color changes or a non-interactive item moves, it shouldn't trigger a 'replanning' event. The agent must demonstrate structural awareness by only reacting to changes that violate predicates in its chain.
  - Reject any trajectory where the agent's 'Reflection' block fails to correctly attribute the cause of the failure. If the robot cannot open a door because its hands are full, but the reflection states 'door is too heavy,' the reasoning is logically detached from the symbolic state and is useless for training planning logic.
