# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Spatio-Temporal Anchor Retrieval: Systematically query the database for Points of Interest (POIs) and their corresponding GTFS public transit metadata to establish geographical grounding for the schedule. The agent must retrieve the geodesic distance between every candidate attraction and its nearest transit stop (e.g., bus, rail) to ensure accessibility. An edge case involves identifying POIs in remote regions where the nearest stop exceeds 5km, necessitating an immediate replanning of the transit mode.
  - Persona-to-Duration Parameter Mapping: Translate user-specified personas like 'Adventure Seeker' or 'Laidback Traveler' into quantitative duration and frequency parameters for attractions. For instance, laid-back travelers are mapped to longer visit durations with fewer attractions (e.g., 4.5 hours for Nature & Parks), while adventure seekers prioritize higher task density per day. This ensures the exploration phase is tuned to the specific temporal behavior of the traveler rather than using a generic average.
  - Integrated Event and Flight Synchronization: Perform concurrent searches for arrival/departure flights and Ticketmaster-style event calendars to anchor the multi-day plan around fixed temporal pillars. The agent must record precisely when events (Sports, Music, Film) are held to prevent conflicts with meal times or city-to-city transfers. A concrete step is ensuring a 3-hour window between a flight's arrival at 14:00 and an event's start at 17:00 to account for transit and check-in.
  - Categorical Boundary Mapping: Inspect the attraction database for specific category tags (e.g., 'Sights', 'Nightlife', 'Museums') to satisfy the user's hard preference constraints. You must group these attractions into localized neighborhood clusters to minimize displacement costs between sequential nodes. An edge case involves finding a 'Water Sport' attraction that also satisfies a 'Cultural' preference, allowing the agent to satisfy two constraints with a single high-value sequence.
  - Meal-Gap Continuity Scraping: Scan the restaurant database to identify breakfast, lunch, and dinner options that align with the traveler's cuisine and budget while satisfying the 4-hour natural scheduling gap. The agent should verify that the selected restaurants are within a reasonable travel radius (<2km) of the preceding attraction or the current accommodation. For example, if an attraction visit ends at 13:30, the agent must find a lunch spot that is reachable before a 14:30 start time.
* **Target Trajectory Profile**:
  - High-Resolution PoI Sequence Signature: The target trajectory must exhibit an ordered, timestamped sequence where every interaction (staying, visiting, dining) includes a precise start/end time and a transit anchor. Concretely, the trace should show the agent explicitly calculating the duration of each visit based on the attraction's type and the traveler's style. A good profile shows the transition from 'Accommodation' at 08:30 to 'Breakfast' at 09:40 with the corresponding transit stop distance documented.
  - Inter-Day Topological Flow: A robust profile demonstrates structural continuity across multiple days, ensuring the terminal state of Day N (the accommodation) is the identical start state for Day N+1. The trajectory must record the logic for choosing specific multi-city routes, avoiding zig-zagging between distant nodes. For instance, moving from Seattle to Portland to Boise in a linear sweep rather than returning to Seattle between every leg.
  - Constrained Resource Orchestration: The trajectory MUST demonstrate the agent maintaining a running budget tally and constraint checklist (e.g., no-pet room check) across the entire sequence. Each decision, like choosing a restaurant, should show an internal 'Thought' verifying that the total cost remains under the user's defined ceiling. A sharp trajectory concludes by presenting the final budget consumption alongside the completed itinerary.
  - Persona-Aware Density Scaling: The final trajectory shows a distinct difference in activity density based on the user's purpose of travel (e.g., 'Relaxation' vs 'Adventure'). For a relaxed traveler, the plan should show fewer segments with higher durations, whereas an adventurous plan will feature more frequent tool-calls for diverse sport or game events. This confirms the agent's ability to tune its execution program to subtle qualitative preferences.
