# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Multi-Agent Meta-Verification (MAMV) Pipeline: Implement a collaborative exploration framework where separate agent personas—such as a Validator, a Simulator, and a DocRefiner—systematically probe tool functionality. The Validator generates and executes diverse API call samples, while the DocRefiner updates descriptions based on observed execution feedback. For example, if an experimental call to a 'Car Search' tool fails without a specific category, the DocRefiner adds that requirement to the documentation to guide future planning.
  - Active Error-Scenario Sampling (EXPLORE): Intentionally derive 'near-miss' trajectories by sampling erroneous steps from successful traces to construct a dynamic 'Error -> Reflection -> Correction' learning library. The explorer should take a correct step, replace it with a plausible but wrong action (e.g., using a string instead of an integer), and then record the environment's error response. This ensures that the exploration phase captures not just successful paths, but the logic required to recover from specific technical failures.
  - Step-Level Feedback Analysis: Force the exploration policy to pause after every tool call or code execution to perform a step-wise audit of the environment state. The agent must map specific syntax errors or runtime exceptions (e.g., HTTP 400, 403, or Python Tracebacks) to the corresponding planning or parameter segments. For example, if a compiler returns a 'Type Mismatch', the scratchpad must explicitly link this to the incorrect variable declaration in the preceding step.
  - Hierarchical Parameter Probing: Conduct 'fuzzing' flights over complex tool interfaces by varying hyper-parameters and observing the divergence in performance scores or error outcomes. You should systematically check how changing a single variable (like a cooling rate in simulation or a limit in an API) affects the technical outcome to establish the sensitivity of the refinement loop. An edge case involves identifying exactly which range of values causes an API to trigger a 'Rate Limit' or 'Timeout' response.
* **Target Trajectory Profile**:
  - Recursive Hypothesis-Test-Refine Signature: The target trajectory must clearly exhibit a multi-turn structure where subsequent action blocks are visibly 'inspired' by preceding observation logs. Concretely, the trace should show the agent quoting the error from Step N (e.g., 'Date should be YYYY-MM-DD') in the reasoning block for Step N+1. This confirms the agent is using System 2 deliberation rather than repeating stagnant, cached patterns.
  - Diagnostic-Correction Coupling: Each trajectory must demonstrate 'Causal Grounding' where a specific code edit or parameter change is directly justified by the findings of a technical execution. You should see the agent identify a 'Missing Parameter' feedback and then immediately insert that specific parameter into its next code execution block. A high-quality profile concludes by showing the final artifact succeeding only after these intermediate restorative steps were applied.
  - Step-Wise Trajectory Minimality: A sharp trajectory avoids 'blind backtracking' or 'infinite trial-and-error' by using feedback to perform surgical corrections. The log must show that the agent reduced the total number of operations by correctly interpreting the failure in one go, rather than guessing five different variations. For example, the agent adjusts all three required fields simultaneously based on a single comprehensive error report.
  - Multimodal Observation Grounding: The trajectory must successfully process diverse feedback modalities, such as raw JSON error objects, textual stack traces, or visual status indicators (e.g., a red 'fail' icon in a UI). The trace must show the agent translating these heterogeneous signals into a unified correction strategy. For instance, seeing a 404 error and concluding that the 'Resource ID' must be re-queried from a different search silo.
