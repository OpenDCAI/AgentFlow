# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Identify the scalar thresholds and mathematical units operating as strict rules within the environment context. Establish the foundational base units governing the prompt constraints, such as currency types or volumetric limits, to prevent conversion-based planning errors. This prevents instances where the agent authorizes 40 Liters of a chemical when the safe limit is 40 Milliliters.
  - Map out the spatio-temporal intersections required for schedule-based activities or time-sensitive workflows. Transform natural language availability constraints into a continuous free-time algebraic array that accounts for travel buffers. If a user dictates a specific start time and sequential commutes, build an offset clock representing the new temporal baseline for every subsequent action.
  - Trace hierarchical conjunctive dependencies where fulfilling Constraint B relies on successfully answering Constraint A. Systematically map condition trees so the agent identifies required prerequisite actions, such as performing a 'verify_identity' tool call before browsing a 'user_settings' tool. For instance, ensuring no red-meat is served requires an initial tool check for exact ingredient lists.
  - Analyze 'Gating Policy Transitions' by scanning the system instructions for mandatory sequential authorizations. The agent must determine exactly which tool-call observations (e.g., 'Verification: Success') act as the functional keys to unlock subsequent tasks. A concrete case is recording that a flight modification is permanently blocked in the graph until the 'auth_user' node returns a valid session ID.
  - Perform robust categorical coordinate extraction by utilizing exploratory diagnostic queries across professional endpoints. Map specialized classification systems or domain ontologies into simplified tokens so the planner can easily match against user exclusions. Discovering that a recommended code belongs to a forbidden family requires immediate pinning in the scratchpad to satisfy the negation constraint.
* **Target Trajectory Profile**:
  - The trajectory must showcase a 'predicate-grounded decision branch' where the transition relies completely on verifiable preceding tool outputs. Traces must outline an explicit verification comparison—like 'Wait time is 45 mins < Limit of 60 mins'—prior to execution. A failure profile features the agent guessing the constraint is satisfied without confirming the value array.
  - Documentation must reveal parametric mathematical validation whenever a specific parameter demands generative tweaking based on current formulas. Explicit formulas must be present in the tool generation thought block, evidencing true calculation logic through steps like 'Price + Tax < Budget cap'. A perfect trajectory showcases calculations deducing the final dosage or cost natively in the reasoning window.
  - Conjunctive checkpoints must aggressively structure the validation log in real-time before concluding a composite plan. Ensure the internal reasoning updates an imaginary scorecard representing every distinct boundary constraint named by the user, such as 'Timing: OK | Dietary: OK | Pricing: OK'. A robust record will list these states right before the finalizing API commit to ensure holistic compliance.
  - The trajectory must exhibit a 'Policy-Gated Handoff' where sensitive actions are only attempted after the log confirms an authorization state. The trace should show the agent identifying the need for authentication, executing the challenge, and only then adding the 'Modify Account' step to its sequence. A sharp trajectory avoids 'Predictive Authorization' by waiting for the grounded 'Authenticated' observation before planning the next sensitive move.
