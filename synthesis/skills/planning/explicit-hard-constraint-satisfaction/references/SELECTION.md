# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only trajectories where calculated plan artifacts strictly satisfy the parametric or scheduling boundaries mathematically. Human or script verifiers must independently execute the calculation matching the tool outputs to ensure 100% compliance. If the agent allocates an itinerary block for 30 minutes when driving requires 45, automatically fail the logic sequence.
  - Accept only if the agent reliably filters negative constraints by discarding results containing forbidden categorical tags or policy violations. The step-by-step trace must highlight the active pruning of at least one otherwise valid artifact due to an authentication failure or privacy exclusion. A strong proxy for this is verifying that the word 'policy' or 'unauthorized' triggers an immediate abandonment of a specific branch.
  - Accept only when evidentiary audit trails exist for every quantitative fact or authorization state referenced throughout the final decision payload. The agent's knowledge of a temporal window or identity status must originate explicitly from a captured `search` or `verify` response included earlier in the trace. Hallucinating a success state to fulfill a gated policy constraint automatically invalidates the record.
  - Accept only if the 'Identity-State Transition' is auditably grounded in tool results. The planner must successfully bridge the gap between 'User Request' and 'Authorized Action' by using intermediate verification tools without skipping the gate. If a sensitive tool is called without the trace containing a preceding 'Verification: Success' node, the seed must be rejected.
* **Rejection Criteria**:
  - Reject seeds displaying threshold-guessing hallucinations when addressing explicitly bounded mathematical parameters or scheduling loops. An agent inserting a definitive numeric variable (i.e. 'Reserve the table for 15:00') without actively querying the restaurant's operational hours exposes severe reliance on parametric pre-training. Any unverified numerical assignment constitutes a reasoning defect.
  - Discard any trajectory executing a 'Boolean Flop', where the agent correctly observes the boundary breach but executes the action regardless. When an agent's internal monologue identifies 'Potassium is 4.5, limit is 3.5' but then formulates a prescription anyway, the logic gate is fundamentally broken. This proves the agent is merely summarizing text, not utilizing System 2 control boundaries.
  - Reject any seed where the agent exhibits 'Policy Guessing,' defined as calling a restricted tool (e.g., `modify_order`) while assuming authentication will succeed later. The agent must never perform a privileged action until its working memory contains a literal confirmation of the permitted session. Attempting cross-user access because the agent 'believes' they are related is an immediate rejection.
  - Refuse traces where decorative constraint language masks an underlying lack of structured filtering parameters within the backend API payloads. Declaring 'I will find a pet friendly venue' in text but transmitting a generic `{location: downtown}` JSON payload is rhetorical compliance. Authentic constraint compliance requires injecting the strict variable right into the executing function.
