# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Accept only if the 'Hierarchy-to-Coordinate' mapping is perfectly synchronized across all levels of the Scene Description Tree. You must verify that the viewpoint ID selected at the zone level actually belongs to that zone and that its coordinates are reachable in the 3D simulator. If an agent claims a 'bedroom sink' is in the 'garage zone', the seed must be rejected as an ungrounded hallucination.
  - Accept a trajectory only if the navigation instruction demonstrates 'Style-Demand Alignment,' matching the Simulated User's persona and communication style. The instruction must avoid robotic step-by-step commands (e.g., 'turn left, go 2m') in favor of high-level, natural user demand phasing (e.g., 'Go to the cozy kitchen and find the coffee maker'). Verifiers check if the instruction complexity reflects the user's documented lifestyle and occupation.
  - Accept only if the 'Target-View Clarity' in the trajectory is absolute, meaning the destination view contains the precise semantic keywords mentioned in the instruction. If the instruction asks for a 'wooden table with candles' but the target view only contains a 'plastic chair', the retrieval phase failed. A valid seed must have a visible 1:1 match between the refined instruction objects and the scene tree object layer.
  - Accept only when the 'Connectivity Validation' check confirms that the proposed path across zones is fully traversable in the navigation graph. You should use a graph checker to ensure that every transition (from Zone A to Zone B) corresponds to an existing edge in the MP3D or HM3D simulation graph. Any trace that bypasses a wall or 'teleports' across non-navigable spaces is a structural failure.
* **Rejection Criteria**:
  - Reject any seed that exhibits 'Semantic Ambiguity Overlap,' where the generated instruction could equally apply to multiple different zones or viewpoints in the same scene. If the agent says 'Go to the chair' in a house with ten identical chairs without adding unique zone/attribute qualifiers (e.g., 'the gray velvet sofa in the rustic loft'), the plan is ambiguous and useless for precise navigation training.
  - Discard any trajectory that relies on 'Trajectory-Based Translation' (translating images to steps) rather than 'Hierarchy-Based Planning'. Our goal is to test global context, so traces that only narrate the immediate surroundings without referencing the zone-level or scene-level layout are rejected. For example, a plan that only says 'pass the fridge' without noting that it's entering the 'Kitchen Zone' lacks hierarchical depth.
  - Reject seeds with 'Persona-State Mismatch', characterized by an agent recommending a destination that contradicts the user's role or lifestyle. If a 'Pro-Athlete' user is sent to a 'stationary workspace' to 'do sprints', the planning reasoning is logically detached from the user-demand constraints. This ensures the synthetic data accurately captures persona-driven intent resolution.
  - Reject any trajectory where the 'Refined Instruction' fails to add significant detail or accuracy compared to the initial 'Rough Instruction'. The RAG process must be functional; if the refinement step is purely rhetorical and doesn't inject new attributes (like 'stone countertop' or 'round vessel sink') discovered during retrieval, the seed is rejected as a failure of the refinement loop.
