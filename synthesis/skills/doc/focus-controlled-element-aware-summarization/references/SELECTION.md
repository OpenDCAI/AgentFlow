# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Mandatory '5W Dimensional Coverage' requires that the summary addresses Who, What, Where, When, and Why if the context allows. Accept the trajectory only if the final summary accounts for every slot defined in the exploration phase or explains why an element was missing. A verifiable path shows a 1-to-1 mapping between the summary sentences and the core investigative questions. If 'Where' is missing and the document specified it, the instance fails.
  - Static 'Character/Length Compliance' must be strictly maintained within a +/- 5% margin of the requested limit (e.g., < 700 characters). Accept the trajectory only if the final string length falls within the hard constraint provided by the user. An example of perfect compliance is a bulleted list that provides high information density while sitting at exactly 685 characters. Trajectories that ignore the character count for the sake of 'completeness' are rejected.
  - Absolute 'Factual Grounding' permits zero introduction of information from the model's internal weights that is absent from the document. Accept the trajectory only if every proper noun and numerical value in the result is traceable to a specific paragraph in the source. This is verified by checking the 'Integrity Filter' logs in the trajectory. A correct answer must never include a person's middle name if the document only provided the surname.
  - Structural 'Format Adherence' requires the output to mirror the requested layout (e.g., bulleted list vs. prose). Accept the trajectory only if the response utilizes exactly the markdown indicators (like '*' or '-') requested. If the user asked for a 'short and precise' list, but receives a single long paragraph, the selection logic must trigger a redraw. This ensures the output is compatible with the user's intended downstream consumption format.
* **Rejection Criteria**:
  - Reject 'Lead-In Mirroring' where the summary simply copies the first two sentences of the document as a shortcut. This behavior, identified as a common model failure, represents a lack of real summarization and analysis. A rejection occurs if the overlap between the summary and the document's first paragraph is disproportionately high while later key facts are omitted. True abstractive summarization must synthesize the essence of the whole document.
  - Reject 'External Knowledge Leakage' where the agent includes quotes or details found in its training data but not in the news article provided. For example, if the document mentions 'The President,' and the agent names the specific president which isn't in the text, it represents a grounding failure. This is especially critical when the model 'hallucinates' quotes that sound plausible but are not in the source. Any summary containing one ungrounded entity addition is immediately discarded.
  - Reject 'Unbalanced Register Collisions' where technical jargon is used alongside layman terms in a confusing manner. If the agent translates half of a sentence but leaves a highly technical phrase like 'diacritic markers' in a 'patient-friendly' summary, it fails the fluency and register requirements. This ensures the summary is consistently accessible to the targeted persona. A failure case is mixing 'heart attack' with 'myocardial infarction' in the same short list.
  - Reject 'Mid-Sentence Truncation' errors where the summary ends abruptly because it hit a length limit. The agent must manage its character budget proactively rather than simply cutting off text. A rejection signal is a summary ending with an incomplete thought or an open-ended punctuation mark. Successful synthesis requires the agent to condense earlier points to ensure the final sentence is completed properly.
