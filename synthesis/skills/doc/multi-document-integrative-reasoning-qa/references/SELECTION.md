# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Mandatory 'Hop Necessity' validation ensures that removing any single hop in the query, including referrals, makes the final answer logically impossible to reach. Accept the trajectory only if the final answer depends on information or pointers from *all* retrieved files in the chain; if the answer can be found on one page alone, the multi-hop label is rejected. A verifiable path logs that [Pointer A] from Hop 1 was the only way to identify [Data B] on Hop 2. This prevents 'parallelizable' tasks or single-source lookups from being synthesized as integrative reasoning.
  - Strict 'Fragment Completeness' requires that all dispersed pieces of a distributed data point must be found and reconciled. Accept the trajectory only if the agent has located every siloed fragment (e.g., both halves of a 'split table') before formulating the final answer. This ensures the synthetic data provides a clear signal for evaluating complete retrieval versus partial retrieval. An example of compliance is a task where the agent identifies that two different 'game' documents are needed to cover the full set of specified dates.
  - Verification of 'Redirection Linkage Integrity' ensuring that referral links are semantically valid and grounded in document hints. Accept only if the trajectory proves the agent followed a specific pointer provided by a source (e.g., 'Dante knows about finances') to reach the final data. This distinguishes 'informed navigation' from 'lucky guessing' based on training data. A correctly validated path logs the extraction of the referral text and the subsequent successful retrieval from the referred source.
  - Requirement of 'Multimodal Integration Clarity' where the reasoning chain involves traversing at least one non-textual modality, such as a graph or table. Accept only if the trajectory shows the agent successfully mapping a textual entity from one document to a visual element in a separate slide or chart. This validates the 'MM-Doc' nature of the challenge by proving information cannot be integrated through text-only shortcuts. A failure to show a modality-switch in the reasoning trace results in immediate rejection.
  - Strict 'Evidence-Chain Uniqueness' requires that the final refined query points to five or fewer ground-truth pages globally across the corpus. Accept the trajectory only if the agent has performed at least one refinement iteration if the initial candidate pool was too high. This ensures the synthetic data provides a clear signal for retrieval evaluation. An example of perfect compliance is a 3-hop query where only a single 3-page sequence provides the unique path to the final correct data point.
* **Rejection Criteria**:
  - Reject 'Redirection Dead-Ends' where the agent follows a referral that does not lead to any relevant data. If the trajectory shows the agent jumping to Source B based on a hint, but Source B contains no information related to the question, the instance is discarded. This ensures the synthesized data contains a 'true' reasoning path rather than 'noise' hops. A rejection signal is an agent wandering between multiple users/files without acquiring the necessary variables.
  - Reject 'Linear-Shortcut' reasoning where the agent skips the multi-hop or referral process by guessing the final answer based on internal knowledge. If the trace shows the final answer appearing before the intermediate hops or redirections are completed, it indicates a bypass of the logic pipeline. This is often detected when models use internal world knowledge (e.g., knowing a celebrity's partner) instead of finding it in the provided documents. Any trace where the logic jump is 'invisible' or 'undocumented' is rejected.
  - Reject 'Partial Reconstitution' where the agent provides an answer based on only one part of a split document. If a table is split between two files and the agent only extracts data from the first half, the answer is deemed incomplete and the trajectory is rejected. This enforces the 'Integrity' requirement of the skill. A clear rejection signal is a final list that is significantly shorter than the ground truth provided in the 'split' source material.
  - Reject 'Unlinked Compositions' where the multi-hop query is just a collection of independent questions asked in parallel (e.g., 'What is X and what is Y?'). If the steps can be solved simultaneously without sequential dependency, the task fails the 'Multi-hop' definition. We strictly require 'Linkage-Driven' queries where the answer to Step 1 is the *input* for Step 2. A rejection signal is a query that can be split into two unrelated standalone questions without losing meaning.
  - Reject 'Overconfident Hallucinations' where the agent generates a plausible but ungrounded answer when the evidence chain or redirection path is broken. If the trajectory shows the agent 'filling the gap' with training data (e.g., inventing a 1980 campaign name that doesn't exist in the corpus), it must be discarded. This ensures the resulting data tests for 'Epistemic Humility'—a core requirement for trustworthy RAG. If the agent fails to refuse when evidence is missing, it is a critical failure.
