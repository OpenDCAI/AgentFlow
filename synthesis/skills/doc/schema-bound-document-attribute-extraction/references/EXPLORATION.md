# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Initialize the 'Ontology & Schema Ledger' before any extraction occurs. The agent must transcribe the target schema's definitions, required fields, and constraints (e.g., JSON structure, regex, or specific IDs) as a mandatory checklist. For example, if a neuroscience task requires aligning terms to UBERON, the agent must pre-load the search keywords for that ontology. This prevents 'schema-blindness' where the agent extracts facts that do not fit the target structural slots. An edge case is a task requiring hierarchical extraction where a 'parent' entity must be identified before any 'child' attributes are processed.
  - Execute 'Contextual Disambiguation Probes' for polysemous terms. When an extracted term like 'cortex' or 'cell' is identified, the agent must search the immediate context (sentence and neighboring paragraphs) for 'Domain Anchors' (e.g., words like 'brain', 'neurons', or 'botany'). This ensures the agent selects the correct ontology candidate from candidates like UBERON (anatomy) or PO (plant ontology). A concrete step involves the agent recording: 'Found term "cortex"; identified context anchor "synapse"; selecting UBERON candidates for alignment.' This proactively blocks hallucinations caused by common-word ambiguity.
  - Perform 'Spatial-to-Logical Anchoring' for layout-rich documents like forms or invoices. The agent must map visual cues (e.g., 'Total Due' header or 'Signature' box) using spatial coordinates and proximity logic to bind data values. For example, in a clinical form, a checkmark next to 'Yes' must be spatially linked to the question text appearing above or to the left. A failure case is extracting a date from the top-right corner and incorrectly assigning it to the 'Birth Date' field when it was actually the 'Filing Date' based on the header proximity.
  - Deploy 'Tri-Chunk Context Parsing' for relation extraction tasks. To determine the causal link between two entities (e.g., drug and side effect), the agent must explicitly analyze the prefix, suffix, and the intervening text (the 'infix'). This allows the agent to identify directional markers like 'resulted in' or 'induced by' to distinguish the Subject from the Object. An edge case is a passive sentence (e.g., 'Hypertension was caused by X') where the agent must reverse the order of discovery to ensure the 'Subject' in the schema is X and the 'Object' is Hypertension.
* **Target Trajectory Profile**:
  - The trajectory exhibits 'Verification of Antecedent Basis' for structured documents. In high-stakes documents like legal forms or assessment instruments, the path should show the agent tracking how entities are introduced (e.g., 'a loan') and subsequently referenced ('the loan') to maintain consistent attribute mapping. This confirms the agent is not mixing up separate clauses that use similar-sounding attributes. A successful log entry would show: 'Confirmed "the patient" in Paragraph 3 refers to the "John Doe" defined in the Header; mapping attributes accordingly.'
  - The trajectory documents 'Recursive Refinement of Ontology Candidates' during alignment. The path must show the agent retrieving multiple potential IDs for a term (e.g., several 'cortex' IDs) and then applying a logical filter based on the document's specific target species or domain. This proves the agent is performing 'Grounding' rather than simple string-to-ID lookup. A strong trace shows the agent discarding a general biological ID in favor of a specific 'human' or 'mouse' anatomy ID when the document context specifies the research organism.
  - The trajectory demonstrates 'Format Normalization and Regex Verification' at the point of extraction. Logs must record the transformation of raw text (e.g., '04/25') into a standardized schema format (e.g., '2025-04-01') prior to the final output generation. This ensures the output is machine-readable and FAIR-aligned. A concrete example in the log is: 'Extracted raw date "April 1992"; normalized to "1992-04-01" based on ReproSchema YYYY-MM-DD requirements.'
  - The trajectory reflects 'Exhaustive Attribute Coverage Checks' against the target schema. For complex forms, the trace should show the agent explicitly checking off each required field (e.g., title, description, instructions) and noting any 'Missing' values found in the source. Doing so prevents 'incomplete extraction' hallucinations where the agent ignores missing fields. A failure case is an agent claiming 33 questions were found when the schema requires 39 entries, without providing a justification for the gap.
