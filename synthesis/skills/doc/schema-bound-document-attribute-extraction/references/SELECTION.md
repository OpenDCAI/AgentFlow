# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Mandatory 'Canonical ID Alignment' requires that every key entity is linked to a unique, verified identifier from the specified ontology (e.g., UBERON:0000956). Accept the trajectory only if the agent has confirmed the label and the ID match the document's domain context. This is verified by checking the 'Contextual Disambiguation' logs. A success signal is an extraction where the ID mapping remains 100% consistent throughout a multi-page document even when the term changes from 'cortex' to 'cortical layer'.
  - Strict 'Spatial-Relational Fidelity' mandates that data extracted from a layout (e.g., a table or form) is provably derived from its correct visual anchor. Accept the trajectory only if the agent's log shows it identified the header or label that defines the field. This distinguishes 'informed extraction' from 'random field filling'. For example, if extracting 'Client Name', the agent must have identified the 'Client Name' text box spatially adjacent to the value.
  - Requirement of 'Format-to-Schema Compliance' where the output target (JSON/JSON-LD) is perfectly valid against the requested template. Accept only if the final result uses the exact keys and data types (e.g., arrays for options, strings for prompts) mandated by the user. If the schema requires a binary 'required' flag and the agent provides a descriptive sentence instead, the instance must be rejected. This ensures the data is ready for downstream procedural use in scientific databases.
  - Verification of 'Directional Logic Integrity' in relational extraction tasks. Accept only if the Subject-to-Object mapping follows the grammatical and causal flow identified in the 'Tri-Chunk Context Parsing' logs. This ensures that in a relationship like 'Drug A induces Side Effect B', the agent does not incorrectly swap the roles. A compliant path logs the specific verb phrase (e.g., 'induces') as the justification for the edge directionality.
* **Rejection Criteria**:
  - Reject 'Domain-Agnostic Collisions' where the agent maps a term to an ID from the wrong scientific ontology. For example, if a neuroscience document refers to 'cortex' and the agent provides a 'plant biology' ID, discard the case immediately. This is the primary failure mode for 'Knowledge Grounding'. A rejection signal is the agent using a general-purpose label when a domain-specific taxonomy (like ADO for Alzheimer's) was available.
  - Reject 'Prompt-Based Hallucinations' where the agent invents metadata or values to fill schema slots that are absent from the source. If the ReproSchema requires a 'Scoring Logic' but the PDF doesn't mention it, the agent must report 'undefined' or 'missing'. If the agent 'guesses' that the scoring is a sum, the instance is discarded. This maintains the 'Scientific Integrity' of the extracted metadata.
  - Reject 'Metadata Mirroring' where the agent simply produces a generic summary instead of the granular, field-level extraction requested. If the user asks for a ReproSchema object and receives two paragraphs describing the questionnaire, it fails the structural requirement. This enforces 'Schema Fidelity'—the agent must stick to the structure, not the story. A failure case is an agent summarizing an invoice rather than returning the 'Line Items' JSON array.
  - Reject 'Inconsistent Normalization' where different fields use different formatting standards. For example, if one date is '2024-01-01' and another is 'Jan 1st', it violates the 'Normalization' requirement. This ensures the synthetic data provides a high-quality signal for training agents on strict data cleaning. Any trajectory that bypasses the regex or normalization rules defined in the Exploration phase is rejected.
