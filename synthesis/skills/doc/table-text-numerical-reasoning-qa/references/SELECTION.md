# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The calculation logic must follow a 'Precision-Relaxed Matching' protocol derived from the document's numerical evidence. Accept the trajectory only if the final answer is equal to the ground truth after rounding to the coarser of the two precisions (e.g., 1.230M matching 1.23M). This ensures that valid predictions aren't rejected due to minor rounding or formatting variations. A verifiable path logs the extraction of [Value A] and [Value B] and proves their rounded sum matches the document.
  - Every operand in a multivariate formula must have a unique, verified document source. Accept the trajectory only if the agent has individually located and confirmed every variable required (e.g., numerator, denominator, and any multipliers). If the agent 'guesses' one value based on surrounding context without direct extraction, reject the instance. A verifiable path logs the extraction of [Value A] from 'Income Statement' and [Value B] from 'Investment Table' separately.
  - Latent variable derivation must be mathematically sound and transparently logged. For complex tasks, accept only if the agent shows the math used to compute the hidden variable (e.g., 'Total Debt = $7.2 / 0.181'). This ensures the student is learning 'Intrinsic Reasoning' rather than 'Pattern Matching'. If the final number appears without a clear operator-based justification, the example is underspecified and should be discarded.
  - Temporal and entity constraints must be 100% consistent across multi-table hops. Accept only if the agent used the same 'Year', 'Entity', and 'Company Segment' for all numbers used in a single calculation. In a 40,000-token document, the agent must prove it didn't accidentally pull a 2021 Net Income value and a 2022 Asset value. This check is performed by comparing the metadata of the source tables cited in the trajectory.
* **Rejection Criteria**:
  - Reject 'Intrinsic Hallucinations' where the output contradicts the input financial context. If the document states 'Operating Income was $500,000' and the agent predicts '$500 million' due to a scale error, discard it immediately. This is the primary failure mode identified in the FAITH benchmark. A rejection signal is an agent claiming a growth rate that is mathematically impossible given the table's raw start and end values.
  - Reject trajectories that fail the 'Uniqueness' test due to lack of specificity. Discard any instance where the question is so vague that multiple numbers from the table could be correct (e.g., 'What is the amount in Table 3?'). The question must use specific constraints (e.g., 'for the Retail segment in 2024') to ensure ONLY ONE number is the correct answer. This maintains the integrity of the data synthesis pipeline.
  - Reject instances where 'Financial Sensitivity' is absent in label binding. If the trajectory shows the agent picking a 'Total Revenue' number from Table A when the question specifically requires 'Pro Forma Revenue' from Table B, discard it. This prevents the synthesis of data that rewards keyword-spotting over precise attribute matching. A common failure is confusing 'Net Income' with 'Comprehensive Income' because they sound similar.
  - Reject 'Unbalanced Arithmetic' where units or scales are mixed without conversion. Discard any example where a 'dollars' value is added to a 'thousands of dollars' value without an explicit 'x1000' step appearing in the agent's logic. This maintains the high-fidelity requirement for financial reasoning datasets. Silent, unexplained math errors in the final answer are grounds for immediate rejection even if the final number is close.
