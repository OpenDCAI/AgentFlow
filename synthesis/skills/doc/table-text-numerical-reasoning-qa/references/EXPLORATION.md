# Phase 1: Environment Exploration Guide
* **Exploration Strategy**:
  - Classify the required math into the four-tier FAITH taxonomy (Lookup, Comparative, Bivariate, Multivariate) before searching. The agent should explicitly categorize the difficulty level (e.g., 'This is a Multivariate task requiring debt and equity variables') to determine the depth of retrieval required. This prevents the agent from stopping after a simple 'Direct Lookup' if the query actually implies a complex ratio. An edge case is a 'Comparative' task that requires finding the same label across three different years located in three separate tables.
  - Perform 'Latent Variable Reconstruction' by identifying gaps between textual claims and tabular evidence. When a question provides a final answer or a complex metric (e.g., 'equity investment'), the agent must work backward to identify hidden operands like 'total debt' or 'pro-rata shares' that are not explicitly asked for but are necessary for the calculation. This involves scanning footnotes and table headers to find implicit relationships like 'pro-rata debt = total debt * ownership'. A concrete example is reconstructing a 'Gross Margin' by finding 'Revenue' in one table and 'Cost of Goods Sold' in a different section.
  - Execute a 'Scale and Unit Sensitivity Audit' to prevent magnitude hallucinations ($M vs $B). The agent must systematically record the 'unit' and 'scale' listed in table headers or footnotes (e.g., 'in thousands', 'millions of USD') for every number extracted. This ensures that when numbers from different sources are combined, they are normalized to the same base (e.g., converting 500k and 1.2M to the same power of ten). An edge case is a document where the text uses 'billions' but the source table is formatted in 'millions', requiring a 1000x multiplication step.
  - Map table-to-table dependencies in long-context documents horizontally. For documents exceeding several thousand tokens with multiple tables, the agent should first create a 'table index' by identifying the headers and reporting entities of each table present. This prevents 'table-drifting' where the agent starts calculating using values from Table A but finishes using values from a similarly-named Table B on a later page. A concrete step is recording that 'Table 3 on page 12 contains 2021 data' while 'Table 7 on page 45 contains 2022 projections'.
* **Target Trajectory Profile**:
  - The trajectory demonstrates explicit 'Inferential Chaining' where hidden intermediate values are logged. The path should not just jump from raw cells to a final answer; it must document the derivation of intermediate metrics (e.g., 'Step 2: Calculated Total Debt by normalizing pro-rata share'). This proves the agent is performing 'Multivariate Reasoning' rather than accidental guessing or retrieval. A failure case is seeing a complex equity figure appear in the log without the agent ever calculating the underlying asset-to-debt ratio.
  - The trajectory showcases 'Numeric Normalization' records before arithmetic execution. Logs must record the 'Base Number' and 'Precision' for each value (e.g., 'Value: 1.23, Scale: Billion, Precision: 0.01B'). This makes the reasoning audit-ready and prevents 'Scale Errors' where different magnitudes are blended incorrectly. A concrete example in the log is: 'Identified Table A uses thousands ($K); normalized $500 to 500,000 for calculation with Table B (dollars)'.
  - The trajectory reflects 'Contextual Sensitivity' by using provided 'Hints' or 'Type Constraints'. If the prompt specifies a value type (e.g., 'Absolute Value' or 'Percentage Change'), the trajectory must show the agent using this constraint to select the correct cell. This ensures 'Uniqueness' in recovery tasks where multiple numbers (like 10% and $1M) might both be factually true. A strong trace shows the agent considering both values but explicitly choosing the one matching the hints.
  - The trajectory preserves 'Semantic-Numeric Grounding' between disparate modalities. The path must prove that the agent used textual descriptions to help identify numerical rows, such as using the phrase 'unconsolidated venture' in the text to locate the specific line in a 'Property Ownership' table. This demonstrates that the agent is not just doing OCR/cell extraction but is integrating narrative context. An edge case is identifying a specific property name ('Mohawk Commons') to filter out a table containing generic property IDs.
