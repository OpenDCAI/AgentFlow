# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Each judged claim must have an explicit, localized evidence target. Accept only if the trajectory tells the evaluator exactly which minimal passage was checked for each decontextualized claim. This is the minimum structure needed for support verification. Without it, the example is too vague or requires too much human reading to be useful.
  - The support relation must be semantically decisive. A selected example should make clear why the evidence fully supports, partly supports, contradicts, or fails to support the claim. This guards against simple keyword-overlap false positives. A good check is whether a human could defend the same label without consulting outside knowledge.
  - Decontextualization traces must be clearly logged. Accept only if the path explicitly documents replacing conversational filler or referencing pronouns with their true noun entities prior to fact-checking. The exact expansion must be logically valid based on the document. An example is rejecting the sample if the agent resolved 'the organization' to the wrong company name out of two listed.
  - At least one realistic validation failure or safety risk pattern should be present. Strong examples often include real citations that are subtly misapplied, structural precedent errors, or safely identified spoofed documents. These are far more valuable than obvious fabricated nonsense. They closely mirror the hallucination and security risks found in practical legal, medical, and RAG workflows.
* **Rejection Criteria**:
  - Reject under-decontextualized attributions. If the evaluated claim still contains unresolved semantic gaps, like 'this process helps,' discard the trajectory immediately. Verification must only be performed on fully self-sufficient statement blocks. Fact-checking an ambiguous shard leads to noisy annotation.
  - Reject metadata mirroring and large-scale page citations. If the agent merely copies broad sentence-level citations or entire paragraphs instead of executing specific sub-sentence localization, reject it. The entire point of the capability is minimizing the cognitive overhead of the target evidence span. A 200-word citation for a 5-word fact is unacceptably broad.
  - Reject unresolvable logical contradictions or unverified safety spoofing. Discard any instances displaying 'Supported' grounding on explicitly recognized spoofed/phished domains. Verification must fail early if the source lacks authenticity. A document that looks real but originates from a phishing domain must result in a rejection of claims.
  - Reject evidence-free structural audits mimicking basic spellcheck. If a grammar anomaly is flagged but fails to evaluate complex intra-document structural reference cohesion (i.e. it just catches a misspelled word rather than a broken antecedent link), delete it. The benchmark must test deep structural tracking, not surface-level typo detection.
