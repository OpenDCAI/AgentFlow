# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - Mandatory 'Semantic Threshold Validation' for paraphrased queries requires that the retrieved chunk contains the conceptual answer even if 0% of keywords overlap with the query. Accept the trajectory only if the agent can provide a logical 'Semantic Link' showing how the document's formal phrases correspond to the user's intent. This prevents rejections of valid answers caused by rigid keyword filtering. A verifiable path logs: [User Term: 'Help'] -> [Document Term: 'Subsidy'] -> [Logical Match: Verified].
  - Strict 'Abstraction-Level Alignment' between the information need and the chunk granularity. Accept only if the agent uses a higher-tier chunk (Section/Document summary) for high-level questions and a lower-tier chunk (Paragraph/Sentence) for extractive lookups. If a user asks 'What is the goal of Section 2?' and the agent retrieves 10 sentences from Section 4, the instance must be rejected. A compliant path proves the agent retrieved the 'Section Summary' for the specifically requested structural unit.
  - Requirement of 'Spatial-Verbatim Fidelity' where extracted bounding boxes land precisely on the target evidence. Accept the trajectory only if the provided coordinates (W,H,X,Y) encompass the correct textual or visual element without including irrelevant neighboring noise. This is verified by checking the spatial anchors in the environment. For example, a bounding box for 'Article Number' must not include the 'Date' field that might be adjacent to it in a header.
  - Verification of 'Grounding Density' within a specific character range (e.g., 2K-4K chunks). Accept only if the retrieved chunk contains the absolute minimum necessary context to be self-contained for the LLM to answer. This ensures the synthetic data provides a clear signal for evaluating efficient retrieval. A successful path logs the removal of 'Overlapping Chunks' from the context to prevent redundancy and token waste while maintaining enough context to resolve the query.
* **Rejection Criteria**:
  - Reject 'Lead-In Mirroring' where the agent simply copies the start of the document as a shortcut because it contains high keyword frequency. This behavior represents a lack of deep semantic analysis and often misses the actual answer found deeper in the regulation. A rejection signal is an agent providing the document title as an answer when the query asks for a specific condition. This prevents the synthesis of 'lazy' data that doesn't test real reasoning.
  - Reject 'Domain-Specific Splitting' where the agent attempts to create a separate skill for institutional, medical, or legal localization. Based on the consolidated taxonomy rule, all document-grounded localized QA—regardless of whether it involves a university statute or a hospital record—must remain within this skill. Any attempt to isolate 'University RAG' as a new capability will result in immediate rejection. We strictly maintain the underlying logical mechanic of localized evidence retrieval.
  - Reject 'Paraphrase Hallucination' where the agent rewords the answer to match the user's casual query but loses factual precision. If the document specifies 'cumulative GPA of 7.0' and the agent tells the user 'you just need good grades,' it is considered a concealment error. This ensures that the synthetic data maintains the 'Ground-Truth Rigor' required for institutional or regulatory tasks. Any answer that replaces specific numerical limits with vague adjectives is discarded.
  - Reject 'Coordinate-Neglect' where the agent returns a textual answer when a spatial location was requested. If the user asks 'where exactly in the ordinance is this rule,' providing only a text snippet is an environmental failure. This ensures the MM-Doc Agent's unique perceptual-spatial capabilities are correctly synthesized. A failure case is the agent stating the rule exists but failing to provide the [X, Y, W, H] array for the specific clause box in the PDF.
