# Phase 2: Trajectory Selection Criteria
* **Acceptance Metrics**:
  - The 'Translation-to-Reference Length Ratio' must fall within the 0.7 to 1.43 range. Accept the trajectory only if the final translated document's length is consistent with the source, preventing severe cases of under-generation (skipping sentences) or over-generation (hallucinating extra dialogue). This quantified metric ensures the agent is neither too brief nor too verbose for the target language. For example, if a 100-word English news story becomes a 50-word Swahili summary, the instance must be rejected as an under-generation error.
  - Terminological consistency must be maintained across the entire discourse unit. Accept the trajectory only if specialized terms are translated identically in every sentence where they appear, unless a meaning shift is explicitly identified. This ensures internal cohesion and avoids confusing the reader. A verifiable path logs the reuse of 'Bank client confidentiality' for every mention of 'Bankgeheimnis' throughout a 5-page report.
  - Every domain-specific reference (laws, treaties, codes) must have a 100% accurate target mapping. Accept only if the agent has correctly translated legal or technical abbreviations to their standard counterparts in the target language (e.g., PatG for Patent law). This is verified by checking the 'Reference Fidelity Audit' step in the trajectory. If the agent uses a generic name where a specific code was required, reject the instance immediately.
  - The 'Word Repetition Score' must be within natural linguistic limits. Accept only if the output is free of machine-generated loops, such as the repeated generation of the same subject-verb phrase within a single paragraph. This acts as a quality filter against standard LLM degradation patterns found in document-level tasks. A success signal is a paragraph that uses varied but synonymous connectors rather than repeating the same Swahili conjunction ten times.
  - The output must pass a 'Language Identification (LID)' audit for off-target detection. Accept the trajectory only if the generated text is verified to be in the requested target language (e.g., 100% Amharic) without 'leaking' English or other dialects into the body. This prevents the synthesis of 'off-target' translations where a model switches scripts mid-document. The selector verifies that all characters used belong to the target script's Unicode block.
* **Rejection Criteria**:
  - Reject any trajectory containing 'Critical Reference Hallucinations'. If the agent misidentifies a law, treaty, or formal reference—such as citing the 'Stock Exchange Act' (BEHG) when the source mentioned the 'Patent Act' (LBI)—discard the case. These errors are the most damaging in professional document work. A common edge case is an agent assuming a common law name based on a similar-sounding abbreviation.
  - Reject 'Interpretive Omissions' where critical conditions are dropped. Discard trajectories where the agent fails to translate a legally or technically relevant qualifying phrase (e.g., 'unless otherwise stated' or 'pursuant to Art. X'). This prevents the synthesis of 'Simplified' translations that lose the source's precision. A failure signal is a translated contract that omits a specific liability exclusion found in the original.
  - Reject 'Register-Inconsistent Paraphrasing' that weakens the document's authority. If the agent replaces a standardized professional term with an unusual or creative synonym (e.g., using 'Tram for free' instead of the established 'Gratistram-Initiative'), the instance is tossed. This reinforces the need for 'Lexical Cohesion' and domain expertise. Terminology should stay within the established 'Codebook' of the professional field.
  - Reject 'Multi-Paragraph Merge Errors' where punctuation or spacing is lost. If the realignment of translated chunks results in a single massive block of text without the original document's headers, bullet points, or carriage returns, reject the instance. Proper document reformatting during translation is mandatory for a 'MM-Doc Agent'. A failure case is a translated technical manual that loses its numbered steps during the translation process.
  - Reject 'Off-Target Script Leakage' in the final synthesized output. Discard the instance if the agent provides an Amharic translation but includes English words for concepts that have native equivalents simply because it was easier for the model. This ensures the data trains for 'high-purity' translation rather than 'lazy' mixed-language generation. A rejection signal is seeing Latin-script Yorùbá words appearing in the middle of a Ge’ez block.
